# 虫群增殖 R3 · 本地实现与验证

2026-11-20。虫族首个分支在主线工作区接入 45 张正式牌。数值以 [R3 确认稿](../../docs/project/ZERG_SWARM_45_REVIEW_20261120.md) 为准，执行与验收对照 [R2 接口规格](../../docs/project/ZERG_SWARM_IMPLEMENTATION_SPEC_20261120.md)。

## 实现范围

- 正式关间商店与图鉴登记 9 白、9 绿、9 蓝、6 普通紫、9 紫节点、3 橙节点。第三个有效普通进度锁主并弹出免费三选一。白牌复购升档，紫节点提供已有节点升级位，橙节点三选一。
- 编制、正式订单、孢子、寿命、甲壳、成熟、分裂、复活及双英雄均沿现有 World 固定步执行。实体标记区分正式兵、分支临时兵、原生子虫与受控体。载体表现复用项目现有主脑、虫卵和坑道资源。
- 物理主武器按发射时武器识别，虫后酸性骨刺、酸液／毒液、反伤、持续伤害及派生段都不进入被动播种。已有孢子的普通敌人可在合法致死后孵化。体验敌保持独立结算。
- 战斗档升级为 27。26 版迁移只变更版本字段。继续使用原有账户、订单、回执与关间检查点。修复原校验拒绝扎加拉带编号的在途连续弹，保留原版技能时序。

## 已跑的验证

完整回归通过 3468 项。最后一处原生武器装备标尺调整后，43 项虫群增殖、六单位和 D05 专项复测通过。类型、生成数据一致性和 45 项接口清点通过。正式包包含 4161 项资产，其中包含本支三种投放载体的原版资源。

- 专项测试覆盖 14 张周期部署牌的逐牌实际出场，固定步真实双体投放、第三点锁主、三次王虫腺体复选、37／46 席、订单时间比例与主脑已付交付、物理命中和体验敌分流、复活权限、扎加拉双体共用冷却及 60 秒单体恢复。26 档迁移用真实归档编解码对比矿气和随机状态。
- 正式 Web 构建 `f5135c9c17a3` 从第三点前的关间档进入。实际购买跳虫投放锁主，领取孢子母巢，导出后重新载入第 3 关存档，再进入第 4 关，实际产生 4 只临时跳虫。桌面 1280×800、模拟横屏 860×415、模拟竖屏 415×860 的三选一均可见，页面横向溢出 0，控制台与资源错误 0。已目视核对桌面节点及战场。最终构建 `3dd6eb1bafa6` 复跑同一流程，三种尺寸无横向溢出，第 4 关再次实际投放 4 只跳虫，页面与资源错误为 0。
- 密集复现使用种子 17、普通第 12 关、40 秒真实模拟。两个体数上限分别达到 60、90，实际同场都有体验敌和原生子虫。

| ---: | ---: | ---: | ---: | ---: |

密集夹具固定友方最低生命并布置分支兵。两组敌军峰值不同，结果用于发现实际固定步成本和验证容量。物理设备帧率、自然长局强度和复杂装备交叉仍需测试。

## 复现

- [本地正式入口](http://127.0.0.1:15302/) 选虫族，进入关间战备补给后可刷到虫群增殖牌。三点结算后选择免费节点，下一战观察自动投放。需要重开服务时在主线工作目录执行 `npm run dev -- --host 127.0.0.1 --port 15302 --strictPort`。
- `node --import tsx --test test/zerg-swarm.test.ts` 跑机制回归，`node tools/qa-zerg-swarm-interfaces.mjs` 核对 45 项映射，`node --import tsx tools/qa-zerg-swarm-density.mts` 跑密集样本。
- `npm run build:web` 使用专用 `SC2_WEB_OUTPUT` 目录构建，再用 `SC2_ZSW_WEB` 指向该目录执行 `node --import tsx tools/qa-zerg-swarm-web.mts` 复测正式购买和导入。脚本从第三点前的关间检查点进入。

变更仅保留在本地工作区。按保留规则清理验证构建和详细日志。
