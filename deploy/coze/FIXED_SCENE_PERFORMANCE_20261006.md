# 固定场景性能阶段 · 2026-10-06

UI 接入完成后，用户要求继续下一步。按既定顺序进入固定场景性能分析与优化，基线提交 `1f7ef85051dbea038fad4d56248214a568322098`。先记录当前版本，依据浏览器性能剖析定位，再做同场景前后对照。

## 约束

保留当前战斗、经济、地图、存档规则、英雄／精英机制、确认过的模型与特效和正式 UI。run schema26、profilev6、地图配方v3不变。不得用减少实际敌人数、改伤害／时钟、丢弃模拟欠账、关闭已确认效果或更改测试场景来宣称优化。原素材及 UI 原稿逐项保留。

固定诊断存档、自然战局和生产 Web 检查分别标注。当前格式不能导入旧 P6 schema23 档案；不得为了复用旧证据新增兼容分支。P6-V01 的旧截图保留，用当前场景复查相似强光现象不能直接宣布原自然战局问题已解决。

## 方法

1. 冻结当前源文件、资源清单、UI 原稿、应用构建和固定存档哈希。
2. 同机单个浏览器顺序取样，记录真实帧间隔、首十秒、长任务、模拟欠账、实体数、提交开销、绘制调用和浏览器 CPU 剖析。开发剖析与未插桩生产帧测量分开。
3. 三族大编队和高压力场景分别比较；所有失败、场景结束和硬件／浏览器信息留档。截图在测量外进行，画面诊断不偷偷改变发行版本。
4. 优化后复用冻结场景，重复测量、比较完整模拟状态，检查正式 UI、存读、Web与离线产物。报告实测改善与仍未达到的门槛。
5. 完成本阶段后更新当前游戏及增量应用，提交、推送和核对远端 CI；不部署 Coze、不启用后台。

既有自然性能门槛 P95≤16.9ms、P99≤20ms、超过20ms帧≤1%、180秒新增模拟欠账≤0.1秒继续保留。短时固定诊断不能代替这组自然门槛，也不能代替完整 M6/M7、人工视觉和实体设备验收。
