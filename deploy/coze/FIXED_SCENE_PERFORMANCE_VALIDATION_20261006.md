最终 `src/render` 完全恢复基线字节，未改画质、模型、材质、特效、亮度、绘制范围或显示数量。步进器及欠账处理未改。run schema26、profilev6、地图配方v3不变；不加入旧存档兼容。

## 方法与边界

Windows、AMD Ryzen 7 5800U／Radeon Graphics，1440×900、DPR1、Chrome 实际硬件渲染。浏览器和显卡完整字符串保存在每组结果中。单个浏览器串行采样，测量时不同时执行其他测试或构建。生产 Web 帧间隔与插桩开发版的单步／提交耗时分开；截图在帧采样之外保存，首十秒计入结果。

使用冻结的当前格式第16关诊断存档，三族各一组、各三次30秒。神族额外300靶标场景也各三次30秒。靶标为静止、不射击、高生命的诊断单位；没有在采样中锁血、改时钟、强行推进、增加生产编制或减少敌人。这些存档不是自然赚取的战役记录，也不代表自然敌军的完整攻击压力。

原版和最终候选核对相同存档 SHA-256、机器、Chrome 和 GPU；全过程保持战斗阶段。暂停恢复到首个采样点之间已有少量累计欠账清空记录，逐项保存在 `discardedAtFirstSample`；首个采样点至结束没有继续增长。不能把整个恢复窗口写成“零清空”。三十秒样本不能验证既有180秒自然欠账门槛。

这九次最终样本均在短时帧参考线内，采样欠账峰值约0.0167秒。原版与最终版都出现过孤立长帧，虫族最大值分别约150.3／150.1ms。九轮平均帧间隔的中位数为16.722／16.732ms；没有证据宣称这些接近60FPS的场景进一步提速，也不宣称每项波动都改善。

## 状态等价与回归

冻结完整原版模拟模块，与最终源代码分别加载七组全身份诊断及100／300靶标场景。每组执行相同的1,800逻辑步、移动指令和每三秒英雄指令；初始及每60步比较完整配置、地图、World和永久档案图编码，共279个检查点全部一致。记录在 `replay.json`，原版模块哈希也在其中。

该 Node 回放属于逻辑 CPU 测量，不是浏览器 FPS。300靶标单步平均耗时11.664→10.662ms，约减少8.6%；100靶标6.012→5.323ms。九组中八组平均耗时降低，最小的独立死神组0.176→0.182ms略增，因此不宣称每组都有提升。

最终1,153项回归和类型检查通过，当前数据文档检查与165项天赋生成检查通过。新增验证覆盖当前五地图未嵌入清单时的资源解析，以及光环来源在死亡、所有权、临时身份、子单位身份、删除和重新加入后的即时资格。原有动画测试增加连续空帧后重新出现时的位置与当前姿态检查。
