# 战斗与基地实机样例 · 2026-10-08

这是独立交互样例，不是完整游戏，也不接入 main 游戏入口、存档或后端。

复用当前 `World`、`BattleRenderer`、真实主动技能入口、原模型／特效／立绘和批准的 R12 样式。仅本目录提供 UI 提案与诊断场景；`src/`、正式 Web、完整 HTML、部署包和游戏数值保持原样。

样例场景：战斗、基地建设、战备补给、满员增援、尚无英雄。人族五个兵种为陆战队员、劫掠者、恶火、坦克和医疗运输机，三名英雄为雷诺、泰凯斯和诺娃。

- 第一排五个兵种槽＋三名英雄槽。有手动操作的兵种前置；每个兵种至多一个既有手动操作，英雄一个主动技能。没有技能的兵种点按看详情。
- 鼠标左键／手机短按施放；鼠标右键／手机长按 480ms 查看原单位详情。冷却时详情仍可打开。详情保留所有士兵和三名英雄的切换。
- 取消样例里的“单位操作”按钮；全局推进、侦测等仍单列。
- 两排分别折叠，收起时箭头向上，展开时向下；按钮名称和 aria-expanded 同步。
- 战斗中“基地”和关间“设施调整”直接进入基地面板。设施页显示真实数量、武器／防护研究、当前训练兵种和已有科技；训练、订单和部署复用现有生产面板／World 命令。发展目标保留原来的关间修改限制，战斗中为禁用状态；建设购买仍只发生于原建设阶段。
- 研究等级和累计强化读取真实状态；卡片详情仍保留精确收益。军衔、研究等级、卡片强化分别展示，不编造新等级。
- 满员场景先生成真正合法的增援报价，再用诊断场景补满编制。原报价保留，但按现有容量规则显示“编制已满”，禁止购买；不改抽取概率、扣款或人口规则。

场景由诊断配置建立：已解锁科技、设施、资源和高生命静止敌人不代表自然战役获得。战斗没有完整关卡推进；不检验普通模式后期平衡。显示和操作走正式引擎，游戏素材原字节保持。

“前往补给”“返回前线”使用原关间推进命令；订单、扣费和强化保留。只有工具栏的场景切换与“重置”重新建立诊断配置。

构建：`node tools/build-battle-ui-sample.mjs`。独立 HTML：`dist/Battle-UI-Feedback-Sample-20261008.html`。

预览：`node tools/serve-battle-ui-sample.mjs`，仅在本机提供该 HTML，默认端口 4195。离线文件内置原始素材，不访问游戏后端。

检查：`node tools/qa-battle-ui-sample.mjs`；`node --import tsx --test test/battle-ui-sample.test.ts`；`node node_modules/typescript/bin/tsc -p preview/battle-ui-feedback-20261008/tsconfig.json --noEmit`；`node tools/verify-battle-ui-sample.mjs`。证据位于 `reports/local/battle-ui-sample-20261008/`，最终截图对应具体 HTML 哈希。
