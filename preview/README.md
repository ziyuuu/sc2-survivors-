## 后续功能包约定

建筑真实逻辑独立包使用 `preview/building-workbench/`，舰装 UI／装备原型使用 `preview/starship-workbench/`；两者是计划路径，本次未创建。正式规则放在 `src/` 并由主游戏与独立入口共同导入，预览目录只承担入口、展示、隔离状态和测试夹具。

2026-10-13后续进展：建筑工作区已有[独立对接模块](building-workbench/README.md)，统一三族UI、报价、进化与生产，使用隔离World验证原接口。用户明确要求本轮不挂载主游戏；新规则暂留独立模块，原`src/`仅读取复用。此前“尽早接入”不构成本轮挂载授权。舰装工作区仍按其工作线进度处理。

先独立验证，再接入主游戏；关键链路通过后尽早进行小规模接入。独立包交付要写清已实现规则、启动步骤、测试状态与未定参数，不能把静态样图或虚拟钱包变化当作真实逻辑完成。完整约定见 [MVP 收尾计划](../docs/project/MVP_COMPLETION_CONTRACT_20261013.md#独立包必须包含真实规则)。

成品放 `dist/`、验证证据放 `reports/local/`，不要把大包、私有数据和重复资源混入入口源码。目录与保留规则见 [项目文件夹说明](../docs/PROJECT_STRUCTURE.md)。
