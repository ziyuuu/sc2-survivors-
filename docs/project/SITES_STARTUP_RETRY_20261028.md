# Sites 首页初始化自动恢复

用户报告手机 Chrome 的开场停在 `INITIALIZING / PREPARING MISSION / …` 超过十分钟，要求失败后自动重试。归属 V05，问题编号 V05-SITES-BOOT-001。

## 已确定的缺陷与修复

- 菜单资源失败后，旧代码在开场遮罩下等待手动重试，玩家看不到也无法操作。现在会自动重试三次，间隔为 1、2、4 秒；同 hash 已完成资源保留，不清理存档或已缓存资源。
- 一条资源准备通道失败后，不再继续把剩余菜单资源全部排进可能失败的队列；已有请求完成后进入同一轮恢复。
- 资源包 Service Worker 的下载和读取响应体原来没有期限；旧 Promise 可能被后续请求继续等待。现在每次包读取最多 45 秒，超时中止并移除失败任务，下次重试建立新请求。
- 程序引导的服务注册、激活和程序下载增加期限及三次自动重试。仍失败时露出现有样式的恢复入口，不再永远停留在开场。
- 菜单实际已完成的资源数量驱动开场 0–25% 进度，自动恢复时显示重连状态。持续失败后停止假加载进度并露出“重试”。

原资源包、压缩参数、玩法、存档 schema 26、D1/R2 与后台认证保持。没有修改玩家数据或实际玩家存档。

- 新增自动恢复测试及既有 HTTP/超时测试共 16 项通过；覆盖部分成功资源复用、三次延迟重试、挂起响应体中止及迟到响应不污染新请求。
- 完整 `npm test` 2720 项通过。受限执行环境初跑有 7 项本机 HTTP 连接 EACCES，允许本机连接后完整复核通过，没有为通过测试修改产品代码。
- 实际浏览器访问本机故障注入服务器：程序 502 一次、清单 502 两次、资源包 502 一次后，自动进入菜单；清单共请求 4 次、程序 2 次、资源包 14 次，资源包请求中仅故障 1 次。未点击重试、未清缓存。
