## 界面与真实规则

战场、关间的页面名入口均归一到简化旗舰配装：左侧当前舰船和十二槽，右侧当前出征背包。保留同页查看与比较、筛选、排序、选择；不显示舰装导航、种族切换、仓库、工坊、预设、套装汇总、地面列表或继续／撤离按钮。后两项由模拟战场和关间外层负责。

| 操作 | 战场 | 关间 | 实际结果 |
| --- | --- | --- | --- |
| 查看 | 可以 | 可以 | 不改变装备或收益 |
| 丢弃 | 可以 | 无按钮 | 同一实例由背包回到地面，无粉尘；真实 World 注册原有落地事件 |
| 销毁 | 可以 | 可以 | 删除所选实例，无粉尘；地面也可销毁 |
| 装备／卸下 | 禁止，暂停仍禁止 | 允许本次背包中合法散件和特殊装备 | 调用原有 World 换装与属性刷新；模块、套装仍只能局外更换 |
| 分解 | 禁止 | 可以 | 使用既有品质粉尘价格一次入账；污染装备仍须局外清洗 |

用户最后明确要求关间“换装备、分解”，此要求覆盖先前关间仅查看／销毁／散件换装的限制。手动锁定、收藏、系统奖励来源锁定以及已穿戴保护继续由命令层与真实规则校验；批量操作先预览合法项，跳过保护项。没有新增价格、掉率、装备强度或污染豁免。

`discard` 历史命令保留其永久删除语义，界面明确称“销毁”；新增 `drop` 为放回地面。没有把原永久删除命令悄悄改成地面移动。地面落点、距离、可达性与满包拾取继续走原共享管线。

## 曾获得的合成配方

运行时装备账户新增 `acquired`，由生产规则记录获取，不依赖 UI 图册或当前物品是否还存在。配方身份为模板（含品质）、种族、槽位及英雄／精英／方向绑定；词条随机数、白字分配和污染状态不另算配方。

- 进入仓库或背包的真实发放，以及成功地面拾取，记录获取；仅生成在地面、看到它或满包拾取失败不会记录。
- 丢弃、销毁、分解、结算遗失后记录仍在；精英绑定洗练得到的新绑定也记录，旧绑定保留。
- 工坊品质、指定套装、指定槽位仅展示已获得的合法选项；空记录显示获取后的解锁入口。
- 随机和指定合成都在相同已获得配方内抽取。仍先选合法槽位、按现有稀有权重选模板，再从已获得的绑定中选择；不按持有件数加权。现有价格、污染专属禁合成及绑定合法性校验保留。
- 账户创建使用 `newEquipmentAccount()`。本批不新增装备存档、迁移或恢复工程；跨关闭恢复随既定 MVP 收尾存档工作完成。

## 接入接口

正式主游戏仍未挂载整套 UI。共享规则、控制器及真实 World 适配器已经可供宿主接入，演示与主游戏使用相同生产模块。

```ts
import {createWorldStarshipHost} from '../../ui/starship/world-host';
import {mountStarshipUI} from '../../ui/starship/view';
import '../../ui/starship/style.css';
import '../../ui/starship/legacy-r12.css';
import '../../ui/starship/polish.css';

const host=createWorldStarshipHost(world,{
 resolveImage,
 inputReset:clearHeldInput,
 begin:beginThroughApplication,
 continue:continueThroughApplication,
});
const ui=mountStarshipUI(root,host,{startOpen:false,onClose:restoreHostFocus});

// 首页进入：
ui.open('loadout');
// 战场或关间进入：都依真实 phase 决定功能，暂停不能开放战场换装。
ui.open('backpack');
// 关间也可明确调用：
ui.open('intermission');

// 所属界面销毁：
ui.dispose();
host.dispose?.();
```

挂载容器的位置和覆盖层属于宿主：R21 演示在应用设置栏下用固定覆盖层，内部滚动。真实主游戏须提供自身挂载位置、输入清理、资源解析、开始与继续回调，保留原生奖励／建筑等关间决策和资源准备；不能将演示默认跳过未展示窗口的续关实现当成正式游戏流程。

实现自定义 `StarshipHost` 时，除原接口还须提供 `drop(id, revision)` 和 `dismantle(ids, revision)`。真实适配器分别调用 `dropWorldEquipment()` 与原生阶段校验后的 `dismantleEquipment()`；独立适配器使用相同库存规则。UI 仍通过 `StarshipController` 提交含账户和管理修订号的命令，校验保护项及重复请求。
