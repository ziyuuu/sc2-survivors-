# 合包资源更新兼容性核对

2026-10-28，V06-SW-001。用户转述外部部署的解释：旧SW使用`aa62d6`索引，不认识新`0bb43ff1`索引中的43个KTX2资源，因回源没有独立文件而404，拟增加解包兜底。实际Coze地址、失败请求及运行中的SW版本尚未取得，不能据此确认线上根因或部署正确性。

## 已核对事实

- 当前资源发布确实新增43份KTX2，旧索引不含这些条目，新索引包含全部43份。
- `src/assets/http-store.ts`的资源请求会在压缩版启动器提供版本时携带`sc2-index`；GPU贴图和预下载也经过该路径。
- `28c7987`的SW已经支持按请求参数读取指定索引。因此仅看到默认索引旧，不能推出新资源必然404。更早的`91b0775`尚无此能力。
- 启动器会注册并等待所观察到的更新及控制者，但没有向最终控制者确认协议能力和当前资源版本；已有控制者不等于已确认兼容。此为代码审查结果，并非本次复现真实手机更新竞态。

## 定向检查

使用实际Git中的SW处理代码、两份实际索引和14个GPU资源包，在隔离Node VM中模拟请求。模拟服务器对独立资源返回404；没有启动浏览器或访问真实Coze。

以上历史提交未与外部部署所称v3/v4建立对应关系。安装、激活、控制权切换、真实缓存和Safari行为均未在本检查中模拟。

## 对拟议修复的判断

提供与清单同hash的独立KTX2文件，可以覆盖SW不拦截或查不到条目后回源的路径，是可验证的兼容兜底。它不能自动覆盖SW主动返回502、错误数据、索引下载失败等情况，也不证明“任何SW状态都不会失败”。优先构建时解包并核对43份长度/hash；不在每次请求时重复解整包，不强制清除玩家数据。

发布前应核对实际失败URL是否保留`sc2-index`、控制中的SW源码/版本与作用域，并测试保留旧浏览器状态升级、新安装及再次进入。正常SW路径和直接资源路径均需校验内容，避免只验证HTTP200。必要时补兼容握手和受控重试，不能依赖无限刷新。
