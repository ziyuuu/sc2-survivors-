## 本轮实施

1. 移除构建的固定体积失败条件，继续记录真实字节数、SHA-256、分类体积、来源和派生关系。
2. 核查运行入口及动态引用后排除零引用发行资源；源文件留在开发素材库，不做磁盘清理。首次已发现三族载体替换后的旧 `model.droppod` 仍被保守装包。
3. 复用现有按内容散列的分片共享：相同模型贴图/完全相同资源只存一份，原图与有效派生不同时装包。保留逐字节重建验证，不能用有损压缩或删除有效动作冒充去重。
4. 输出相同内容ID分组、未证明可删除的候选和已排除项；“整类加载”只能证明当前消费行为，不能证明每个素材设计上不可替代。继续保留明确的审计缺口。
5. 重建离线包、运行打包/资产测试及三族离线存读；报告实际减少量，不虚报已完成全部冗余排查。

新增必要素材沿锁定SC版本、精确路径/依赖、原始散列、本地转换和播放核验流程获取；保留三族完整内容，不因下载量擅自替换或降质。若确实取不到原资源，记录具体缺失，不用“需要用户提供”代替已有获取途径。
