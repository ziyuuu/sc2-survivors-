# 体积优化版画质与解码优化 · 本地候选

用户于2026-10-28明确批准[优化计划](SITES_QUALITY_OPTIMIZATION_PLAN_20261028.md)的A～D及KTX2小样。实现进入共享源码，通过压缩版启动能力开关启用；本批没有提交、推送或部署，也没有修改线上数据库或玩家存档。V06保留待验证，原手机问题继续开放。

## 当前行为

- 设置→画面提供自动／高／中／低／自定义。预设同时应用渲染分辨率、世界贴图与既有特效策略，子项置于高级画面设置。手改子项保存为自定义；自动分辨率浮动不改变该状态。
- 新安装先读取本机线索，再在重资源前做约200ms、有600ms采样截止的小型CPU/GPU探测；缺少GPU证据不升高档。结果保存在本机，刷新复用。旧手动设置迁移为自定义，保留原生分辨率。相机、操作、音量、字体和账户设置不随画质切换。
- 高／中／低渲染比例分别为 `min(DPR,2)`、`min(DPR,1.5)×0.85`、`min(DPR,1)×0.70`。完整动作保留，15Hz仍只由用户手动选取。低档采用原有危险提示策略。
- 高档保留当前压缩资源原字节。中低档从原始运行时图像生成世界贴图变体，同时覆盖外部和GLB嵌入图片。保护UI、肖像、文字、队伍遮罩、法线、原版特效图集等；不能缩小或反而增大的资源继续用原载荷。231个变体模型的非图像bufferView逐段相同。
- 贴图在现有战场准备门中切换，先验证编码资源，再逐张替换已加载图像；主菜单改档后最迟在下次准备门生效。分辨率和特效立即应用。失败或取消回退旧档并释放暂存URL；World、伤害、订单、奖励与存档格式不因切档变化。
- 音效按当前部队、英雄、近期敌军和支援依赖准备；对白库和轮播顺序保留，只提前解码小窗口。未命中样本按需解码；取消/暂停后迟到的声音不重放。PCM按设备预算淘汰非活跃数据，活跃音源不被截断；极端情况下活跃声音可暂时超过软预算，诊断如实标记。
- 网络、模型、图片、音频解码分别限流，GPU上传分批让出事件循环。低内存预算与用户画质选择分开：手动高档不会解除硬件并发预算。GLB仍在Service Worker中展开。
- 包内存采用按字节LRU，在途请求单独去重。多页面预算取保守值；服务重启后使用保守缺省并重新请求页面握手。额外提供独立的256MiB哈希包磁盘缓存，避免内存淘汰造成重复网络下载，配额失败仍可继续加载；与玩家数据及资源IDB分开。
- 包、索引、清单、程序均有内容身份。请求固定本页索引，服务更新后可读取旧索引；更新工具保留旧入口和样式。发布时必须先上传新内容并保留仍在用的旧索引/包，再切入口。当前候选的清理不代表可删除线上旧版本。

## KTX2小样结论

只测试陆战队员、地面、法线、透明特效、队伍遮罩五组512以内样本，未进入正式资源。使用官方Basis Universal WASI编码器、本地UASTC+mipmap和Three.js 0.186.0的单Worker KTX2Loader；没有上传私有素材。

本机使用BC7时mip载荷约为RGBA估算的四分之一，强制无压缩能力的RGBA回退也成功。但五组文件均明显大于WebP，首次KTX2加载/转码约202ms，后续16～26ms，WebP约6～16ms。第一次WebP上传含驱动预热，不能拿它证明稳定性能提升。方向校正后查看了颜色、法线、透明和遮罩对照；尚无物理手机/完整材质视觉验收。**本轮保留分档WebP，暂不全面采用KTX2。**

## 复现与交付边界

1. 先核对当前源码及资源来源；`node --import tsx tools/build-quality-assets.mjs`生成输入，`python tools/build-quality-assets.py dist/quality-20261028/quality-input.json`生成变体。需要Pillow、本地原始运行时资源及当前压缩基线，不能由空目录凭空恢复私有源。
2. 显式设置 `SC2_WEB_OUTPUT=dist/quality-20261028/web`，运行 `npm run build:web`，再 `node tools/update-compressed-game.mjs dist/quality-20261028/public dist/quality-20261028/web`。更新工具保留既有资源身份映射，不再补丁替换压缩代码中的并发数字。
3. `node tools/verify-quality-assets.mjs`；用本机HTTP服务提供候选，运行 `verify-quality-browser.mjs <origin> low|high [constrained]`。其他专项入口见[工具导航](../../tools/README.md)。临时测试页面由 `build-quality-harness.mjs`生成，不能进入部署包。
4. 发布前重新核对静态资源限额、部署清单、旧版本保留和真实入口；本轮未更新两份Sites源码快照、没有上传、推送或部署。资源/原声视觉验收与原手机崩溃复测仍开放，自动档阈值仍需更多真实设备数据校准。

本轮未测浏览器总内存、物理手机温控/后台恢复或全游戏帧率，也没有把头显/触屏/CPU线程数当成GPU性能证明。后续优先用原手机复测第1～3关及切档；用户确认发布范围后再交运维更新线上。
