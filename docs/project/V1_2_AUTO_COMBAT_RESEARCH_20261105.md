## 1. 基线与结论

- 当前检出：`体积优化版`，HEAD `6510fb2a85a4140aecb6151ab0ab3132b42f239a`。工作区包含 1.1 教学候选及历史未提交改动；本次读取的是工作区源码，不是单独的 HEAD，也不是线上版本。
- 现有围攻位置、近战绕行、接敌冲锋、射线检查、弹丸结算与召唤归属可复用。主要缺口是各单位独立选敌，没有同时分配“可用攻击位置”和“足够击杀的火力”。
- 推荐保留当前固定步、地图寻路和碰撞求解器，增加小队层的约束分配：**先执行玩家指令；停下后联合分配目标和攻击位置；最后由原移动、攻击链执行**。
- 不推荐只修改距离评分，也不推荐先替换成通用行为树、HTN、ORCA 或新的物理引擎。前者无法保证指挥优先或近战容量，后者扩大实现与回归范围，且不直接解决火力分配。
- 已执行 8 个相关现有测试文件，77 项全部通过。通过的是旧行为与基础能力，不是 1.2 新规则。没有浏览器、GPU、自然战役或物理设备测量，不宣称性能与体验达标。

## 3. 一手资料与采用边界

1. Craig Reynolds 的 [Steering Behaviors for Autonomous Characters](https://www.red3d.com/cwr/steer/gdc99/) 将行为分成动作选择、转向与运动执行，并区分路径寻找和沿路运动。本项目可采用这种职责分离：目标分配不直接改坐标，避障不反过来改玩家命令。该资料不提供本游戏的集火规则或数值。
2. Guerrilla 的 [Killzone's AI: Dynamic Procedural Tactics](https://www.guerrilla-games.com/read/killzones-ai-dynamic-procedural-tactics) 说明结合地图静态条件和当前动态状态评估战术位置。这里借鉴“评估实际位置”的方法，把射程、可达性、占位和走路成本一起考虑，不采用其完整射击游戏 AI 架构。
3. UNC 的 [Optimal Reciprocal Collision Avoidance](https://gamma.cs.unc.edu/ORCA/) 通过速度空间约束和成对避让责任处理多主体避碰。它适合比较局部避让方法，但不负责挑敌、击杀预测、近战容量或玩家指令。**本轮不建议引入 RVO2/ORCA**，这是结合现有代码的工程判断；论文中的速度或无碰撞结论不能套作本项目性能保证。

以上为作者/开发商/研究团队原始资料。未采用转载教程作为算法依据，未下载或引入第三方实现。

## 4. 建议的决策与执行顺序

```text
现有输入 → 玩家移动/模式/技能意图
              ↓
真实已承诺攻击按原时序结算 → 当前战场只读视图
              ↓
可指挥单位筛选 → 合法候选及候选武器 → 候选攻击位置
              ↓
联合分配：可达位置 + 短时间有效火力 + 目标剩余需求
              ↓
单位执行前重验 → 原寻路/移动 → 原攻击与技能结算
              ↓
原接触修正 → 反馈到位/受阻/目标失效，下一次决策使用
```

全队重新规划按低频决策节奏运行，移动与伤害仍按 1/60 秒固定步。玩家新指令、目标失效、占位释放立即使相关计划失效，不必等普通选敌间隔。不得为了集中决策，调整原伤害、状态、死亡、掉落处理的先后顺序。

建议在 `step` 中现有状态更新后、普通单位循环前建立共享规划视图；`tickCarrierSubsystem` 和部分技能先于该循环执行，需要明确只参与哪些只读数据，后续使用同一分配策略但保留原结算阶段。执行时仍复查当前目标与位置，防止同一步内前一个单位已经杀死目标。

### 4.1 指令仲裁

- 优先级是硬约束，不做成“玩家命令 +100 分”。自动攻击、接敌、让路都不能生成与有效玩家移动指令冲突的目的地。
- 将现有 `manualMovement/marching/order.arrived/movePending` 统一为可查询的单位执行意图。全队锚点抵达不等于后排单位抵达，要明确尾队何时完成移动、何时恢复接敌。
- 连续方向输入只维持命令，不每帧重置攻击；真正改向、取消或新目的地才更新规划版本。暂停/恢复/特殊场景切换也要使旧规划失效。
- 可边移动边完成的攻击保留；不能随指令移动的自动前摇允许取消，沿用 `nextShotAt` 的真实射击截止时间，既不免费刷新也不额外罚一次完整周期。
- 已发射弹丸、已承诺范围效果和手动技能遵循原生命周期，不能为撤离统一清空攻击队列。手动引导技能中断、返还与否另列规则，不从“自动战斗”推导取消全部手动施法。
- 坦克移动命令触发收起；建议保留此前的手动模式偏好，抵达后才恢复该偏好，避免撤离中重新架起。这一“抵达后恢复”细节仍待确认。无手动偏好时才由自动模式策略决定。
- 眩晕、根缚、合法跨崖过渡、必要变形时长继续有效。不得通过移动命令绕过控制、强制停止或付费技能成本。

### 4.2 目标与位置联合分配

不采用“先全队选 Boss，再给所有近战找位置”的顺序。推荐流程：

1. 先保留仍可有效攻击、无需移动的单位位置，并读取在途承诺。
2. 为空闲单位产生少量附近候选，每个候选包含合法武器、可达攻击位置、预计到位时间、是否已被占用。
3. 近战只在得到可达位置后计入该目标的预计火力；远程必须有合法射程/射线，最小射程同样检查。
4. 先满足第 9 节的兵种职责与当前紧急威胁。在同一职责优先层内，若精英/Boss/lord 能在有限击杀窗口内由实际贡献覆盖，按到位和出手时间分配足够单位；其余兵力继续清杂。
5. 若不能覆盖，不把全队长期锁在高血量重要目标上；按第 9 节的远近战顺序，结合范围命中收益、武器克制、距离和旧目标稳定性处理附近杂兵。没有合适杂兵或不参与当前紧急任务的富余兵力仍可攻击重要目标。
6. 多个目标争夺同一攻击位置时，位置预留必须在本次分配中全局可见。不能只在“同一个敌人”的缓存里避免重叠。

采用确定性的贪心分配加少量局部替换即可，不先求全局最优匹配。建议排序为：已有有效位置/已承诺攻击 → 本轮任务优先级 → 到位和出手代价 → 稳定单位 ID。若反复抢不到位置，加入等待时长，避免大体型近战永久饥饿。顺序只作用于计划，不能重排整个实体结算循环。

目标层级先于连续评分：合法性、玩家意图、实际可达性是门槛；快速击杀的重要目标与普通清杂是任务层级；距离、克制和密度是同层比较。这样不会因为距离项权重变大就压过玩家命令。

### 4.3 击杀预测与减少过量攻击

使用有限窗口内的离散攻击时间线，而非简单 `总血量 / 面板DPS`。

- 读取当前冷却、已有前摇、预计到位时间与弹丸飞行时间，排出窗口内可能实际命中的攻击。
- 真实在途包从其当前飞行位置、冻结伤害和目标状态估计；即时命中已扣过血，不再次加入未来伤害。
- 已发射包、尚未发射的前摇、仅计划接敌的单位分别标记可信程度。软计划到期、目标失效、路径无进展或玩家命令改变时释放，不能让所有射手因“别人可能会打”而空等。
- 弹丸丢失/过期、目标隐身或换阵营、弹射换目标时，撤回或重新归属预计伤害。来源已死但原攻击仍有效的包，按原包生命周期保留。
- 按预计到达顺序在一个轻量的生命/护盾/已知吸收模型上演算，包含每次攻击的护甲结算；多发武器不能只对总伤害减一次护甲。
- 估算不掷暴击、不调用 `fire/hit/attackHit`，不消耗能量、RNG、冷却或奖励收据。未触发的随机额外伤害不当作确定杀伤。
- 先把可无副作用复用的算术拆为纯查询或纯函数，再以真实结算对照验证。未知英雄/精英连锁、目标防御特例、范围二次效果使用明确的低可信/保守回退，不能虚构“精确预测”。
- 范围收益与击杀承诺分开：敌群密度可影响瞄准，但不把未来可能进入范围的所有敌人都算作已经承诺击中。未来弹射尚未选中的目标也不提前预占。

最容易出现的实现错误是重复计算护盾、低估护甲后的多段伤害差异、把弹丸表现再算一次、在途预测已失效却长期保留。该部分应独立于 UI 和真实奖励账本。

### 4.4 近战、友军让路与接敌速度

- 扩展 `EngagementSlots` 为“查询候选/预留位置/更新实际路径终点/释放”四类操作，保留现有正在攻击的位置。普通空位查询失败直接换目标，有限局部搜索失败不能等同于数学意义上的永久不可达。
- 继续使用 `meleeApproachGoal`，先测试直达，必要时才进行局部搜索；对多个可用围攻点比较实际路线成本，不让近战为了同一敌人绕到远侧很久。
- 路径无进展时依次处理：复核终点 → 同敌换空位 → 换附近目标 → 无目标时就近候补。避免每帧左右换路或所有单位同时重规划。
- 让路优先通过空闲友军的短侧移和接敌者的局部路线解决，侧移目的地必须合法且不能导致玩家命令反向、把正在输出者推出射程。原硬碰撞继续兜底。
- 先调软避让余量；如果仍需缩小友军硬接触半径，必须作为独立待讨论改动，只针对双方均为普通移动友军的情形，不直接套用全局 `unitContactScale`。
- 接敌速度最后调。现有冲锋与新增普通近战加速应分开标识，普通加速不自动获得现有冲锋的穿体能力。到达有效位置或玩家移动即结束，已花冷却保持。
- 保留已有普通/精英爆虫、狂热者科研冲锋、潜伏者地下移动、飞行与跨崖单位的差异；不将所有短射程单位仅按兵种名字统一处理。

### 4.5 自动技能、变形与召唤

现有 AUTO-04 至 AUTO-07 仍在 1.2 规划中，不因本次聚焦近战而消失，也不在本次调研直接启动。

- 技能：保留施放执行器，增加只读选择条件；治疗看可恢复量，范围技能看实际命中收益，控制看剩余覆盖时间。自动施法不能改变已确认手动操作。
- 变形：先区分手动偏好与自动选择，再分别定义进入/退出条件和最短保持时间，防止地空目标交替时来回变形。移动命令覆盖妨碍撤离的自动模式，不替玩家取消所有手动技能。
- 召唤：保留母体、子体、付费补充和奖励资格的现有账本。航母母体不凭面板再贡献一份虚假主炮伤害；只计算实际可用子机。自主装备体和任务驻守单位有自己的范围，不强制跟锚点。
- 内容：AUTO-07 本轮仅核对行为接口所需的武器/单位身份，不增加 1.4 以后的新兵种、卡牌、美术和资源预算工作。

- 缓存按 World/战局/场景/命令作用域隔离，身份需要验证实体代次。新局、恢复、特殊关往返和目标死亡清掉派生预留；不能只依赖可重复的 target ID。

- 当前实际伤害函数含 RNG 与副作用，不能复制整个 World 试打一遍作为每个候选的估算。候选评分本身不新增随机抽取；相同新版本、同输入应可复现。新选敌改变后，真实击杀顺序可以变化，不能承诺与旧版整场随机结果相同。

- 预算不足时延后低优先级重新规划、复用合法旧计划；玩家新命令与非法目标清理不能延后。预算只约束决策，不裁掉真实伤害/状态固定步。

### 9.1 要求与证据分层

- 远程优先集火毒爆，然后处理已经开始造成杀伤的近战。
- 近战优先攻击高威胁远程，然后近战，最后毒爆。

文中毒爆对应本作数据中的 `baneling`（爆虫）。这两条是本作设计要求，不能包装成“暴雪公布的全兵种固定优先表”，也不能声称所有职业选手在任何战况下都使用相同排序。我们的目标是吸收职业微操中的威胁处理、分工与有效输出原则，以真实 SC2 机制为参考，转成可执行的本作规则。

### 9.2 全局约束与默认顺序

共同前提：玩家指令最高；目标必须可见、合法且在当前接战范围内，必须有可用武器、攻击线或有限成本的可达攻击位；不能隔墙追击、跨全图抢目标或穿过封锁去追后排。

| 己方职责 | 默认目标顺序 | 分配限制 |
| --- | --- | --- |
| 通用远程 | 接战范围内爆虫 → 正在对友军造成杀伤/已经贴身出手的近战 → 其他高威胁远程或施法者 → 其他合法作战目标 | 爆虫只分配足够可靠的拦截火力；剩余射手立刻处理下一档，不能全军同时浪费一次齐射 |
| 普通近战 | 可达且有攻击位的高威胁远程/施法者 → 可接触的敌方近战 → 其他普通远程 → 爆虫 | 后排不可达时处理前排开路；围满后分流。爆虫始终作为独立类别，不因本身短射程被重新归入普通近战档 |
| 范围远程 | 服从远程威胁顺序，在对应档选择实际可覆盖多个目标的落点 | 炮火优先覆盖爆虫群/正在杀伤的近战群；单只已被其他火力可靠覆盖后转打下一处，不为密度放任未处理的高优先威胁 |
| 反装甲/防空单位 | 先按武器合法性过滤，参与自己能处理且尚未覆盖的紧急任务；余力优先发挥武器优势 | 不能对地的单位不分配爆虫；不能让少数对空火力被普通地面目标长期占用；也不能因为“反甲”就完全无视无人处理的爆虫 |
| 己方爆虫/特殊接触型范围单位 | 按实际范围收益与可达落点选择敌群 | 不套用普通近战追单个后排的规则；保留本作爆虫恢复再攻击及精英特例 |
| 支援与子机 | 治疗/控制保留支援职责；子机经母体可交战范围参与分配 | 不虚构主炮伤害，不把任务驻守或自主临时体强制纳入整队 |

“精英/Boss 可快速击杀”作为**同一职责档内的优先机会及富余兵力收尾机会**。不覆盖远程的爆虫拦截和已经在杀伤的近战处理，也不把原本近战不应优先追击的爆虫 Boss 无条件升到第一档。一个高威胁远程 Boss 可以被近战优先接敌，但若短期杀不掉且有可处理杂兵，不能永久吸走全部近战。具体投入上限在候选验证中定，不拍定固定兵力比例。

### 9.3 不是只按名字排队：怎样判断威胁

1. **爆虫：** 先区分本轮能够接近并威胁友军的目标，再在同档比较预计接触时间、可造成的范围损失与实际击杀成本。已经逼近密集脆弱单位的爆虫，比远处或暂时无法接近的爆虫更急。拦截计算使用真实冷却和伤害到达时间，不能拿两秒后才能打出的伤害当成及时拦截。
2. **已经造成杀伤的近战：** 当前正在攻击友军，或最近有真实伤害且仍保持接触；建议将已经贴身、有效攻击前摇将完成的敌人一并纳入，避免必须先掉血才救援。已经转身离开、被长时间控制或失去目标的敌人及时降级。前摇预判属于本作建议补充，不冒称用户已单独确认的阈值。
3. **高威胁远程：** 依据当前武器、模式与可观察行为，评估短时间内可能造成的实际单体/范围杀伤及控制。正在展开输出的炮兵、能覆盖多人且即将出手的施法者通常高于普通射手；远处、不可达或当前无法发挥能力的单位不能仅靠兵种名称霸占首位。
4. **同档再比较：** 能迅速移除的威胁、实际武器克制、残余所需火力、到位时间、当前目标保持性。不是全队只打血量最低者，也不只按总面板 DPS 排序。
5. **有限情报：** 不读取战争迷雾下敌人的位置、未来指令或未来随机结果；只能使用已揭示目标和合法可观察行为。需要临近攻击/近期伤害信息时使用模拟数据，不从渲染画面反推。

“真实威胁”和“在途火力足够”都要有过期与重验，防止一个过去伤害过友军的敌人永久高优先，或一发已失效的弹丸让大家误认为爆虫已被解决。

### 9.4 职业微操原则在本作中的取舍

- 分工集火：拦截爆虫、清理贴身近战、压制后排可以同时发生，不让每个优先目标都要求全队参与。
- 保持有效输出：高优先目标暂时打不到时，攻击当前能打到的次级目标；存在可达侧路时只分配适合的近战，不能所有单位排队绕路。
- 控制过量伤害：已发射的真实攻击不取消、不转移；新攻击根据剩余需求分配。缺乏可信预测时保守保留少量补火，而不是让全队空等。
- 围攻而不堆叠：预留真实攻击位，分散到多个高价值目标。没有空位的单位不能计入短时击杀预测。
- 保护操作权：职业选手的后撤、分散和运输微操不自动扩展为本作全队自行撤退。自动接敌仍受玩家位置与主移动方向约束。
- 主动承伤是另外的策略：暴雪指南中的掠夺者承伤有依据，但派少数近战主动撞爆虫、牺牲单位或用昂贵英雄挡爆炸不在当前默认规则里，需另行讨论。
- 本作数值不同：玩家爆虫可恢复再攻、跳虫有针对敌方爆虫爆炸的既定减伤；预测必须读取本作当前规则，不直接照搬 SC2 对战中的自爆成本和交换比。

### 9.5 对实现调研的增量

- 在只读战场视图中增加职责、短期威胁与预计接触/出手时间。`observation.ts` 当前是可选贡献统计，主要记录己方对敌输出，不能直接当作“哪个敌人刚伤害过友军”的完整产品数据源；如需近期敌方伤害摘要，应在模拟伤害确认点记录有界、可重建的威胁信息。
