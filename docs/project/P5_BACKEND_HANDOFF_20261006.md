## 首次启用

1. Node.js 22 或以上。在应用包目录运行 `npm ci --omit=dev`。本版本新增 `pg` 依赖，不能沿用“完全无需安装依赖”的旧说明。
2. 将 `.env.example` 中的字段设为真实服务端环境变量。`SC2_BACKEND_ENABLED=0` 是默认状态，静态游戏与离线保存照常工作。
3. 正式开启前填写 `SC2_BACKEND_ENABLED=1`、精确 HTTPS `SC2_PUBLIC_ORIGIN`、持久化 `DATABASE_URL`、真实 `SC2_PRIVACY_OPERATOR`、`SC2_PRIVACY_CONTACT`、实际备份最长保留天数 `SC2_BACKUP_RETENTION_DAYS`（1—365），以及绝对路径 `SC2_DELETION_JOURNAL`。日志路径必须在独立持久卷，不随数据库旧备份一起回滚。数据库连接的 TLS/CA 由部署环境配置，不关闭证书验证来凑通连接。
4. 执行 `node backend/cli.mjs create-admin 管理员名`，通过标准输入传入至少14字符密码并结束输入。不要将密码放在命令参数、Git、网页或共享日志里。需要联系方式导出权限时，在名字后明确加 `--contacts`；没有默认账号或公开注册。
5. 启动 `npm start`。默认端口3000，平台可用 `PORT` 指定。入口 `/admin`。API 必须通过相同 HTTPS 源访问，不开放跨域 `*`。反向代理必须转发原始 `Origin`，不能自行伪造授权头。

生产 `DATABASE_URL`、域名、管理方、联系渠道、平台日志期限与备份计划尚未提供，本轮不能验证真实线上权限或接收。上面是可执行交接流程，不表示生产已经启用。对外声明必须与这些实际配置一致。

## 仅本机检查

源码仓库已安装开发依赖，可运行 `npm run typecheck`、`npm test`。交付包如需独立本地试用，运行 `npm ci`，启用 `SC2_LOCAL_DEV=1`，填写 `http://127.0.0.1:端口` 的精确源、真实本机说明字段、持久化 `SC2_PGLITE_DIR` 和删除日志路径。然后按同一 CLI 自行建立管理员。

PGlite 是仅本地使用的文件持久化 PostgreSQL WASM 引擎；它用于本次 SQL/事务/重启检查。生产分支使用 `pg` 连接外部 PostgreSQL，本机验证不等同于生产数据库连通与并发验收。本地 HTTP Cookie 例外仅允许显式本机模式，生产必须 HTTPS/Secure Cookie。

## 维护和备份恢复

- 启动后执行一次维护，运行中每小时刷新日汇总并清理到期数据；不依赖游戏网页打开。停止的服务不会运行计时器，平台若需要停机期间也按时清理，应独立调度 `node backend/cli.mjs maintenance`。
- 原始事件/会话90天；战局/关卡摘要180天；浏览器去重索引最后活跃365天；无浏览器标识日汇总730天；反馈/联系方式180天；管理员审计90天。
- 删除操作先将主体哈希和期限写入独立 JSONL 删除日志并 `fsync`，再提交数据库删除事务；数据库也保存删除清单。保留至少实际备份期限加一天。该文件不记录原浏览器ID、反馈正文或秘密凭据。
- `node backend/cli.mjs export-deletions 新文件.json` 导出当前删除清单，文件须独立保存。独立日志为追加记录，运维轮换前必须保证覆盖所有仍可恢复备份的删除请求；本应用不自动删除该日志。
- 恢复数据库时，先保持服务对外关闭，将独立删除日志/清单恢复到正确持久卷，执行 `node backend/cli.mjs replay-deletions 文件路径`，再执行维护，核对受删记录不存在，最后开放流量。不要先上线旧备份再补删。
- `node backend/cli.mjs disable-admin 名称` 禁用账号并吊销所有会话。导出联系方式是独立权限和单独动作，写入审计；不会自动发邮件或联系反馈者。

当前迁移为独立业务数据库版本1，只做建表、索引和新增反馈授权版本列，不 DROP 既有表。战局 schema23、成长 profile v5 不变；没有上传完整存档或将本地进度迁入数据库。
