## 1. 卡牌、按钮与进入战场的对齐

**确认存在卡牌布局问题。** 目前卡面由弹性立绘区和随文案变化的内容区组成；累计强化信息增加行数后，会反向挤压图片高度。不同卡的标题、效果和图片底边没有共用行高。底部购买区虽各自固定，不能保证内部所有层级同线。`reference-card.ts`、`reference-r12.css` 和后加的 `battle-feedback.css` 共同决定最终尺寸，补丁之间缺少统一尺寸约定。实际 100%/150% 字号截图均复现了不同卡种的立绘/标题错位。

**进入战场也已复现。** 四种尺寸按钮中心分别偏左 191、191、105.30、197 CSS px。原样式仍以 `#enter-battle` 为选择器设置 flex:1，但正式按钮实际采用 `data-action="flow-continue"`，没有这个 ID；唯一按钮因此贴在装载操作容器左侧。这是明确的选择器接入遗漏。

修复方式：

- 为同一屏的三张卡定义共同的结构：卡类/品质、立绘、标题、风味文字、实际效果、已购与累计、价格、购买按钮。采用共同网格轨道或同排高度测量，不再让文案独立改变立绘基线。
- 卡面标题保留合理换行；累计值允许换行但不顶住价格。缺少累计信息的卡保留同排对齐所需的内部空间，不增加空卡或额外说明。手机单列不强行保留桌面的空白高度。
- 购买按钮的宽度、左右内距、价格下方间距一致；禁用、折扣、已购买状态不改变尺寸。按钮文字与图标按整个组合居中。
- 手机 150% 字号下，底部“设施调整、刷新、返回前线”已出现不合理逐字断行，纳入同一项处理；短横屏还需逐张滚动检查价格和购买区能否完整到达，不能只检查首屏截图。
- “进入战场”修正为实际按钮选择器，按 `.loading-actions` 和实际可见内容区中心定位；只剩一个按钮时仍应居中。核对按钮边框、文字及装饰切角，避免只测文字中心。

验收：1203×1063、1440×900、390×844、844×390；另补 320px 窄屏；100%/125%/150% 三档字号。同排标题/立绘/价格/按钮基线误差不超过 1 CSS px，单按钮中心误差不超过 1px。覆盖最长卡名、累计换行、无累计、满级、折扣且不足、售罄和手机滚动。不得缩短真实效果说明来通过检查。

## 4. 精英及 Boss 随机掉落直接入队

**确认实际存在额外领取流程，不只是 UI 原型。** `dropBossLoot → collectBossLoot → bossLootQueue → claimBossLoot` 会打开领取页面并阻断战斗。实际探针拾取后入队数为 0、队列为 1、`requiresPlayerDecision=true`。普通精英掉出的精英/英雄奖励也会进入这条队列。历史搜索显示这条机制在本次 UI 整合之前已存在，不能将其起源归给上轮样式修改。

修复：

- 保持击杀掉落、原概率/品质、掉落位置与现有拾取触发，拾取后直接结算入队/晋升，不打开首领奖励面板、不提供再次选奖励或选变种的步骤。这里按“地面掉落被拾取后直接入队”落地，不擅改成死亡时远程自动领取。
- 掉落时确定随机身份并保存，读取或拾取不得重新抽奖；同一凭据只结算一次。统一普通精英、Boss 和关卡转换回收的处理入口，移除手动队列路由和暂停按钮中的领取项。
- 已有同精英按原晋升机制处理；新精英有空位则加入。满员需要替换普通兵的情况，计划自动使用合法候选中最低军衔者、同级按稳定 ID 选取，保留已有精英及已付训练预留。这是实现“直接入队”需要明确的边界，不能在代码中随意选择或吞掉掉落。
- 无任何合法入队/晋升对象、英雄名额已满的情况，优先沿用现有合法奖励池/补给回收规则，不新增“稍后领取”页面，不凭空提高资源回收价格。具体自动替换策略和无合法对象的回收结果会在实现前的规则表中单列。
- 若当前存档已经带有待领取队列，恢复后应一次性按确定的规则结算，不丢掉既有奖励。是否需要变更当前存档结构取决于最终实现，不能沿用旧字段却改变其解释。

验收：精英/Boss/领主、各品质、同身份晋升、满员替换、满军衔、英雄上限、拾取前后保存、重复拾取、跨关回收、恢复已有队列；无领奖弹窗，无重复发放，不改变敌人参数和原掉落概率。

## 6. 商店是否只抽到“已解锁且正在生产”的兵种强化

**当前答案：不是统一按此条件。** 原生 `inspectReinforcementPool()` 的 16 种组合探针结果如下。

| 类别 | 当前主要进入条件 | 是否要求当前启用产线 |
|---|---|---|
| 兵种训练加速 | 在生产方案 outputs 内、未停产，且 `availableFamily` 满足兵种解锁与相关关卡门槛 | 是，表示选入启用产线；不是要求这一帧恰有训练订单 |
| 恢复/能量强化 | familySlots 中有该兵种，且有存活实体和相应恢复/能量能力 | 否；不是统一查解锁或当前产线 |
| 全军火力/全军防御 | 全军类型、各自累计上限等规则 | 不绑定单个兵种 |
| 增援牌 | 本族、设施、研究等级、容量和落点等 | 与兵种强化不同，不按相同筛选 |

另一个边界：训练加速的 `availableFamily` 本身不核实当前实际设施数量；理论异常状态下，已解锁并启用的配置不一定表示设施真的在工作。相关源码：`expedition-drafts.ts` 的 `selectedFamilies/effectLegal/reinforcementPool`、`expedition-production.ts` 的 `availableFamily`。

处理计划：先固定这张真实规则表。如果目标是统一为“已解锁且启用生产的兵种”，将训练、恢复、能量牌共同调用该资格函数，并核实有可用生产设施；全军牌保持全军逻辑。存活但已停产/被救援得到但未解锁的兵种是否仍允许强化，会因此改变，必须作为明确规则决定，不能当 UI 整理顺手修改。本次只确认现状，未改抽卡池。

验收：解锁/未解锁、活着/阵亡、选入/未选入、启用/停产、设施存在/缺失的组合；队伍刚减员或训练刚完成不使资格随机闪烁；不改变全军牌的效果和权重。

## 7. 黄圈、红圈来源与移除范围

**确认渲染器会主动绘制多类圆圈。** 不全是有实际范围伤害的技能：其中包含精英/Boss/领主身份圈、单位状态圈、虫巢或经济目标提示，以及技能预警。颜色本身不代表必定发生特殊效果，因此会出现“看到圈却没变化”。

修复：按语义列出并去除玩家指出的地面黄色/红色身份与警报提示，信息保留在小地图；不要全局删 `RingGeometry` 或所有以 ring 命名的效果。真正的枪焰、弹道、命中、爆炸、持续攻击效果、己方指向性技能落点和选中反馈分别列入保留项。实际危险判定不因移除装饰圈而变化。涉及 `battle-renderer.ts` 的 enemyTier、状态、hive warning、经济提示及相关预警绘制分支。

验收：五张地图、三个种族、精英/Boss登场、经济目标及玩家主动技能；地面无被取消的黄红警示圈，小地图对应位置与敌方身份提示可见；攻击事件、命中次数、范围数值和最终 World 状态对照不变。不能通过关掉整套特效来消除圈。

## 8. 五人满员后，增援转晋升

**确认是规则分支不一致。** 普通培养已有补人/最低军衔晋升能力，但商店 `supplyEligibility()` 只检查剩余身体名额，`applySupply()` 也只造 body；空投乘员目的固定为 body。24 个直接/空投探针中，5 人、低军衔仍被 `capacity` 拒绝。

修复：统一援军和当前培养的容量规划。先补缺位，再将剩余额度转为可晋升军衔；本次购买在普通兵已满且全部达到当前军衔上限时，才因容量原因禁用。资源不足、未满足明确前置等原因仍可禁用，不能把“仅满军衔”误解为免费或跳过前置。

采用现有普通兵最低军衔优先规则；保留原卡的数量、价格、空投/直接到队时机、虫族双体计数、已付款订单和军衔预留。卡面直接写本次结果，如“增援 1 / 晋升 1”或“晋升 2”，购买前后即时更新。不要新增多选晋升页面，也不要把精英/英雄当普通兵升阶。

边界：混合军衔、只有 1 个可升级额度却出现 ×2/×3 卡、途中减员、已付空投未到队、虫族半对存活，都要使用同一结算计划。部分额度不足的卡不能无提示吞掉剩余价值；需在具体规则表中确定是否限制该数量报价或如何等值处理，不能直接扣全额。

验收：4/5 人 × I～V 阶 × 直接/空投 × 1/2/3 数量；支付、到达前后存档、重复事件、预留与退费；普通培养与商店购买不再有两套相反的容量定义。

## 9. 新设施自带基础兵种解锁

**确认当前缺失。** 真实购买重工厂和星港后设施已建，但 `unlock.hellion` / `unlock.medivac` 均为 0，对应生产输出为空。现 `applyDevelopment()` 的设施分支仅增加设施；“建成设施”和“单独兵种解锁”完全拆开了。

修复：首次建成重工厂同步授予恶火解锁，首次建成星港同步授予医疗运输机解锁；若对应产线为空，设置该基础兵种为默认启用输出，让首次建成即可使用。用户本条“医疗兵”按现游戏星港单位医疗运输机处理，不新增步兵医疗兵。

同一次原子购买完成扣费、设施、解锁和默认输出；重复扩建设施不重复赠送解锁/单位/资源，不覆盖玩家已经选择的生产方案。基础解锁不再作为同线必须重复购买的项目。其他种族先对照既有基础单位映射，不能仅据人族两条反馈擅自增加额外赠品。

验收：首次建设、扩建、已手动解锁后建设、多个设施、资源不足和存档恢复；旧关卡门槛、科技链、训练时长及已付订单保留。

## 10. 设施同级，解锁与生产在一起

**确认现入口分散。** 研究与强化在上方，设施调整在底部；设施面板又将设施/训练/当前科技分为独立页签，玩家需要切换才能理解“解锁后在哪里生产”。

修复：根工具组采用同级四项“设施调整｜武器与防护研究｜强化一览｜休整”。桌面紧邻，手机按空间换行或横向滚动，不把按钮分散到不同区域。删除底部重复设施入口。

设施内部按兵营/重工/星港等产线组织，在同一兵种条目显示：锁定及前置、解锁价格和动作、已解锁、是否选入/启用生产、训练状态。由同一条目完成解锁和生产设置，复用既有业务命令。武器与防护研究继续独立；强化一览继续分累计总值与已购来源。虫族设施分配、双输出和原战术培养控制保留，不能以整理面板为由删除。

验收：首次新设施到生产基础兵种无需跨三个页面；未解锁理由明确；解锁/停产/切换不丢已付训练；PC 横排与手机竖屏都可操作。

## 11. 资源不足提示统一

**确认。** `referenceCard()` 计算出了 `short`，但显示角标时折扣优先，导致“买不起的折扣牌”仍只显示 −15%。探针确认 short=true、购买禁用，却没有“资源不足”。部分详情/精英合约也没有统一引用相同的支付状态。

修复：折扣信息与不可操作原因分开；不足时在卡面价格/按钮附近一致显示“矿不足”/“气不足”及缺口，折扣不覆盖原因。购买、详情确认、设施、研究、休整/复活和刷新共用报价/可支付状态。卡面状态优先区分已购买、上限、前置未满足、资源不足，不能把所有禁用都写“待解锁”。

原价格、天赋免单、折扣和扣款源保持一致；每次钱包/条件更新同步重算。无需新增提示页面，也不加入“系统将验证”等开发措辞。

验收：仅缺矿、仅缺气、都缺、刚好够、折扣不足、免单、价格变化、售罄、满级、待生产、刷新；所有按钮原因与真实命令结果一致且不遮住价格。

## 12. 减员红边、Boss 加剧、登场震屏

**这是新增表现需求。** 当前没有对应的减员/Boss 红色屏边层；已有镜头震动主要来自特定攻击命中，不是 Boss 登场反馈。

修复：表现层监听实际我方永久部队死亡事件，触发短促红色边缘晕染；Boss 存活时提高减员反馈强度并保持轻度边缘提示；Boss 首次进入战场触发一次短震动。中心战场、血条、HUD、摇杆和技能位置保持可读，屏边层 `pointer-events:none`。

建议初值供视觉验收：普通减员约 0.6 秒淡出，Boss 期间减员峰值增强约 30%，持续红边低于瞬时峰值；登场震动约 0.5～0.8 秒并衰减。数值是表现提案，不是已修改的规则。尊重现有镜头震动/减弱动态设置，暂停、关间及读档不重复震动。

排除召唤物到期、航母子机、临时单位、主动替换或移除；同一死亡/Boss 不重复触发。多个 Boss 的加剧强度封顶，结束后恢复。复用渲染观察或只读事件，不写入伤害、AI、出兵、时钟和存档的战斗参数。

验收：有/无 Boss、连续减员、英雄阵亡、Boss 死亡与新 Boss 出现、恢复存档、暂停、关闭震动、手机横竖屏；无整屏闪白、无持续强晃、无额外输入阻挡。仍需用户对真实画面和舒适度验收，不能用脚本代替。
