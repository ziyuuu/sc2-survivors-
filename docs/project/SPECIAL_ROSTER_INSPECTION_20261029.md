# 挑战关小兵异常死亡调查

2026-10-29，`V06-SPECIAL-ROSTER-001`，归属 V06。用户要求查找原因；本轮只调查，无游戏逻辑、UI、玩法数值或部署修改。共享源码 HEAD 为 `674c528`，另有解锁、虫族近战及舰装等其他线程未提交改动，未撤销或提交它们。

## 结论

已在当前本地源码复现“5枪兵＋1雷兽，进挑战关只剩1枪兵，返回4枪兵死亡”的状态链。触发因素是**受伤成员与舰装生命加成跨场景迁移不完整**，不是特殊关只允许最高军衔成员参战。未取得原玩家存档、装备及线上构建，因此不声称已完全还原玩家的每个条件。

1. `special-stages/runtime.ts` 对资源关、竞技场、横穿虫群使用 `specialMembers`，会选入全部合格永久成员，没有按军衔只取一人的逻辑。
2. `special-stages/bridge.ts:parkNormalWorld` 复制成员当前/最大生命并新建 `newStarshipRuntime`；原 `starship.native` 是以实体对象为键的 WeakMap，保存装备加成前的属性。它既不能随结构克隆自动迁移，也没有在新实体上重建。
3. 入场调用 `refreshStats`。`starship/runtime.ts:detachEquipmentStats` 查不到旧基准，无法先去掉舰装层；`combat/expedition-combat.ts:refreshExpeditionStats` 把装备生命池上的已损生命，直接从较小的原生生命池扣除，再应用装备加成。结果是无伤害来源也会丢血，严重时归零。
4. 返回时 `restoreSpecialBody` 把错误生命写回原成员，`resumeNormalWorld` 将零生命成员设为死亡。因此进入时已不见这些成员，回来才看到原位置的死亡表现。并非一定走“找不到成员则判死”的分支，本次是成员仍在、生命已为零。
5. 返回还会 `w.starship.native.delete(old)`；下次正常属性刷新也可能再次错误扣血。诊断中仅临时补上入场基准能保住入场生命，但返回后的第一次刷新仍会杀死同4人。修复必须覆盖两个方向，不能只补入口。

例：一名一级枪兵原生最大生命51.75，加一件蓝色防御散件后151.75，受伤剩30.35（20%）。切场景时旧基准丢失，把已损121.4直接从51.75扣除，生命被截为0；没有发生敌方攻击。复现里的五级枪兵设为90%生命，所以幸存，但也错误失血；这不能推断原玩家的具体受伤分布。
