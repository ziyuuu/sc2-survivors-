# UI 规范与已确认界面约定

2026-10-27 从既有用户决定整理。本文件汇总仍适用的约束，供 AGENTS 目录按任务引用；不是新一轮 UI 修改授权，不恢复旧页面、旧天赋或过期原型。

## 先确认具体变更，再实施

- 任何 UI 新增或修改都必须先列出具体变更并取得用户明确确认，包括布局、字体、按钮样式、文案、状态提示和功能入口位置。功能实现授权不自动等于 UI 改动授权，不在其他任务中顺手扩改 UI。
- 用户已确认的具体范围内连续实施，无须逐步重复确认；范围外的新改动先说明并等待确认。明确点名某项 UI 修改的用户指令本身可作为该项授权，不重复询问同一件事。
- 说明方案时明确具体页面、当前内容与拟修改内容。不要以“精简”“优化”“统一”为名扩大删改范围。
- U06 曾因扩改首页和暂停页被整轮回退；后来的批准仅针对具体清单。不能把回退版本或旧截图当现行规范。

## 极简文案的七条规则

1. 默认采用极简界面文案，只保留必要的标题、名称、操作、数值、状态和结果。
2. 禁止自动添加解释性副标题、卡片描述、灰色小字、冗余提示条、装饰性标签和页脚说明。
3. 不得通过增加辅助文案来弥补交互设计问题。优先调整布局、命名、视觉层级和状态反馈；实际调整仍须在已确认范围内。
4. 不允许为了填补留白而创造文字内容。留白是正常的设计元素。
5. 只有错误恢复、关键风险、复杂操作确实需要时才提供辅助说明，且保证可读性；重要信息不得使用低对比度小字。
6. 游戏和交互式 Demo 优先通过视觉、动画、图标和操作反馈表达规则，避免说明书式界面。
7. 完成 UI 后执行文案审查：逐项识别不影响理解和操作的文字，在批准范围内删除。不得把删除的冗余内容转移到 tooltip 中。

简要/详细分层只用于已确认需要的规则说明：简要层交代用途、核心收益和重要代价，详细层保留数值、条件、上限、限制和差价。不能为了短文案删掉必要代价，也不能用“详情”恢复冗余解释。已批准的任务目标、商品说明、错误恢复等不是一律删除对象。参见 [趣味 UI 合流约定](FUN_UI_MERGE_GUARD_20261022.md)、[U05 文案结果](../../reports/qa/u05-copy-20261023.json)。

## 自动保存、管理入口与必要提示

- 后台自动保存保持安静，不在正常游戏各页显示“已保存”“保存中”“操作完成”等日常系统状态。
- 真实保存失败、无法继续及必要恢复操作要明确且可操作；保留 D05 的失败保护，不向玩家直接暴露底层异常原文或测试标记。
- 读取、导入、导出等存档管理功能集中在设置，不擅自在主菜单、暂停主操作、关间、舰装或结算页增设入口。正常续局使用已确认的“继续游戏”。
- 2026-10-28 用户确认：新游戏可直接覆盖旧局，不要求先结束或结算旧局；出发前仅提醒一次覆盖。沿用现有部署确认页显示提醒，不叠加重复弹窗。原局未带出战利品放弃的必要后果在同一提醒说明。
- 首页免责声明保留用户恢复的原位、原文和原样式，不能作为冗余系统提示删除。
- 仅在已确认清单内调整装饰图标。U06 删除暂停“继续”的播放图标和“设置”的齿轮图标，不构成全局删除图标、放大字号/按钮/弹窗的授权。

## 视觉语言、布局与输入

### 体积优化版画质设置

2026-10-28用户明确批准[画质优化计划](SITES_QUALITY_OPTIMIZATION_PLAN_20261028.md)中的设置页清单。仅压缩版启用“自动／高／中／低／自定义”整体预设；高级画面设置区分渲染分辨率与贴图质量，保留既有特效及动作子项。手改子项记为自定义；自动分辨率浮动不改为自定义。贴图在现有准备门切换，确有待生效变化时显示必要状态。相机、字号、音量、输入及其他页面不随档位变化；旧手动偏好不被默认自动覆盖。当前实现和验证范围见[实施记录](SITES_QUALITY_IMPLEMENTATION_20261028.md)。

- 延续已确认的 SC2 风格：三族气质、金属面板、切角、克制的种族色和既有美术。菜单封面使用融合的角色立绘，不自行换成战场模型或新主题。
- 优先保留战场可见面积；用肖像、血盾条、冷却遮罩、必要倒计时、图标和真实视听反馈表达状态，不铺设教程式说明。必要状态不只依赖颜色。
- 沿用当前已确认的布局。竖屏右侧士兵栏、横屏底部 UI 的位置、尺寸、边框、排列和分页/滑动方向保持；小地图外框、内部图面和右侧工具列作为整体，不单独拉伸或搬动。
- 桌面、手机横屏、手机竖屏使用统一的按钮与字体规范，同级操作不混用无依据的样式和字号。三种布局分别验证阅读、滚动、焦点、点击和遮挡，不以缩放一张截图代替响应式检查。
- 桌面/非移动版本不显示左下摇杆，包括缩窄的桌面窗口；移动横竖屏保留摇杆。不能只靠窗口宽度把桌面误判成手机。
- 保持原鼠标/触屏控制和用户偏好；试玩切换/重试不强制改为键盘模式。特殊关使用普通游戏相机，不恢复毒爆专用俯瞰，也不擅自居中、缩放或改变安全边距。

来源：[SC2 视觉基线](SC2_UI_DESIGN_BASELINE_20261005.md)、[HUD 视觉语言](HUD_VISUAL_LANGUAGE_20261003.md)、[趣味 UI 合流约定](FUN_UI_MERGE_GUARD_20261022.md)。早期“所有版本两行底栏”、旧天赋页面、固定字号和样板细节不覆盖后来的布局与授权；旧图只用于对应的视觉参考。

## 2026-10-29 已确认的关间与装备操作

用户在[反馈方案](FEEDBACK_PERFORMANCE_20261029.md)后确认先实施撤离、装备操作、商店与按键音，孤星、掉落和BGM后置。本次具体界面范围如下：

- 每个正常战役/无尽关间，在继续操作区显示“撤离”，舰装原入口共用同一资格与结算。特殊关先返回正常关间。
- 装备列表保留品质底色，增加“可装备／局外更换／需清洗／来源锁定”等真实资格及“可装备”筛选；详情给出同一规则的原因，不把效果未激活当作禁止装备。
- 背包/仓库“全选筛选结果”覆盖分页，提供取消选择；搜索或筛选变化清空选择，翻页和排序保留。分解、销毁沿用确认件数、粉尘及保护项预览。
- 关间背包提供“一键换装”，只选本局合法普通散件，按品质选择，同品质保留现装，保护套装、模块、特殊、锁定和收藏装备。沿用同级按钮和三端布局。
- 主菜单起统一播放既有短按键音；新默认界面音量25%，已有音量及静音偏好保持。BGM、音乐滑条和新音源本轮不加入。骰子详情改为准确说明权重增量与随可售商品变化的实际概率，不显示不再成立的固定百分比。

实现与验证范围见[本批记录](FEEDBACK_ACTIONS_20261029.md)。

## UI 验证与交接

2026-10-29 兵种解锁修订：用户确认首次解锁只自动排入一个运行中且有空位的兼容生产组；雷神等重型兵种提前解锁时可先预排，第10关开工。现有“设施调整→布置”中的兵种按钮允许取消这种提前预排，取消后仍遵守原训练门槛；不新增按钮、文案或布局。卡面循环箭头保持简略／详细说明切换，本次未授权更换图标。实现及本地检查见[解锁反馈修复](UNLOCK_FEEDBACK_FIX_20261029.md)。

2026-10-29 后续BGM确认：用户接受[试听与接入方案](BGM_AUDITION_20261029.md)并回复“就这样吧”。现有设置→操作的音量区，在界面音效后加入同样式“背景音乐”滑条，默认15%，0为静音；保留既有主音量、战场音效与界面音效偏好。音乐随主音量控制，设置单独记忆。本次仅此一个设置项，不新增播放栏、曲名标签或其他页面入口。菜单/局外与关间的切页续播、入战淡出和后台暂停见[接入记录](BGM_INTEGRATION_20261029.md)，暂不部署。

按照这次实际修改检查对应页面、状态与三类视口；看真实渲染、内容可达和交互，不只判断 DOM 存在。检查焦点、滚动、重叠、不可读小字、状态真实性和暂停/恢复。复用已有检查时注明版本与范围，不自动开展全目录逐项截图。

提交说明同时写清用户确认的范围、实际改动、检查及未覆盖设备。静态原型/独立对象、正式组合战场、模拟触屏/物理设备、自动检查/用户认可分别记录。详细截图等只在当前工作中保留，结束遵循 [产物保留规则](ARTIFACT_RETENTION.md)。
