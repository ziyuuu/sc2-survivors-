# R01 真实 GPU 成本与零权重地表采样 · 2026-10-20

用户授权“开始 R01，完成后核验并更新看板”。本批已本地实现并核验：以 S07 最终冻结输入为基线，定位实际 GPU 绘制成本，只实施地表零贡献纹理采样优化。[看板](PERFORMANCE_BOARD.html) · [范围报告](../../reports/qa/performance-r01-20261020.json)。50 项完成 32、剩余 18；下一项 R02 尚未开始。

## 改动

生产代码只改 `src/render/terrain/layered-ground.ts`。每层原有两种尺度的颜色和法线共四次纹理采样，仅在该层最终混合权重严格大于零时执行。没有用近似阈值丢弃小权重；原权重、材质纹理、宏观变化、法线反向旋转、粗糙度、金属度、查尔发光、揭露和底座融合公式保持。

UV 导数在分支外计算，分支内使用显式梯度采样，保留材质交界的 mip 选择。不能把隐式导数采样直接放进随像素变化的条件分支；依据 [Khronos GLSL ES 3.00 规范](https://registry.khronos.org/OpenGL/specs/es/3.0/GLSL_ES_Specification_3.00.pdf) 的导数及 `textureGrad` 规则。程序缓存键同步更改，避免复用旧着色器程序。

接触深度材质原本已有 `colorWrite=false`，折射也原本在没有活动面时绕过；这些不计作本批新增优化。保留完整阴影、接触阴影、折射、透明效果、辉光和 ACES/sRGB 输出。300 上限、4∶4∶1、模拟、经济、五图内容和存档延期边界保持。

## 测量方法

Windows Chrome 155，ANGLE/AMD Radeon Graphics、D3D11，1440×900、DPR 1，native 分辨率、普通/英雄完整效果和完整动画。地图 recipe version 3、seed 529。使用 `EXT_disjoint_timer_query_webgl2` 的真实 GPU 查询结果；不是 JS API 调用耗时。GPU 和 CPU 分开保存，不能相加。

分阶段分别测总提交区间、接触阴影、其深度/AO 子项、阴影、主场景、地表、折射、辉光及最终输出。主场景包含阴影，地表只是主场景的一部分；接触阴影包含深度与 AO。后补透明/不透明网格绘制的独立查询和，排除阴影阶段。各阶段在不同采样窗口测量，存在频率/调度波动，既不能相加，也不能据总区间减去其他阶段推算差额。总 GPU 区间可能包含 CPU 提交间隙，不等于纯片元忙碌时间。逐绘制查询本身有诊断开销。

正式同页 A/B：由两份实际生产工厂提取五图完整地表片段，在同一真实场景和原材质/纹理中交替编译，只替换精确匹配的地表片段。提取工具仅用占位 Texture 取得代码，浏览器使用全部真实资源。每场景六轮，交替先后顺序；每阶段排除八帧预热，记录二十帧，共七场景、168 个采样窗口。所有帧保留，不挑最好值。每窗口 World 字符串快照精确不变、disjoint=0、查询回收完毕，地表及总区间每帧均有正 GPU 结果。

实际候选构建另行启动，无 A/B 注入；从真实已编译 GPU 程序读取 shader source，与上述五图候选片段匹配。源码/输入哈希和浏览器运行分开绑定，不能将同页替换直接当作最终候选已验证。

## 阶段诊断与分辨率压力

基线包括近战 300、远程 300、治疗、护盾/风暴/光束、航母与装备、最终主巢及空场。初始三个场景每阶段十六帧/五帧预热；其余四个场景及分辨率诊断每阶段二十帧/八帧预热。各类数据属于不同窗口，不与正式六轮 A/B 混合。

远程 300 先导中接触阴影约 4.06ms（深度约 3.35ms）、阴影约 7.23ms、主场景约 17.91ms、折射约 0.75ms、辉光约 1.46ms、输出约 0.72ms。近战 300 后续窗口接触约 2.63ms、阴影约 1.79ms、主场景约 11.16ms。它们反映密集场景还有多项成本，不能把所有问题都归为地表采样。航母场景主场景单独窗口约 30.85ms、总区间另一个窗口约 10.97ms，说明本轮时序波动明显，原因未定位；不能将这些阶段值拼成一帧预算。终端进度打印取偶数样本的上中位位置，正式汇总统一取中间两值均值，原打印保留。

分辨率只用于诊断，串行 100%→75%→50%→100%，完成后恢复 100%。远程 300 总区间约 23.54→23.26→16.32→23.04ms，辉光约 1.33→0.78→0.47→1.37ms。它并不随像素数量同比缩短，不能据此承诺自适应解决全部密集性能问题。空场 50% 个别阶段异常增大也保留。没有据诊断修改生产默认画质。

实际候选另测主场景网格，不透明/透明逐绘制查询和分别为：近战 300 约 8.80/1.67ms，远程 300 约 12.33/1.28ms，治疗约 3.58/0.65ms，航母装备约 4.37/1.96ms，主巢约 2.61/0.61ms，护盾风暴约 9.00/2.11ms。每项二十帧、八帧预热，排除阴影/接触/折射。它是实际提交的分类成本，不是片元覆盖次数或透明 overdraw 比例，也不是与上述基线分阶段窗口可直接相减的优化收益。

## 对应审计去向

- **R09**：采纳严格零权重层跳过采样。全混合区域仍需所有贡献层，不减层、不改纹理、不过滤小权重。实际 GPU 与五图材质边界有对应证据。
- **R10**：当前 bodyVisible 仍取镜头可见与阴影投射范围的并集，接触/主场景共用批次。本批保留；把镜头外投射体直接剔除会改变入屏阴影，拆开独立批次/投影包围盒尚无本批验证，不能直接作为安全收益采纳。更激进可见性取舍交 D02 讨论。
- **R11**：接触深度不写颜色、空折射绕过已存在；普通场景仍需线性 HDR、辉光及输出。现有各项实际成本和分辨率压力已记录，降低样本、辉光尺寸、阴影或特效密度属于 D02，尚未批准/实施。
- **FX-011**：源特效没有完整保守屏外边界；屏外 actor 仍可能有跨屏长光束、粒子以及重入后的生命周期。已有 CPU/池/求值优化归此前 X01–X04，本批没有直接停止屏外生命周期或减少输出。透明实际提交成本另测，不能当作片元过绘比例或删减许可。
- **R15**：复核发现人族英雄按身份筛选 getter、舰队 child 查找及旧神族 stroke 固定 16384 顶点/49152 索引边界仍存在；源 DrawBatch 则按需增长。旧精英事件查找已有此前索引路径，仍受 sourceOwnsFlight 路由限制。R01 不改这些上限，也未覆盖所有旧层极限 dropped 数；对应规模/CPU 子项继续在 A01 复核，不因本批 GPU 诊断宣称已全部优化。

A01 只补本批五条当前结论和去向，169 条整体复核不关闭。D02 保持待讨论。

## 失败记录与交付边界

`paired-r1` 第一次跨到工业图时，直接诊断 reset 未先准备该图资源，第一轮地表查询为零、后续才出现地表。该轮中止并标作无效先导，报告和 `invalidation.json` 保留。正式 `paired-r2` 显式等待地图准备、来源哈希/主题一致、加载清空、真实地表正 GPU 结果；运行时诊断入口也补同一准备步骤。生产普通开局原本已有准备流程，不为诊断失误修改游戏加载行为。

本轮还保留 GPU 大波动、同页最多一级色值微差、恢复最多两级微差和上述较大的跨会话差异。汇总工具首次使用 Windows 默认 GBK 读取 UTF-8 报告失败，改为显式 UTF-8 后生成分析；随后跨会话相机比较因未启用的 autoTarget 不同失败，修正为先断言固定模式、保留两边非活动目标，再比较全部其余相机字段。两次分析修正没有更改原浏览器证据或游戏源。未测结果不补造。
