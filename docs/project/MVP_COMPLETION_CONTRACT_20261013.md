原规划时的可运行底座为折射与科学球修复、应用 0.6.25，现已推进到上述0.6.27五图交付。屏幕折射实现与三档精英科学球死亡来源缺口已解决。正常游玩中的具体显示问题、自然性能、用户试玩与实体设备、正式环境验收仍按各自范围处理；不再把未作精确客户端校准视为必做欠项。新建筑、事件和舰装方案不能沿用旧测试结果直接标记完成。

## 原版战斗表现与地图验收

按用户后续澄清，取消单独的原版客户端短片匹配任务，不要求录制对应版本／镜头、逐阶段或逐像素对齐，也不把折射幅度与原版引擎精确相同列为门槛。主要从代码与真实运行确认：资源和单位／皮肤映射正确，实际引用的网格／材质／动画通道完整，武器起点、飞行、命中、治疗、护盾与死亡按本游戏事件正确触发，暂停／回收／恢复可靠，未误改玩法和存档。

代码不能证明主观观感，因此仍用正常游玩或少量代表场景检查明显缺失、黑块、闪烁、挂点错位、失常尺寸或持续时间；已有证据充分时直接复用，不反复采集全量画面。只针对实际发现的错误修复。M3 type 2 折射和科学球精英来源缺口已经在 [本轮修复](REFRACTION_SCIENCE_20261013.md) 中关闭，历史失败记录保留；这一结论不等于整个 MVP 4 已完成。其他来源不明或实际缺层仍如实处理，不能冒称已找到原件。已有英雄与精英的自定义附加机制按已批准方案检验，不要求原版存在同名机制。

“单位小”“特效多”“查尔暗”“身体偶尔出框”不单独构成返工理由。应先检查是否偏离原版表现或妨碍整队移动、地图目标和实际可用操作；不为了让每个身体始终显眼而随意放大模型、缩小原版效果、改灯光或新增英雄微操。固定、自动、电影三种相机与既定手动控制保留。

首版不新增普通地图、章节、昼夜天气系统、水体物理或可破坏地形。优先使用原版环境资源与材质，保持现有通行骨架、地图规模和出生规则；可见地貌与实际可通行区相符。每图用固定动态巡游路线检查出生区、主要活动区、地表交界、物件根部和边界，不能只交一张局部精修截图。新增装饰进入加载、释放和画质预算，不先无限堆物件再解决成本。

### 独立包必须包含真实规则

“外部独立包体”指可独立启动、操作和验证的功能模块。建筑包必须执行真实前置、费用、解锁、产线选择、订单和产出；不能只在界面上增减数字。舰装 UI／装备原型先验证槽位、合法装卸、物品身份和关键能力计算；尚未决定的掉落、损失或经济参数明确标为待定，完整舰装范围仍在阶段 C 关闭。

1. 正式业务规则放在主项目可复用模块中。独立入口和主游戏导入同一份规则代码；UI 发送操作意图并显示实际结果，不复制 World、钱包、生产或装备计算来维持第二套实现。
2. 独立入口可以提供固定种子、示例钱包、测试物品、沙盒场景和时间控制；这些是输入夹具。支付、合法性、订单、奖励与能力计算仍执行正式代码，夹具不得伪造通过结果。
3. **先独立验证通过，再接入主游戏。** “真实钱包扣款—建造—生产交付”和“装卸一件装备—真实效果变化”各自在独立包通过后，尽早做一次小规模主游戏接入并验证失败分支；其余独立内容可以继续完成，正式整体接入仍以包内验证通过为前提。早期接入不提前改写完整成长、会话结束规则或用户存档。
4. 独立包使用明确隔离的测试档案或内存状态，不读取、覆盖玩家正式档案。交付附启动方法、规则版本、已实现清单、未定项和实际检查结果；静态设计通过与功能通过分别记录。
5. 后续正式 1／3 以这些模块为基础补齐和集成，独立入口继续作为调试与验收入口；不以“独立演示完成”直接宣称主游戏已经完成。

目录职责见 [项目文件夹说明](../PROJECT_STRUCTURE.md)。本次只确定约定和文档，不创建空功能模块或启动实现。

### 7A 与 7B 的边界

7A 先测同机加载、帧时和内存基线；处理开局／入场阻塞、重复解码或材质与着色器准备、已确认的无效渲染开销、资源释放和持续影响试玩的热点。地图装饰从样板开始纳入数量、加载和生命周期预算；严重卡顿或内存问题不等后期才修。

7A 不提前承诺完整内容下的 60 FPS，也不提前冻结最终画质档、最高密度预算或跨设备结论。九个套装、特殊虫潮、新敌人和完整事件接入后的系统性能、长期内存、低配置适配与最终门槛，统一在 7B 验收。每批合入继续记录变化；7B 不是第一次测性能。

4／5 的当前内容基线通过后固定风格、来源标准和地图样板。后续 1／3／2 新增的建筑、技能、附件与特殊场地按同一标准检查，只复验受影响的画面和生命周期；不能借新增内容重新打开整轮原版表现或五图美术。已知缺层和可复现回归仍须修复。

## 性能和最终验收

普通游玩 60 FPS 方向沿用 [原 MVP 计划的性能约定](../MVP10_ITERATION_PLAN.md#72-普通游玩60的测法)。参考环境仍以已记录的 Ryzen 7 5800U／Radeon、1440×900、DPR 1、原画质为起点；7A 记录实际设备和浏览器。已有 1280×720 的短时记录只能作为诊断，不替代这套合同。

拟沿用的测量门槛是：60 Hz 环境 P95 帧间隔不高于 16.9 ms、P99 不高于 20 ms、超过 20 ms 的帧不超过 1%；180 秒样本新增模拟欠账不超过 0.1 秒且不持续累积。主线程工作 P95 目标 14 ms，连续战斗不能反复因资源准备产生超过 50 ms 的长任务。具体阈值在正式性能验收前锁定，不能测完后为凑通过而放宽。60 Hz 实测仅表述为接近 60；高刷新实测才用于超过 60 的结论。

三族早期完整关段、后期和无尽，以及新事件、舰装第一次触发、精英英雄首次上场都进入自然样本；同场景至少三次，保存中位数和最差值，读条结束后的最初十秒不剔除。高成型舰装、真实虫潮重叠和子机要覆盖。合成压力场景另列，不能把普通玩法会自然达到的负载全部称为极端夹具而豁免。

加载单列“导航至可操作菜单、开始至可操作战斗、再次进入”，内存单列峰值和重复换图后的回落。7A 先测同机基线并制定数字预算，7B 按完整内容验证；现有 15 秒开场准备目标及 20 秒停止新开场任务的设计不等于实际菜单一定按时可操作，更不等于百秒入场等待已经可接受。

最终验收按以下顺序完成：

1. **规则与数据。** 自动回归、类型检查、数据文档一致；公共交易、装备与奖励一次结算、真实存档和失败恢复通过。特殊稀有内容可以用明确标注的固定种子或诊断入口补分支覆盖，不能当作自然通关证据。
2. **实际完整玩法。** 三族正常开局到十八关结局的完整记录，覆盖无尽、特殊关往返和不同结束方式；平衡抽样覆盖现有难度和无、中、高成型舰装。没有必须依靠测试注入才能继续的流程。
3. **画面与操控。** 本游戏战斗效果异常检查、五图巡游和必要界面集中观看；键鼠、真实触屏、真实手柄完成各自支持的操作。电脑窄屏或模拟手柄仅证明相应仿真结果。
4. **你的集中试玩。** 正式试玩前确定有限的场景表，至少含三族开局与发展、地图环境、事件与特殊关、舰装换装与撤离、后期战斗。自动化和我的观看不替代这一项。一次集中反馈后修复并复验；新的玩法想法单独进入 1.1。
5. **正式发行。** 同一候选版本完成 Web、实际命名离线 HTML、应用包、资源复用、升级回滚和正常提交推送核验；再完成既定正式环境部署与现网 B4，包括实际后台接收、反馈、管理权限和原有删除及恢复流程。生产环境由真实配置验证，不能拿本机后端替代。

最终版本不得有阻断出征、进程崩溃、错误扣款或结算、装备复制、存档损坏等未解决问题。轻微美术瑕疵、额外设备拓展和不影响既定流程的润色可以明列在 1.1；若历史要求需要调整支持范围，须在相应验收方案锁定前明说，不到最后静默取消验收项。
