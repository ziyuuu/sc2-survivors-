## 已实现的运行规则

- 死神本作适配为两次6伤害；锁定来源仍为两次4。射程5、周期及军衔/科技/精英/卡牌顺序保持，统一入口防止重复加成。
- 交战站位按武器、射程、体型和通行条件分配。可开火者保持位置；近战接触环没有空位时短期避开该目标；短射程单位加入混编交战。医疗单位与手动部署单位不被当作可自动移动的射手。缓存0.4秒，地形射线区分近战和远程。
- 普通敌人出生军衔、前六关简单/普通减血和固定I级追加虫海分别派生。属性在出生时固定；特殊敌人保留独立公式。救援守军按实际出场关卡确定基础属性。
- 虫海独立队列和来源保存，300敌人容量不足时排队，原事件优先；矿气、击杀和天赋检查均走原结算。按来源累记计划数、入场数、击杀和收入。复核还修复了满员延迟的战役Boss在跨关时被覆盖的问题：待入场事件保留原关参数并进入下一关队列；无尽特殊单位也先检查容量。
- 无尽60秒一轮、每四轮发展、每轮购物及300/250基础奖励。旧四分钟普通/经济事件切分；精英、Boss、扩张巢时钟连续；分钟和轮次奖励收据独立。
- 当前战局schema9登记虫海状态；站位及出生位置缓存重建。没有恢复旧玩法分支。

## 界面与发行

关间以三张卡、钱包、价格、刷新和继续为主，生产/修复/复活等折叠为部队整备；发展方向不进入随机商店的抽样条件。部队详细信息按需展开；固定英雄技能、细血盾条保留。窄屏卡片修复了旧绝对定位使图标越界的问题。

Web使用固定版本清单、内容散列地址、SHA-256校验、同内容文件共享及四路资源下载。失败保持加载页，可重试；错误缓存强制重取一次。菜单与选族完整预载衔接同一协调器，战斗仍在浏览器计算。服务包含MIME、gzip、跨域与长期缓存；地图glTF的`model/gltf+json`及文本压缩已补齐并有响应回归；入口/配置不长期缓存。修复了浏览器原生fetch被当作对象方法调用造成的Illegal invocation，以及分离资源根目录时误将应用JS也发往资源根的问题。

发行引用闭包733个ID、727个完整资源文件、458,127,859资源字节；逻辑字节458,230,327，相同完整文件共享102,468字节。756项准备结果中23项有零引用证据而未发行，没有未决保守候选。离线内嵌包另通过分片共享减少68,380,183原始字节。这两种去重统计不能混为一谈。模型、贴图、动作原素材未删。

Coze应用ZIP只带编译入口、JS/CSS、清单、静态服务及说明，采用官方要求的单根文件夹。资源ZIP独立上传HTTPS静态托管；`ASSET_BASE_URL`指向assets的父目录。官方导入及部署说明已核对并链接在 [交接文档](COZE_GITHUB_DEPLOY.md)。未在用户Coze账户部署，未开通收费服务。

## 内容诊断与自然尝试（严格分开）

锁血仅保护开发诊断中的玩家战斗单位；真实命中、护盾、控制与伤害统计正常，不保护运输载体或建筑。WeakMap不进入存档，正式发行没有可启用入口。独立QA档案没有送钱、删敌、强制过关或修改敌方数值。

旧`swarm-content-objective`、`swarm-content-resumed`和`swarm-content-easy`锁血样本误将运输载体纳入保护，全部作废，不可用其中“神族已通无尽”作为验收。已增加实体类型边界回归。

随后`swarm-content-verified`从新局运行正确的战斗单位锁血，查实另一处问题：守军降落绕过300容量，人族可见敌人峰值412、虫族350；人族最终Boss可能等待到关末仍未入场。这些是有效的问题证据，不能当作修复后的通过记录。

### 守军排队与Boss优先修复

- 守军沿用原数量。原guardTypes与保留的guardianIds重建入场进度；损毁载体不会丢掉未生成守军，未清除守军不提前放出乘员。
- 波次、守军、巢穴产兵和虫海共用非Boss容量；战役预留尚未入场的六个预定Boss席位，无尽预留下一Boss一席。仍不超过300存活敌军；不删除普通兵、不改奖励或各波总量。
- 原Boss队列跨关保存来源参数。首次两个回归分别复现302>300和Boss无法入场，修复后通过。另以100个待生成载体验证每轮容量只扫描一次，消除逐载体数全体敌人的重复工作。
- 新状态使用原保存字段，没有另建队列格式或旧开发档兼容路径。见`swarm-capacity-before.log`、`swarm-capacity-after.log`和`swarm-guard-budget.log`。
