# 舰装模型 特效与落地拾取梳理

日期：2026-10-15。对应用户本轮要求：先梳理幻影、康斯坦威等装备需要的特殊建模与效果，设计暗黑式落地表现并保持走近自动拾取。本文是表现盘点与制作方案，未修改游戏表现或装备规则。

共享逻辑已接入，但逻辑生效不等于所有装备都有完整的可见反馈。本轮按当前 **210 个装备模板、189 个效果键**逐项归组，机器清单没有未分类效果键：[完整模板清单](../../reports/local/starship-presentation-balance-20261015/presentation-inventory.json)。一个模板可对应多类表现；此计数不是已完成的视觉验收数。

## 已找到的原始素材依据

幻影不用另做一套人物模型。当前本地 Liberty ActorData 的 `HighTemplarHallucination` 明确给出染色 `108,108,255`、透明度 `0.7`，并有 `HallucinationBirth`、`HallucinationDeath` 与巨像专用出生／死亡条目。可作为本项目幻影的原始来源起点，再适配真实三族模型、子机与本游戏相位规则。

康斯坦威属于本游戏装备增益，原 SC2 没有此装备。当前本地有 `StimpackStartImpact`／`StimpackEndImpact` Actor 与 M3 路径，原挂点为 `Overhead`。可复用其启动／结束语言；持续状态和紫档差别是本游戏新增设计，不能冒称原客户端已有同名效果。当前原战斗效果运行目录没有这两项已备妥定义，仍需正式提取、依赖检查与接入。

已读来源：

- `assets/private/actor-source/mods/liberty.sc2mod/base.sc2data/GameData/ActorData.xml`：13653 起的兴奋剂开始／结束，17333 起的幻象染色与出生挂点。
- 同目录 `ModelData.xml`：22947 起的兴奋剂原 M3，23498 起的幻象出生／死亡模型。
- `src/simulation/starship/projections.ts`、`controls.ts`、`support.ts`：真实投影、增益、持续火区状态。
- `src/render/scene/battle-renderer.ts`：已接入阵地与原身体；当前奖励标签读取的是 `rewardDrops` 卡片，不能当作新装备落地标签已实现。

新增美术工作应集中在少量共用材质、原始效果资源和拾取物组件。身体、武器和已有英雄尽量继续复用原模型；共享实例材质不能因一个幻影改变原体或另一支队伍。

## 暗黑式装备落地与自动拾取

设计重点是“掉出来能认出价值，走近就收下”。暴雪对暗黑 3 的官方说明区分普通传奇橙光与太古红色光柱，并把稀有掉落的兴奋感作为目标；本项目借鉴分层反馈，沿自己的白／绿／蓝／紫／橙品质，不复制暗黑的品质规则或素材。[官方掉落表现说明](https://news.blizzard.com/en-gb/article/22989464/legendary-an-ancient-primal-guide)

| 品质 | 落地形态 | 常驻提示 | 瞬时与音效 |
| --- | --- | --- | --- |
| 白 | 低矮装备实体、弱白色底光 | 走近显示名称；远处只留实体 | 短落地声，无高光柱 |
| 绿 | 绿色底光与短粒子 | 近距简短名称 | 小落地闪光与轻提示音 |
| 蓝 | 清楚蓝色底光、短光束 | 中近距离名称与槽位图标 | 清晰但克制的品质音 |
| 紫 | 紫色细光柱、地面纹环 | 在视野内保留简名 | 一次落地闪光和独立音色 |
| 橙 | 更高但细的橙金光柱、少量上浮粒子 | 视野内名称与装备图标 | 一次稀有提示音与短提示，不停战 |
| 污染 | 保留原品质色，外缘异色纹理／碎裂符号 | 名称附污染标识 | 在原品质音上叠短污染音，不伪装成新稀有度 |

建议第一批只制作 3 类可读拾取物：攻击组件、防御组件、功能模块箱；槽位差异用现有图标和小附件表达。品质由共用效果层控制。这样能完整表达 210 个模板，而不为每件装备建立独立战场高模。若后续特定橙件确实需要独特落地轮廓，再按名单补充。

交互顺序：真实敌人掉落收据生成 → 地面实体落下／短弹跳 → 品质标识稳定 → 玩家队伍锚点走入现有 2.5 范围 → 库存操作成功 → 吸取尾迹和背包计数提示。吸取是成功入包的反馈；不因演出等待而延迟规则领取，也不让演出重复领取。装备不自动穿戴、不弹选择框、不暂停。

背包满时保留地面物品和标记，给一次明确“背包已满”反馈；不得静默删除、自动分解或自动替换背包物品。扎堆掉落把标签避让／聚合，优先展示高品质；省略重复发光层不等于删物品。自动拾取范围沿队伍锚点，临援、子机和飞在远处的随行体不能跨图扫包。

批量掉落音要合并，低品质不连续轰炸听觉；每件物品仍保留可辨的底光。落在墙内、水面或不可达地点时，需要在合法地表找到视觉与拾取一致的位置，不把长光柱画在可见处而把真实物品留在障碍后。暂停、清场和切关的视觉生命周期沿实际物品状态。

## 后续制作顺序

1. 先补 P0：装备落地拾取、幻影／相位、康斯坦威、持续火场、真实转换／召回。
2. 然后补派生弹道、炮台武器、临援与巨兽入场、护障／救援和英雄追加表现。
3. 最后收齐成长、冷却、经济与库存反馈。

每类检查真实触发、位置、挂点、寿命、暂停／结束、同场重叠和对象销毁。原有五图与已接受身体不重做；不新增原客户端逐帧对比门槛，也不以本清单替代轻量实际画面检查。
