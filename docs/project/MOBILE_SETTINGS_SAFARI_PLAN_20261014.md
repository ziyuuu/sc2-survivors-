## 2 设置与两个功能

设置采用 **操作｜画面｜皮肤｜预下载** 四个标签，标题菜单、暂停和关间整备使用同一份设置。手机保留可触达的标签与返回按钮，正文独立滚动；更改标签或全屏状态时保留当前页面和合理的滚动位置。沿用现有视觉风格，不重做整套 HUD。

### 2.1 画面标签中的全屏

- 将“进入全屏／退出全屏”放在画面标签靠前位置，状态以浏览器实际结果为准。用户主动点击才发起请求，失败不写入假的开启状态，也不改变战局或暂停状态。
- 桌面和支持的手机浏览器使用原生全屏；兼容需要时才使用确实存在的 WebKit 前缀接口。监听进入、退出、被系统打断及失败，保持设置按钮和旧快捷入口同步。
- 不自动锁定横屏。全屏与屏幕方向分开处理，退出全屏和手机旋转均保持当前菜单、战局和横竖屏各自的镜头偏好。
- iPhone Safari 按实际版本与能力处理。不能只凭接口存在或机型判断成功；不支持网页原生全屏时，在同一位置显示说明及“添加到主屏幕，以网页 App 打开”的操作指引。独立窗口与原生全屏明确区分，不把 CSS 铺满页面当成已隐藏浏览器界面。
- 主屏幕方式不自动跳转或重启当前战局，也不承诺系统状态栏一定消失、已有浏览器缓存或档案一定自动共享。实际入口行为要在目标 iPhone 上核对，不以存档迁移扩大本批次。
- 旧战局档案中的全屏入口保留为同一功能的快捷入口，避免已习惯原路径的用户找不到功能。

Fullscreen API 需要用户操作，且支持范围、嵌入权限与版本有差异。[接口文档](https://developer.mozilla.org/en-US/docs/Web/API/Element/requestFullscreen)；iPhone 的替代入口按[Apple 官方网页 App 指引](https://support.apple.com/zh-cn/guide/iphone/iphea86e5236/ios)提供。

### 2.2 独立预下载标签

- 提供“预下载本族”和“预下载全部”。菜单中使用当前所选种族，战局中使用本局种族；显示种族名称、预计文件总量、已校验缓存、仍需下载和当前任务进度。大小按实际清单和唯一文件计算，不硬编码版本包体。
- 核对本族包的完整依赖：本族模型、死亡与形态、工人与载体、实际可能需要的敌军和共享地图／特效／音效。现有筛选会纳入所有非 model 资源，要先核对真实范围再命名，不能把不完整包称为“本族已就绪”。共享依赖单列说明。
- 预下载只读取、校验并保存文件，不创建模型、展开纹理／音频、编译着色器或常驻一份完整资源 Blob 集合。点击开始游戏后仍通过实际场景的资源准备与首帧校验。
- 下载任务独立于设置正文的重新渲染；切换标签保留任务和进度，返回标签不创建第二份任务。关闭设置、进入战场或页面进入后台时停止启动新的预下载请求，明确显示正在完成当前文件，已成功文件保留；之后继续时只补缺项。
- 正式入场与预下载共享去重及优先级，同一文件不重复下载。手动预下载期间暂停启动新的可选模型／GPU 准备，已在执行的同步任务允许完成；用户开始入场时，正式必需资源优先接管，避免下载与解码争抢内存。
- 显示等待、检查、下载、保存、已停止、完成和失败等真实状态。断网、损坏文件、缓存写入失败、空间不足均可重试缺项；没有成功写入缓存的文件不能计为完成。
- 保留清理资源缓存，清理前说明实际范围；只清资源缓存，保留战局、天赋和用户设置。正在使用的场景资源不因清理持久缓存被错误释放。
- 自包含 HTML 的新标签显示“资源已包含，无需预下载”，相关下载操作不可用，避免误导手机用户再次下载整包。网页缓存不等于完整离线应用，不承诺关闭浏览器后还能后台下载。
- 旧资源下载入口转到这份设置中的预下载页，不再维护两套独立任务和进度界面。

Safari 的存储额度、写入失败和自动回收均按实际返回处理；估算可用空间和持久化请求成功与否不能当成永久保存保证。[WebKit 存储策略](https://webkit.org/blog/14403/updates-to-storage-policy/)

## 3 横竖屏切换

目标是**在同一页面、同一战局内完成布局切换**，减少跳动、黑屏和错位。优先解决尺寸与输入的一致性，不增加掩盖问题的长过场动画。

1. 汇总窗口、visualViewport、全屏与 HUD 尺寸事件，形成一份有效视口。区分屏幕方向变化、浏览器工具栏伸缩、视口偏移和软键盘变化，避免短暂高度变化反复切换横竖屏偏好。
2. 同一帧合并重复事件，数值不变时不重复调用 renderer／composer／折射缓冲区的尺寸分配。布局先响应有效尺寸，再处理仍在变化的昂贵渲染目标；具体稳定策略依据真机事件序列确定，不只依赖固定 160 ms 延时。
3. 画布、HUD、安全区、弹窗、点击拾取、小地图和摇杆使用同一轮视口结果。处理横屏刘海左右互换和浏览器工具栏收放，保持返回、设置、全屏退出等关键操作可见。
4. 方向切换时释放旧指针捕获，取消尚未提交的点击／双指缩放，重置摇杆和小地图拖动，防止旋转后继续移动或误触命令。保留已提交的移动命令及战局状态，沿用原有暂停与模拟时钟规则。
5. 保留固定／自动／运镜模式及横竖屏独立的角度、缩放偏好。仅在确认方向变化后使用对应偏好，不反复恢复默认镜头。
6. 正常旋转不重新下载资源、不重新开局、不重建完整战场，也不为过渡额外保留一张整屏 GPU 副本。真实上下文丢失走既有恢复路径，与正常 resize 分别记录。

覆盖封面、设置、预下载、入场加载、战斗、暂停和关间整备。加载或下载中旋转不能丢任务、重复启动任务或把进度重置为零。对切换前后截图与实际点击坐标一起验证，单独改 viewport 尺寸的桌面测试不能替代真机旋转。

## 4 Safari 入场修复

### 4.1 先取得可区分原因的证据

以用户提供的线上路径和 iPhone 17 Pro 为主复现环境，记录具体 iOS／Safari 版本、种族、地图、资源缓存状态、最终加载阶段及是否真的发生整页重载。现有线上同版本检查和 Chrome 对照直接复用，不重复做整批五图视觉比较。

增加少量本地阶段记录，覆盖资源校验、模型／纹理解码、动画准备、GPU 编译与首帧。记录真实 WebGL 丢失／恢复事件和上次未完成的加载尝试，允许用户导出排查数据；不新增远端日志上传。没有正常结束记录只能说明加载中断，不能直接标成内存不足。

如能取得 iPhone 的进程终止日志，再区分内存、GPU 进程或其他 WebKit 错误；缺少日志时用受控候选与实际复现结果判断，保留原因不确定的部分。[Apple 内存终止诊断说明](https://developer.apple.com/documentation/xcode/identifying-high-memory-use-with-jetsam-event-reports)

### 4.2 按使用阶段准备资源

- 梳理“首关真正需要”“后续关卡或整备选择后需要”“无尽入口才需要”三组依赖。模型、形态、死亡、子单位、原版特效、材质通道和附件一起归属，防止只移走主体而遗漏必要资源。
- 第一批先移出明显属于后续入口的工作，例如普通战役开局准备完整无尽建筑与平地。再按证据分拆未被选择的英雄／精英及三族专有准备；每拆一类就验证它的真实进入路径。
- 新局需要覆盖初始单位、实际可生产／出现的对象和首关敌军；整备与增援入口补齐新选择；无尽入口补齐无尽。进行中的攻击、子机、死亡和持续效果在结束前必须保有所用资源。
- 复用正式规则与已有入口，不提前抽取奖励、消费 World RNG、生成假战局或改变数值来计算资源。对无法提前确定的合法候选，在已有决策／准备边界覆盖完整候选范围。
- 每个入口继续等待精确依赖、实际 HDR／材质／折射准备和首帧校验。不能靠提前显示 100% 或进入战斗后长期临时缺模型缩短等待，也不能把原先等待转成战斗中的明显冻结。

### 4.3 控制峰值与驻留

- 分开统计源文件／Blob、解码图片、动画数据、场景对象、GPU 纹理与渲染目标。保留浏览器能测到和不能测到的范围，不把 JS 堆、文件包体或桌面 GPU 进程数值当成 iPhone 总内存。
- 合并相同文件和不可变图片的准备工作，检查并释放多余临时副本；保护正在显示、飞行、死亡或被下一入口引用的资源。淘汰缓存后必须能从已校验缓存重新准备。
- 将可选后台准备与必需入口的并发、批次和保留范围放到共同约束下。现有可选 24 个模型上限不作为总内存预算；根据实测确定可保留工作量，不硬编码所谓通用 Safari 2 GB 上限。
- 将旋转／全屏引发的 GPU 目标重分配纳入峰值观察，确认旧目标及时释放，避免多个中间尺寸同时留存。
- 如果上次重载发生在加载期间，重新打开后保留明确的重试入口和诊断信息，避免立即重启同一批重型可选任务。普通资源失败保持原地可重试，不通过自动整页刷新恢复。
- 保留现有素材和视觉效果作为比较基线。先解决无关资源过早展开、重复持有和生命周期；若仍需要新的纹理或效果取舍，再提交具体实测与候选方案，不在本计划里默认删内容或降低原素材质量。

## 6 验收范围

| 范围 | 关键场景 | 完成条件 |

| 后续资源 | 三族、实际英雄／精英／形态／死亡／子单位路径、无尽准备、上下文恢复 | 每个被延后的资源都有真实触发证据；缺资源能重试，原版材质和效果无缺失／黑块／明显错位 |
| 既有基线 | 受影响的规则回归、类型检查、入口状态，以及必要的五图轻量检查 | 世界规则、RNG、伤害与生产无意外变化；不重做已关闭的实际客户端逐帧标定 |

先对用户的主复现路径完成有限重复，初始目标为同一修复候选连续三次成功入场，并分别覆盖缺缓存和有缓存；发现差异再扩样，不直接展开无边界设备矩阵。加载时间比较固定设备、浏览器、种族、地图、画质和缓存条件；内存统计说明方法，普通 FPS 和完整自然战役不由这次入场样本代替。

实施完成后提供具名 Web 候选、兼容的离线 HTML／应用包、改动与验证记录，保留 0.6.27 对照及失败样本。手机 Safari 的主要验收入口为 HTTPS 网页；大型离线 HTML 的手机运行不由网页结果自动推定。
