# 1.2 自动战斗落地方案

日期：2026-11-06。任务：`AUTO-1.2`。状态：**方案完成，待审阅；游戏实现未开始**。本轮授权是设计落地方案，并允许与 1.1 同步推进，不包含发布。前置调研见 [11 月 5 日研究](V1_2_AUTO_COMBAT_RESEARCH_20261105.md)。

## 1. 已定范围与最新修正

目标是让现有部队更可靠地服从玩家、选择威胁、取得攻击位置并分配火力。沿用现有固定步、寻路、碰撞、攻击、技能和奖励结算，不引入新的操作方式、通用 AI 框架或新单位。

| 已确认事项 | 本方案执行口径 |
| --- | --- |
| 玩家命令优先 | 移动、架炮/收炮、其他手动模式、手动技能都是玩家命令；自动判断不能覆盖它们。不能简化为“移动高于所有命令”或“所有冲突都由最新命令覆盖” |
| 坦克架炮与移动冲突 | **架炮命令持续有效；玩家先手动收炮，坦克才执行移动。** 保留原架炮防守回归，不实现移动触发收炮，也不实现到位后自动架炮。收炮完成后跟随仍有效的整队移动/队形；其他可移动成员继续执行自己的命令 |
| 远程职责 | 先拦截可合法攻击的毒爆，再处理正在攻击友军、已造成杀伤的近战，随后处理其他威胁 |
| 近战职责 | 先找可达的高威胁远程/施法者，再近战，最后毒爆。没有可达攻击位置的目标不能占用近战火力名额 |
| 快速击杀重要目标 | 在上述职责层内分配足够火力，富余部队清杂；残血 Boss 不覆盖毒爆拦截任务 |
| 普通近战速度 | **首批保持现有速度**。先做分流、攻击位置、让路，再由实际结果判断是否需要另议加速；不采用研究中的额外 +20% 候选 |
| 既有差异 | 保留原冲锋参数及已批准的冲锋穿单位例外、潜伏者地下移动、精英独有行为、地空与最小射程限制 |
| 与 1.1 并行 | 设计和独立模块可并行；共享主循环、保存校验和最终集成测量串行接入。1.1 完成不再是 1.2 设计或独立模块开发的硬前置 |

坦克决定取代旧研究第 4.1 节“移动触发收炮、抵达恢复模式”的建议。本方案优先于路线图中笼统的“撤离时收队”。新 UI 不在本方案范围：继续使用现有移动、模式和技能入口，不增加自动战斗开关、锁定图标或说明条。

## 3. 执行架构与接口

```text
现有玩家输入 / 模式 / 手动技能
             ↓ 指令约束
当前权威战场 + 真实在途收据 → 合法候选与威胁 → 可用攻击位置
                                                     ↓
                                     职责、位置与火力联合分配
                                                     ↓
                          原单位执行器逐次重验 → 原移动 / 攻击 / 消耗
                                                     ↓
                                原命中 / 死亡 / 奖励 / 接触修正
```

建议新增 `src/simulation/combat/tactics/` 小目录，以下为接口职责而非已存在 API。先保持内部接口，不改 app/render/ui 分层：

| 模块 | 输入与输出 | 不能做什么 |
| --- | --- | --- |
| `intent.ts` | 从已有 order、movePending、输入、模式、控制/施法状态查询每个单位的移动、攻击和模式约束 | 不清除手动命令，不把锚点 arrived 当成全员 arrived |
| `candidates.ts` | 单位、当前合法武器、局部空间查询 → 候选目标、职责、威胁证据 | 不攻击隐形未发现目标，不把经济/任务保护对象变成普通敌人 |
| `positions.ts` | 候选与 EngagementSlots → 合法位置、路径长度、预计接敌时间、受阻反馈 | 不直接写坐标，不把“搜索预算用尽”当永久不可达 |
| `estimates.ts` | 实际武器与防御快照、出手/飞行时间 → 逐次命中估算及置信类别 | 不调用 fire/hit/attackHit/expeditionDamage 试打，不推进 RNG 或写护盾/能量 |
| `commitments.ts` | 权威弹丸/范围/技能收据 → 已承诺、待出手、尚在接敌三类贡献 | 不重复计父体/子机、主攻击/弹跳、真实攻击/画面特效 |
| `planner.ts` | 指令约束、候选、位置、贡献 → 目标与位置分配、失效原因 | 不重排真实实体更新，不替代命中与奖励结算 |

计划条目至少包含：单位和目标引用、场景代次、指令版本、职责、目标位置、有效期、预期首个命中时间、贡献置信类别。实体引用使用 id 和实体出生信息；非实体目标使用现有身份及场景代次。缓存建议 `WeakMap<World, ...>`，保留同一个 World 身份。

在普通单位循环前生成共享视图，执行器仍逐单位重验。航母子机、英雄或技能已有的前置阶段保持原时序：需要跨阶段共享时读取当时的权威状态，不把它们搬到普通循环后，也不多结算一遍。首个模块可以先输出诊断分配、不驱动行为，用相同输入比较；诊断开关仅测试使用，不进入玩家界面。

### 3.1 指令与模式约束

1. 整队移动有效时，可移动成员按原队形移动，不能因自动追击、让路或抢位置掉头。尾队未到位仍执行移动；允许原本可边移动边完成的攻击。
2. 连续方向输入不逐帧清前摇。新目的地、方向明显改变、停止/取消只使相关计划失效；移动并不免费刷新 nextShotAt，也不额外罚一整个射击周期。
3. 坦克按手动 `tankCommand/desiredMode` 执行。架炮不因移动失效，收炮仍耗原变形时长。未完成收炮不能移动；没有新架炮命令不重新架炮。精英 `tank.1` 沿用专属行为。
4. 其他有效手动模式同样持续优先。手动技能先经过原资格与支付检查；自动技能只能使用执行时仍可用的能量与冷却，不能抢掉同一步已经接受的手动施放。
5. 眩晕、根缚、合法过渡、已经支付的引导/延迟攻击按原规则处理。“服从玩家”不代表瞬移、跳过变形、无偿取消或重新支付。

### 3.2 威胁、位置和分流

硬门槛依次为作用域、玩家约束、阵营/存活/可见、地空武器、射程与射线、可达位置。友方任务与遭遇关系使用现有关系函数，不仅比较 owner。已有 `funPriorityTarget/encounterPriorityTarget` 特殊目标先核对所属玩法，不被普通评分覆盖。

远近战按当前可用武器区分，治疗及无武器单位另行处理。远程依次处理毒爆、正在威胁友军的近战、其他敌人；近战依次处理可达高威胁远程/施法者、其他非毒爆近战、其余合法非毒爆目标、毒爆，避免漏掉普通远程或建筑。高威胁依据真实攻击/施法状态、合法攻击友军的能力和预计近期输出，不仅依据单位名字。对多武器单位先筛合法武器，再评估对应职责。

每轮先保留有效输出位置和已承诺攻击，然后为剩余单位分配目标与位置。对不同目标的占位也共享检查，防止两圈近战挤进同一个世界坐标。近战只有拿到实际可达位置才计入火力；没有位置就换同一目标的合法点、换目标或在安全队列等待。局部搜索失败设有限重试，不无限追同一堵墙后的目标。

稳定排序为职责层、有效位置/承诺、到位与命中时间、等待情况、单位 id；排序只用于规划，不重排战斗结算。让路仅作用于没有手动移动约束且当前不能有效输出的友军，短距离挪到合法点；不推走正在开火的坦克或近战，不改单位半径、不删除普通敌军碰撞。

### 3.3 有效火力与过量攻击

- 计算离散出手次数，读取真实冷却、前摇、路径到位和飞行时间，不能用纸面 DPS 乘窗口代替。
- 已发射且仍合法的弹丸为高置信贡献；前摇可能失效、接敌尚未到位的贡献分开记录。死亡、失去可见性、弹丸 lost/过期、目标离开范围立即撤销相应预计贡献。
- 普通伤害先支持真实的逐发护甲、护盾及确定性吸收。预测按预计命中次序更新局部防御快照，时间相同按原执行顺序处理；每一发分别减甲。未知共享吸收或特殊效果不声称精确，按保守下界或零贡献处理。
- 已冻结的暴击按冻结值；尚未掷出的随机暴击不预支。范围攻击只将确定可覆盖的目标作为贡献，未选定的未来弹跳不预占其他目标。
- 同职责内能在击杀窗口覆盖的重要目标，仅分配足够的有效攻击者。普通目标也计入在途伤害，减少无意义追加；富余单位寻找同职责其他目标。
- 不为少量溢伤取消已经承诺的攻击，也不靠预计死亡提前删除敌人。仅有软计划不能让全队停火；因真实在途贡献暂缓补射时，设置命中到期重验，落空后立即重新分配。
- 预测纯函数与真实结算做差分验证。若提取共用算术，保持原副作用发生次序，覆盖每一处调用者；不复制一套会长期漂移的“简化真实伤害”。

### 3.4 技能、变形与召唤

只改善现有自动技能的候选与时机，不把手动技能自动化，不改技能数值。治疗按可恢复量和已承诺治疗选择目标；范围伤害按真实有效命中收益选中心；控制读取现有剩余控制时间。具体已付法术仍由原函数结算，取消、死亡、重复事件只处理一次。

坦克架收保持手动。其他模式的自动策略安排在第三批，先区分“玩家指定模式”与“没有手动指定”；手动模式不超时解除。建议复用当前 `expedition.familyModes` 作为手动选择来源，自动建议只写独立的自动状态，不能污染手动字典。旧档已有该字典按手动模式保留；旧档中来源不明的实体模式保守保留至玩家再次指令，不能载入即变形。

现有战场模式按钮仍控制整个族系。自动状态不能让 `familyModeState` 的下一模式与按钮实际执行不一致：无手动选择时从当前实际/已接受的模式计算下一模式，手动点击后该族系统一转为手动选择；混合模式沿用现有明确的下一模式规则。保持现有按钮、标签与布局，实际状态和下一动作都要在 AC-08 核对。本方案不新增返回自动模式的入口；本局手动指定后持续受控，新局按初始规则重置。

| 族系 | 无手动锁定时的第三批候选策略 | 必须保留的退出/禁止条件 |
| --- | --- | --- |
| 恶火/恶蝠 | 已解锁、近身位置可达、扣除变形停火后近战范围收益高于原模式时才考虑变形 | 玩家移动、不可达或远处目标有明确优势时评估机动形态；不借此加速 |
| 维京 | 能安全落地、没有当前可攻击空中威胁、地面输出收益覆盖变形成本时才考虑突击 | 真实落点占用、跨崖/空中移动约束、空中威胁或手动战机命令禁止自动落地 |
| 雷神 | 按合法空中目标的属性、密度及有效命中收益比较两种武器 | 当前有价值目标不因一帧密度变动来回切换 |
| 潜伏者 | 按当前可命中目标与接敌代价比较地上/地下输出 | 地下已有 70% 移速继续有效，不套用坦克“不能移动”规则 |

以上是待实施审阅的候选策略，不宣称用户已逐个批准自动变形阈值。进入与退出用不同收益门槛并设置最短保持时间；手动命令和合法性失效立即处理，不能被保持时间阻拦。第三批先在定向场景验证，达不到稳定收益的族系保留原行为并明确标注未完成，不用降低验收条件宣称全部完成。

航母只累计子机真正发出的攻击，不给母体虚构一份输出；子机保持母体范围与生命周期。任务守军、遭遇友军、装备自动体沿用自己的行动范围和奖励资格。1.2 不顺带新增原版资源、兵种或生产线，AUTO-07 仅覆盖现有名录与适配缺口；后续内容仍归 1.4 起各族版本。

## 6. 参数与验证标准

### 6.1 工程初值和待测项

以下为实施起点，尚未通过 1.2 测量；不是已批准的新玩法数值。

| 项目 | 起点/边界 | 如何决定是否调整 |
| --- | --- | --- |
| 普通决策间隔 | 优先沿用 CONTROL_COMBAT 的 0.24 秒及原分散节奏；固定步仍 1/60 秒 | 命令/失效即时处理不等该间隔；记录反应时延后调整缓存策略 |
| 候选与寻路预算 | 每单位普通候选先上限 8，按职责保留紧急候选；每次最多为其 2 个入围目标寻路，全队每固定步新搜路径先上限 8；单条沿用 2048 节点上限 | 分摊任务按稳定顺序和等待轮转；紧急敌人不能被最近 8 个普通敌人挤掉；测饥饿、路径成本后调预算 |
| 快速击杀窗口 | 先用 2 秒作对照候选 | 检查到位/前摇/飞行后的真实命中与溢伤；窗口不改变攻速或伤害 |
| 自动模式稳定 | 第三批试验收益领先至少 25%、保持至少 1 秒；扣除真实变形时间，退出门槛另设为现模式失去优势 | 按族系对照测定，不给坦克开放自动架收，不压过手动指令 |
| 近战额外速度 | 0，维持现状 | 仅在 A/B 后仍有接敌问题且另获决定时讨论 |

计算预算以候选/路径次数约束，不用机器耗时决定不同设备上选谁或丢掉真实结算。预算用尽只推迟非紧急的新计划，沿用仍合法的旧计划；无旧计划时在玩家约束与职责过滤后回退原合法行为，不能绕过新优先级，也不能为了等规划让整队停火。不能少结算固定步、命中或积压来取得性能数字。

### 6.2 必须通过的有限场景

| 编号 | 固定输入与场景 | 核对结果 |
| --- | --- | --- |
| AC-01 | 点击撤离、连续方向输入、尾队未到位、移动中前摇 | 下一固定步执行有效玩家约束；无自动反向追击；可移动开火保留；nextShotAt 无免费重置 |
| AC-02 | 架炮后下移动命令，再手动收炮；收炮期间输入变化；保存/恢复 | 架炮阶段位置不变、仍可合法防守；原时长收炮后才跟队；不自动重新架炮 |
| AC-03 | 毒爆、正在攻击友军的近战、残血 Boss 同场 | 合法远程优先毒爆；近战先可达高威胁远程；Boss 不能跨职责抢火力 |
| AC-04 | 墙角/窄口、混合体型、相邻两目标的攻击圈、不可达远程 | 实际可用位置分配无重复；不可达者不计火力；可达者能输出，其余换目标/等待，不穿墙或新增长期挤压 |
| AC-05 | 低血量与高护甲/护盾目标、多发武器、在途弹丸、失明/死亡 | 确定性估算逐发对照真实结果，误差不超过 1e-6；不能重复算护甲、弹跳或失效攻击 |
| AC-06 | 足够火力的 Boss 与周围杂兵；火力不足的 Boss | 同职责按实际足够贡献分配；无可杀依据时不承诺假击杀；有合法剩余目标时富余部队继续作战 |
| AC-07 | 治疗/范围/控制重叠，同一步手动技能，能量不足 | 实际收益、原消耗、冷却正确；失败不扣费，不把一份治疗/控制重复承诺 |
| AC-08 | 模式收益在边界往返、玩家手动指定、维京落点占用 | 手动模式不被覆盖；自动候选不过度切换；非法落地不发生；潜伏移动保持 |
| AC-09 | 航母/子机、任务守军、临时召唤、母体死亡与场景退出 | 无双计输出、额外奖励、越界追击、重复回收或重新扣生产费用 |
| AC-10 | 当前 schema26 旧档、暂停/恢复、特殊关往返、写失败 | 无旧计划残留或额外结算；统一账户、两份备份、失败保留、多页冲突保护保持 |
| AC-11 | 三族 1.1 两段教学，工蜂击杀/拾取/购买/装备/结束 | 原生入口、真实回执和等待条件仍能完成；不通过跳步、直接发资源或强杀修复卡点 |
| AC-12 | 同配置三族混编、首战及无尽代表轮次 | 记录决策/路径次数、模拟耗时 p50/p95、有效输出、空等与目标切换；功能正确和性能结果分别报告 |

先用合成状态的逻辑场景定位，再以有限正常速度战场核对组合行为。AC-04 至少包含每种已知问题的一对修复前后对照；若只是偶尔换了目标、原本可达者仍长期无输出，不能认定接敌问题已解决。AC-12 先记录同机同种子旧基线，再同负载比较；模拟 p95 超出基线 10% 作为需要调查的门槛，不以这一个数字代替既有帧率/物理手机标准，不扩成无限压力矩阵。

每批运行受影响的真实测试；游戏实现后运行 `npm test`、`npm run typecheck`、`npm run docs:data`、`npm run docs:check`。现有命令、近战、碰撞、弹丸、模式、航母、教程、保存测试按实际文件选取；历史脚本先核对适用版本。最终使用独立候选目录，保留源码与 appBuildId；浏览器模拟输入、物理设备、人类体验分别记录。
