# 无尽轮次、出怪与成长更新方案

2026-11-06，任务 `FB-20261105-01`。用户要求规划无尽更新，补充“后面都是加1min”，并明确选择“按轮次平滑增长：每轮累计一档，轮内连续增长”。当日先完成源码核对和参数方案，随后用户明确批准实施、15%提速、基础经济同比增加、旧档下一轮切换及本文具体UI范围；实现结果另记。分支 `体积优化版`，HEAD `6510fb2`；两项操作bug已经另行本地修复。

## 已确认：每轮时长

每三轮为一组。以下数字均为**组内每一轮**的时长，不是三轮合计。

| 轮次 | 每轮时长 | 本组开场累计战斗时间 |
| --- | --- | --- |
| 1–3 | 1分钟 | 0分钟 |
| 4–6 | 1分30秒 | 3分钟 |
| 7–9 | 2分钟 | 7分30秒 |
| 10–12 | 3分钟 | 13分30秒 |
| 13–15 | 4分钟 | 22分30秒 |
| 16–18 | 5分钟 | 34分30秒 |
| 19–21 | 6分钟 | 49分30秒 |
| 22–24 | 7分钟 | 67分30秒 |
| 25–27 | 8分钟 | 88分30秒 |
| 28–30 | 9分钟 | 112分30秒 |

公式：设组号 `g = ceil(轮次 / 3)`，每轮秒数为 `g=1:60`、`g=2:90`、`g≥3:60×(g−1)`。第13轮起每组三轮增加60秒，继续递增，不擅自另设时长封顶。暂停、整备、加载不计入战斗时间。

## 已确认：按轮次平滑成长

设 `x = 轮次−1 + 当前轮已战斗秒数 / 当前轮总秒数`，作为敌军的成长进度。每轮开场接续上一轮终点，每轮内平滑推进，不在进组时给存活敌人突然加血。

沿用当前已批准的成长系数，只更换其进度来源：

- 生命：`1.22^x`。
- 伤害：`1.10^min(x,5) × 1.16^max(0,x−5)`。
- 攻速：`min(1.25, 1.025^x)`。
- 各难度、普通兵、精英、Boss、领主的独立基础模板及原护甲保持。

例如第16轮开场仍为 `x=15`，无尽生命倍率约19.74、伤害倍率约7.10；该轮持续5分钟，成长从15逐渐推进到16。若仅改时长而沿用实际分钟，第16轮开场生命约953.71、伤害约128.37，这不是本次选用方案。

敌军在计划出生时冻结成长进度；延迟入场、跨轮排队和读档不按后来时间追溯增强。普通敌人、精英/Boss、虫巢及其增兵、技能伤害都要使用同一成长口径，避免一部分仍按实际分钟强化。保存的老单位属性与出生记录不重算成另一套承诺。

真实战斗秒数继续供训练、技能冷却、经济事件、扩张虫巢周期、永久资源分钟奖励使用。不能直接把全局时钟减速来实现这条规则。

## 已确认：每组三轮增加15%的基准出场频率

统一主波、自然精英和Boss的提速档位：`F = 1 + 0.15×(g−1)`。这是相对初始频率逐组增加15个百分点，不是每组复利乘1.15。自然出场机会增加，不额外提高每只精英/Boss的属性系数，也不在组边界额外空降一批。

| 轮次 | 频率倍率 | 主波间隔 | 精英间隔 | Boss间隔 |
| --- | --- | --- | --- | --- |
| 1–3 | 1.00 | 15秒 | 30秒 | 90秒 |
| 4–6 | 1.15 | 13.04秒 | 26.09秒 | 78.26秒 |
| 7–9 | 1.30 | 11.54秒 | 23.08秒 | 69.23秒 |
| 10–12 | 1.45 | 10.34秒 | 20.69秒 | 62.07秒 |
| 13–15 | 1.60 | 9.38秒 | 18.75秒 | 56.25秒 |
| 16–18 | 1.75 | 8.57秒 | 17.14秒 | 51.43秒 |
| 19–21 | 1.90 | 7.89秒 | 15.79秒 | 47.37秒 |
| 22–24 | 2.05 | 7.32秒 | 14.63秒 | 43.90秒 |

表中是排程间隔，不保证敌军满场时仍能立即入场。简单难度原有的精英间隔×2保留；Boss种类轮换及每第三次Boss为领主的规则保留。

这套分组频率替代当前精英/Boss“前5分钟逐渐提速、最多20%”的计时倍率，不能再叠乘旧频率。普通主波的单波数量仍沿用现有独立数量预算及前5实际分钟最多20%的数量增长，不把新频率倍率再乘进每波人数。混合兵4:4:1、300活跃敌人上限与Boss留位保持。

主波、精英和Boss的计时进度跨轮连续，进组只改变推进速率。暂停/整备不推进，首次无尽开场的主波保留；后续换轮不额外赠送一次开场波。已有积压和失败重试使用原到期记录，不丢波、不把积压改成更强敌人，也不扩展为无限补刷。

## 已确认：保持按实际分钟计算的基础经济预算

长轮次同时延长付费生产。将普通混合波的整轮矿气预算，以及基础过轮结算，按 `该轮秒数 / 60` 比例放大，保持原来的基础每分钟预算。

基础过轮奖励示例：1分钟300矿/250气；1分30秒450矿/375气；2分钟600矿/500气；3分钟900矿/750气。仍在轮末结算一次，随后套用原难度、天赋和装备倍率；按“每关一次”触发的固定装备奖励只触发一次，不随分钟数重复。

主波更密时将该轮既定矿气预算分配给该轮计划成员，不能同时按时长、波数和敌人数三次放大。精英/Boss与装备的原单次掉落保持；更多出场机会可能带来更多实际掉落，需单独统计，不用暗降掉率抵消。

以下既有节奏保留：每轮结束购物与检查点保存；每4轮开放发展及相应精英特约；永久资源仍每完整60秒实际战斗结算；普通经济事件与地狱扩张虫巢仍按真实240秒循环。长轮次跨越多个经济周期时不能漏掉后续周期。

## 旧档与界面方案

旧无尽档的当前轮保留原60秒长度、波次、经济计划和已承诺奖励，从下一轮切入新时长/成长/频率；旧关间档完成原交易后在下一轮切换。新进入无尽的战局从第1轮使用新规则。不把历史轮次累计时间按新表倒算，不补发此前已结算奖励，不删除真实旧档。

实现时保存排程版本、当前轮长度和必要的出生进度，缺字段识别为当前支持的旧规则。新增状态逐项登记到 `run-fields.ts` 并验证两份备份和失败保护。延迟敌人的出生轮次与成长进度须明确区分真实时间；不能继续用 `floor(累计秒数/60)+1` 推断轮次。

已批准的具体UI范围：

1. 现有“无尽整备”页，将固定“60 s / 轮”改为“前3轮 1分钟”，原详情按钮说明上述分组时长、每轮购物和每4轮发展。保留原页面和按钮尺寸，不新增提示条、入口或面板。
2. 原战斗倒计时读取当前轮实际长度；现有精英/Boss名称中的“无尽N”读取真实出生轮次，避免长轮次显示成累计分钟。其他布局与控制保持。
