# 装备落地与自动拾取接入

日期：2026-10-15。用户要求先制作装备拾取特效并接入逻辑；独立舰装 UI 保持可接入管线。本批使用主游戏 `World`、`BattleRenderer` 与实际装备账户，开发入口为 [装备拾取验证页](../../preview/equipment-pickup-20261015/README.md)。

## 本轮边界与后续顺序

1. 当前：落地实体、五品质反馈、污染标记、自动拾取、满包反馈及共享逻辑接入。
2. 下一环节：一起调整四档战役难度。简单和普通也增加怪物投放；困难和地狱同时调整普通怪能力、波次数量和投放节奏，不能只增加单体数值。
3. 再优化无尽：保留指数增长，按轮次控制增长基准和增幅，消除累计精英出生序号造成的突跳；具体指数、数量与基座留到该环节实测。
4. 最后接入其余装备战斗特效，包括幻影、康斯坦威、持续火场、派生攻击、召回及英雄追加效果。

本轮没有调整难度、刷怪、掉率、装备强度、容量或无尽曲线。此前难度方案中的候选数值不是本轮已执行的定案。五图与既有原战斗效果沿当前基线，存档仍留到 MVP 收尾。

## 落地与拾取

- 三种原创建模组件：武器组件、防护组件、功能模块箱。批量实例绘制共用几何和材质，不为每个装备模板增加独立高模；不替换原 SC2 单位、建筑或地图素材。
- 白色弱底光、绿色底光、蓝色短光束、紫色细光柱、橙金色更高细光柱，配合落地弹跳、短冲击环与少量粒子。污染保留原品质色，叠加异色碎裂纹和文字标识。
- 只有真实库存中的地面装备产生常驻实体。自然敌人死亡与战争掠夺通道均登记同一份落地事件，不改变随机抽取或物品收据。
- 队伍锚点进入 2.5 距离，且地形与障碍之间可通行，才执行原库存领取。领取成功先入包，再播放 0.48 秒吸取拖尾；动画不发奖，不自动穿戴，不暂停战斗。
- 飞行敌人在障碍、水面或悬崖上方死亡时，寻找附近可达地面；仍无附近落点时使用当前连通地面的最近点，最终以合法队伍锚点兜底。实际位置和画面位置共用结果。
- 64 格背包满时装备保留在地面，一次提示，腾出真实空间后恢复领取。不会替换旧装备、自动分解或转进安全仓库。
- 地面名称按品质与距离显示，密集时优先高品质并合并附近名称，数量单独保留；全部实体仍绘制，邻近 1.5 单位网格仅共享品质最高的一组光层，避免叠成白块。实例容量按需要增长，标签与光层合并不删除装备。音效按短时间批次合并，沿现有战斗音量控制，污染落地叠加短音；新增音色是本地合成，不冒称原暗黑或 SC2 声音。
- 动画使用原生模拟时间，暂停和决策窗口冻结。物品删除、结算、新局和地图变化按真实状态清理表现；旧地图地面物品不投影到新地图，也不隔地图领取。

## 独立 UI 接入边界

独立舰装页面、图标资源、布局与预览继续沿现有管线制作。战场渲染不导入整套独立 UI 资源，也不在本轮挂载其页面。

共享接口如下：

| 接口 | 用途 |
| --- | --- |
| `world.starship.account` 与 `revision` | 唯一物品、背包、位置和装备状态 |
| `collectWorldEquipment(world, id)` | 自动领取与 `createWorldStarshipHost().pickup()` 共用的距离、地形、满包、入账与反馈入口 |
| `equipmentGroundDrops(world)` | 当前地图真实地面装备的只读投影 |
| `equipmentBackpackState(world)` | 当前背包数量和既定容量 |
| `world.starship.loot.events` | 带独立序号的短期落地、领取成功、满包事件；各消费者独立游标，不互相取走事件 |
| `EquipmentDrops.resolveName` | 将未来独立 UI 的正式命名映射交给地面标签；当前使用共享装备模板名及组件类别 |

UI 明确发起领取时可以处于其自身暂停租约内，但仍校验真实距离与遮挡；关间不再绕过距离跨场领取。自动拾取在暂停、决策和非战斗阶段不执行。UI 只需订阅已有变更通知，不重做掉率、背包容量或发奖逻辑。

常规应用默认的舰装启用状态保持现有行为：验证入口传入隔离装备账户，通过生产入口启用；正式独立 UI 之后传入同一账户即可使用本批实现。
