## 开始工作

- 先读 README.md、docs/PROJECT_STRUCTURE.md 和 docs/project/README.md 指向的当前交接；然后检查 git status 及本任务有关的最新用户决定。
- 当前进度查 docs/project/performance-board.json 的 tasks 和对应最新报告。日期报告是历史快照，其“下一项”不自动覆盖更新结论。
- 先核对已实现内容，避免按照旧设计重新开发。用户最新明确决定优先于旧文档；源码描述当前实现，不能把实现误差当成用户已批准规则。
- 当前部署、公开发布、MVP 最终验收分别记录，不相互代替。新阶段名称不自动修改应用版本、规则 ID 或存档格式。

## 协作与范围

- 在用户授权范围内主动完成实现和必要验证；仅缺失关键决定时集中提问。原需求、后续纠正和已批准操作跨轮次保持。
- 不擅自改变玩法数值、画质、镜头、布局、控制方式或扩充功能；体验取舍先给出具体问题和可核对方案。
- 不擅自恢复全目录截图观看或无限自动游玩/压力矩阵。T01 按用户自行检查的工作方式，代理重点核验实际结算、状态和生命周期。
- 普通中文说明面向玩家；简略层写用途与主要收益，详情层补数值、条件、上限和限制。
- 共享目录已有改动先辨认来源；不撤销或批量提交其他线程成果。不要 git add -A、git reset/clean 或强推来整理现场。
- 有明确需要时在独立 codex/… 分支/worktree 工作；不因一个普通任务自动创建新的用户聊天或联系其他线程。生产运维与功能开发按任务边界协作。

## UI 核心约束

详细条目与出处见 [UI 规范](UI_RULES.md)。以下不能仅靠索引隐藏，接手时必须知道：

- 任何 UI 新增或修改，先列具体页面和变更内容并取得用户明确确认；功能授权不自动授权 UI 扩改。已确认范围连续实施，不重复问；范围外先讨论。
- 默认极简文案，只保留必要标题、名称、操作、数值、状态和结果。不自动加副标题、灰色小字、描述、装饰标签、提示条和页脚；不为填白造文案，不把交互问题转成说明书。
- 优先用视觉、动画、图标和真实操作反馈表达；只有错误恢复、关键风险和必要复杂操作才补说明。重要信息可读，不用低对比度小字。审查冗余文字，不把删掉的内容搬入 tooltip。
- 已确认的商品/装备说明保留简略与详细层：简略说用途、收益和重要代价，详情补数值、条件、上限和限制；不能按“极简”删掉真实决策信息。
- 自动保存安静运行；真实失败仍需明确可恢复。存档管理集中设置，不扩散入口；正常续局使用已确认的继续游戏。首页免责声明保留，玩家界面不出现测试标记或底层异常原文。
- 延续 SC2 视觉与已确认的三端布局、普通镜头和原操作。桌面不显示触屏摇杆；移动横竖屏保留。统一同级按钮和字体规范，不借清理图标放大字号、按钮或弹窗。
- 后续合流保留用户已确认的品质底色、具体英雄/精英名、中文等级、套装门槛与激活分组等；按详细规范查对应来源，不用旧原型覆盖新决定。

## 项目管理核心约束

详细流程见 [项目管理规范](PROJECT_MANAGEMENT_RULES.md)。

- 每次进入当前看板管理的任务，先读最新决定、依赖和状态；开始更新状态，结束记录结果、证据、失败/阻塞与下一步，不能只在聊天里报告。
- 状态源只有 performance-board.json；修改后执行 `node tools/render-performance-board.mjs` 生成看板和计划表，不直接改派生视图。旧 BACKLOG/status.json 不替代它。
- 使用待办、进行中、待验证、待讨论、已完成、暂缓。实现完成但未验证标待验证；满足完成标准且有证据才标已完成。
- 当前看板最多两项同时进行；重型浏览器/GPU 测量串行。此约束不自动授权多代理或新线程；按已明确的任务分工工作。
- 新发现有固定编号和归属；风险不冒称已复现。任务数量不是整体完成率；按依赖和测量排期，不承诺未经估算的日期。
- 日常进度进入看板/交接，规则进入对应规范，简要结果进 reports/qa，临时材料进 reports/local；不在每份 README 和 AGENTS 重复堆历史。
- 工作和阶段结束说明代码/构建版本、实际验证、仍开放事项及下一步；实现、合流、提交、推送、部署、发布与用户验收分别报告。

## 代码与机制边界

- 沿用 src/app、simulation、render、ui、persistence 分层；不为目录美观大规模搬代码或引入通用框架。
- 纯性能/呈现修复保留固定步、RNG 顺序、伤害、冷却、目标、已付订单和奖励回执。不通过少结算、丢积压或隐藏效果伪造性能收益。
- 渲染与音频不驱动伤害/消耗/奖励；恢复、循环、取消、死亡和重复事件不重复结算。
- 维护同一 World 身份和必要共享关系；新增 RunState 字段在 simulation/persistence/run-fields.ts 明确保存或重建。
- 存档沿用当前统一账户/检查点事务、两份备份及多页冲突保护。写失败保留旧数据；不擅自扩大旧开发档兼容，不静默删除用户真实存档。
- 行为或边界变化同步相关设计/架构；精确数据以当前源码及 npm run docs:data 生成参考为准，并运行 npm run docs:check。

## 资源与产物

- 原版身份、动作、贴图、声音及依赖需有来源证据；缺资源如实记录，不用其他单位、占位模型或生成图冒充原版。
- 原始资源、唯一美术源、真实用户存档和当前正式成品保持。preview 含源文件，assets/private 含历史跟踪项，不按目录名字批量删除。
- 生成新插画沿用已授权范围；私有原图/模型/贴图/截图向外上传需要对应授权，不从文本生成授权推断私有素材上传授权。
- 项目图片写入 D 盘：生成图归档 assets/generated/codex-images，截图/联系表/验证图进 reports/local 对应任务，原型源图进 preview。工具的 C 盘默认图片路径先核对是否为指向 D 盘的目录联接，不能当缓存删除或重新积累实体图片；详见 [项目管理规范](PROJECT_MANAGEMENT_RULES.md)。
- 按 docs/project/ARTIFACT_RETENTION.md 管理文件：完成的可重建截图/视频/详细日志/缓存/旧构建清理，只长期保留简要结论、决定及复现代码。失败也不例外；当前工作保留必需输入。
- 发布应用与内容哈希资源分开，Git LFS 遵循现有范围；不提交数据库、凭据、玩家数据、重复大包或测试缓存。

## 验证、交付与收尾

- 选择与改动相关的测试，必要时完整回归。玩法/存档修改验证结算和恢复；呈现修改验证实际输出；打包验证清单、hash 与真实入口。文档修改不重复重型游戏矩阵。
- `npm test`、`npm run typecheck`、`npm run docs:check` 是常规入口。历史脚本先读 tools/HISTORICAL_QA.md，不能为跑旧脚本恢复旧产品行为。
- 构建离线 HTML 显式指定 SC2_DEMO_OUTPUT，不覆盖保留的 Current。共享 dist/web 使用前核对其他工作是否依赖该版本。
- 只报告实际执行的验证；明确区分模拟输入/物理设备、独立场景/组合战场、功能通过/性能达标、人类认可/自动检查。复用旧证据注明版本和范围。
- 每项工作留下简要结果、受影响文件、证据、未解决事项和下一步；进度写当前状态文件或日期记录，不再向根 AGENTS.md 堆叠日志。
- 提交、推送、部署及公开发布按已有明确授权和实际范围执行；“允许实现”或“备案通过”本身不等于新的公开发布授权。状态未核实就不宣布完成。
