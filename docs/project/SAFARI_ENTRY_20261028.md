# Safari 预下载后进入游戏：修复候选与验证边界

2026-10-28，归属 V06-SAFARI-001。用户要求先确认并修复 Safari 重启，再更新 Sites 和远端 Git，并说明 Coze 更新步骤。本次没有提交、推送或部署；Sites 仍为第 13 版，Git 基线为 `02c312a`。

## 已确认的问题

进入战场时，相同内嵌图片随多个 GLB 模型分别解码，并产生重复贴图上传。首战检查中，715 个受管理贴图来源包含 161 个三档内容均相同的重复来源。预下载只把编码文件写入缓存，不会消除随后解码及 GPU 上传的内存需求。

这证明了资源使用浪费，**尚未证明原手机的终止原因**。用户已补充设备为 iPhone 17 Pro、iOS 26.7.1、自动中档；现象是载入战场时网页自动重载。按上下文暂以当前 Sites 网址排查，用户尚未提供具体地址、重载提示或系统记录。不能将页面重载、Safari 退出或整机重启混为一谈，也不能用 Windows WebKit 代替 iPhone Safari 验收。Apple 的 [Jetsam 诊断说明](https://developer.apple.com/documentation/xcode/identifying-high-memory-use-with-jetsam-event-reports?language=objc) 可用于核实是否因内存压力终止进程。

## 本地修复

- 构建工具按高、中、低三档的完整图片内容生成身份记录；只有三档均对应相同图片的来源才共享解码结果。不同材质继续保留独立采样和颜色设置。
- 画质替换前使旧缓存身份失效，防止后续模型把已更换的图片当作旧档图片复用。旧清单没有身份记录时保持原加载路径。
- 原版特效解析时直接绑定已经准备好的材质，避免解码随后被丢弃的材质图片。模型几何、骨骼和动画字节保持。
- 对不提供内存容量的触屏设备收紧下载、图片解码和音频准备并发；没有改画质档、分辨率、模拟规则或存档。

资源二进制没有重新压缩。候选应用 `0c736e81df95afab131b0e5b442bbc2f526a3260a52d5566ca4d12c7b176a389`，资源清单 `943ec11700634ac91311753a9f66750c7a2d8313aa7724ac4a246a06409497e1`。输出位于 `dist/safari-20261028/public`，其中 `quality-lab.html` 和质量检测脚本仅用于本地验证，不可发布。
