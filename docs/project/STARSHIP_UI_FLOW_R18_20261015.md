# 舰装 R18：完整流程、54 张英雄立绘与共用接口

实际完成与验证日期：2026-10-16。文件名沿用 20261015 批次。

本批完成可操作的舰装 UI、共用控制器、内存宿主与真实 `World` 宿主，以及可双击运行的单文件 HTML。两种宿主使用同一套页面和装备规则，真实宿主直接使用传入 World 的装备账户、拾取和属性刷新接口。常规主游戏菜单没有挂载整套新 UI；本批没有替换 Current 或既有命名交付，没有提交、推送或在线发布。

默认进入舰桥，可操作旗舰配装、三族各三个预设、仓库、工坊、出征准备、战地背包、关间整备、继续挑战、撤离／失败结算、待入仓、图册与设置。详情支持白字、绿字、继承与实际生效能力、同槽比较、锁定和收藏；列表支持搜索、筛选、排序、分页和多选。

演示工具默认收起，F1 展开。可切换“独立账户”和“隔离真实 World”，生成演示掉落、结束关卡、触发原生失败以及准备满包／满仓／无粉尘情境。切换宿主或刷新会重新开始本次演示。B 可打开关闭状态下的背包。初始样例由生产规则创建：仓库 288 件、三族各穿戴 9 件、粉尘 18,000。

这是装备流程入口。真实宿主使用实际 World，但该独立入口关闭自然刷怪与地形，不承载完整战役画面；其中“继续挑战”通过原生 `skipReward()` 完成本演示未购买的关间选项，然后进入下一关。未来主游戏挂载应传入自己的出征资源准备及关间选择回调。

## 生产结构和接入

| 文件 | 职责 |
| --- | --- |
| `src/ui/starship/host.ts` | 账户读取、种族、阶段、事件、命令、图片解析和窗口租约接口；会话管理状态 |
| `src/ui/starship/controller.ts` | 两种宿主共用的命令、阶段限制、批量预览、保护规则及重复／过期请求校验 |
| `src/ui/starship/view.ts`、`style.css` | 十个页面、弹窗、输入焦点与可卸载挂载函数 |
| `src/ui/starship/world-host.ts` | 现有 World 适配器；原生装备、拾取、出征、关间和结算 |
| `src/ui/starship/memory-host.ts` | 同规则内存宿主；独立流程验证的阶段容器 |
| `src/ui/starship/presentation.ts`、`catalog-data.json`、`effect-text.ts` | 合法装备与图片映射、中文名称、由实际规则推导的效果说明 |
| `src/ui/starship/art-effects.ts` | 污染黑紫雾、净化橙金光晕；小图静态、详情动态及减少动态选项 |
| `src/simulation/starship/phase.ts`、`loadout.ts` | 按实际战斗阶段校验换装；完整预设的原子校验与交换 |
| `preview/starship-ui-flow-20261015-r18/main.ts` | 样例账户、两宿主切换、调试工具和情境夹具；正式 UI 不导入这些夹具 |

挂载方导入 `style.css`，将自己的同一个 `World` 实例交给适配器，再挂载共用 UI。以下的 `resolveImage`、`clearHeldInput`、`beginThroughApplication` 和 `continueThroughApplication` 由主游戏入口提供：

```ts
import { createWorldStarshipHost } from '../../ui/starship/world-host';
import { mountStarshipUI } from '../../ui/starship/view';
import '../../ui/starship/style.css';

const host = createWorldStarshipHost(world, {
  resolveImage,                  // (key, detail?) => URL，键来自 resources.json
  inputReset: clearHeldInput,     // 打开和关闭时清除宿主的按住／拖动状态
  begin: beginThroughApplication,
  continue: continueThroughApplication,
});
const ui = mountStarshipUI(root, host, { startOpen: false });
ui.open('loadout');

// 所属界面销毁时：
ui.dispose();
host.dispose?.();
```

`begin`／`continue` 返回同步接受结果；如主入口需要异步资源准备，应由主入口持有异步流程并在就绪后执行实际 World 操作。不要在该回调外另建装备账户或先向副本付款。`management` 可由宿主注入，以在同一会话的重新挂载间保留锁定、收藏、预设及设置；本批不新增持久化、存档格式或迁移。

打开 UI 会取得独立暂停租约，并设置现有输入捕获标记；关闭仅释放自己的租约，保持其他窗口及原生暂停状态。卸载释放事件、订阅、焦点、效果动画和计时器。真实拾取复用 [装备拾取批次](EQUIPMENT_PICKUP_IMPLEMENTATION_20261015.md) 的 `collectWorldEquipment()`、`equipmentGroundDrops()` 与原生入账事件，没有再建另一套拾取账本。

## 规则与状态边界

| 阶段 | 可执行行为 |
| --- | --- |
| 局外／结算后 | 合法装备与整套预设、合成、清洗、洗练、分解、扩仓、处理待入仓及再次出征 |
| 战斗中，包括暂停 | 查看、比较、范围内拾取、锁定／收藏及丢弃；直接调用原生装备接口也不能绕过换装限制 |
| 关间 | 换装仍遵从现有 `canEquip`：仅当前背包的合法属性散件；模块、套装及整套预设只能局外使用；可继续或撤离 |

满 64 格背包允许同槽一换一，旧装备回到背包；主动卸下必须有空格。真实 World 刷新属性时保留当前生命与护盾比例，不借换装治疗。完整预设先校验所有物品、种族、槽位、污染、位置和最终容量；任一项非法不会部分穿上。

一键丢弃覆盖整个背包的所有分页，提供白色、绿色及以下、蓝色及以下三档。确认前列出实际数量与跳过原因，默认白色。手动锁定、收藏、已穿戴和系统奖励来源锁定会阻止相应误操作；手动管理状态不改变失败遗失规则。丢弃不返还粉尘。批量精英绑定洗练和分解先筛除保护／不合法项，再按共享规则付款与执行。

洗练只付款一次，提供三个候选或保留原项；保留不退款。账户修订号和管理状态修订号共同校验确认请求，命令 ID 检查重复内容。每次挂载使用新命令命名空间，避免重新挂载误复用先前的合成回执。

结算按原规则处理，污染装备失败必失，普通背包物品按原随机规则判定；穿戴和局外仓库不参与背包遗失。满仓战利品进入待入仓，仍占用真实状态且阻止未处理时再次出征。真实宿主监听原生结算，保留本次遗失物品的展示快照，不再次发奖。

本批不调整难度、怪物投放、无尽增长、装备强度／费用／掉率或其他装备战斗特效。这些继续沿各自已记录的工作顺序推进。存档工作保持“MVP 收尾前都不考虑存档”的延期边界。

## 图片、映射与来源

保留既有 441 张装备图：372 张白绿蓝紫、36 张橙色模块及 R17 的 33 张橙色套装。新增选择 18 位英雄 × 攻击／防御／移动三姿态，共 54 张透明背景原版形象插画；三族旗舰背景图另外 3 张，共 498 个资源键。54 张是本批选用数，重做候选不计入完成数。

英雄包括雷诺、泰凯斯、诺娃、斯旺、托什、大和战列巡航舰；凯瑞甘、扎加拉、德哈卡、斯托科夫、尼亚德拉、利维坦；阿塔尼斯、泽拉图、阿拉纳克、菲尼克斯、沃拉尊、净化者旗舰。巨舰分别表现武器、防御与推进状态；菲尼克斯采用四足机械形态。

进攻四槽使用攻击姿态，装甲两槽使用防御姿态，动力两槽使用移动姿态。普通橙英雄、污染橙英雄及各自合法紫色下位件共用原版形象；实际品质、套装家族、绑定及门槛独立计数。清洗改变污染状态与表现，不把污染家族改成普通家族。污染和净化继续使用已确认的 R2 黑紫雾／橙金光晕方向。

图册从历史 14,979 条展示记录筛得 14,811 条生产合法映射，覆盖全部 210 个生产模板；168 条旧稿里的不合法污染组合被排除，逐项理由保留在 [mapping-audit.json](../../reports/local/starship-ui-flow-20261015-r18/mapping-audit.json)。原图片和历史图册未删除，生产模板与允许的装备内容没有因此删减。

英雄原图、提示词、原生成路径、D 盘实际归档路径、runtime／detail 图及 SHA 均在 `hero-art.json`。原图放在 `art-source/`，实际生成归档在 `D:\星际\assets\generated\codex-images`；历史 C 盘路径为目录联接兼容引用。转换只做透明图片的技术缩放与 WebP 编码。初版裁切候选、菲尼克斯防御修订前原图及提示词记录保留；未用最终图覆盖旧候选。

## 实际验证与限制

- 最终全量回归 **1,581 / 1,581** 通过，无跳过；类型检查和数据文档检查通过。UI 专项 20 项包含真实单位 HP／盾比例、两个宿主的账户与随机状态、满包交换、阶段限制、三档跨页丢弃、锁定无失败保险、待入仓、原子预设与重复付款。
- 最终 Chrome 自动化 **26 项通过、72 张截图、页面错误 0、控制台错误 0、外部请求 0**。HTTP 入口和实际 `file:` 命名 HTML 均运行；621 个小图／详情图变体解码，包含 54 个互异英雄姿态键。
- 两宿主均完成配装、实际付款合成、清洗、洗练保留、拾取、关间换装、64 格满包交换、跨页丢弃、进入第 2 关、撤离、失败与满仓待入仓处理。三族页面在 1440×900、844×390、390×844、320×740 检查横向溢出；另有 320 宽／1.3 倍文字和自动化触摸操作。
- 同一真实 World 连续挂载／卸载 12 次，订阅数 3 → 3，窗口暂停与输入释放通过；另有原生暂停及其他窗口租约保护断言。
- 最终 72 张截图通过 12 张联系表核对，并查看菲尼克斯三姿态和 320 宽大文字原截图。54 张新立绘与 R17 的 33 张图已有 9 张源图联系表核对；生成图逐张检查与修订记录保留。此为模型视觉检查，不写成用户美术确认。

宿主一致性有明确范围：局外相同命令比对完整装备账户。出征流程从 **World 原生开场完成后** 的相同账户起点比较；关间之后仅排除 `account.run.receipts`，因为该集合包含 World 独有的矿物／商店窗口回执，测试另外断言原生 `stage-resource:1` 仍存在。其余账户字段、物品身份、位置、粉尘、随机状态及修订号保持一致。内存宿主不伪装原生单位开场或战场模拟。

早期失败保留原记录：适配器测试曾暴露错误词条夹具、开场 RNG 比较起点、原生窗口回执差异及真实关间未推进的问题；后者已改为原生跳过序列。第一次全量回归有旧“战斗中允许换装”断言；第二次有 3 项旧渲染／音频夹具缺少新拾取依赖。最终只补齐这些测试夹具的关闭舰装状态和空掉落容器，原断言未弱化。所有早期日志、浏览器候选和图片候选留在本批 `reports/local/` 与 `preview/` 原路径，不改写为最终通过。

本次未进行自然完整战役、全内容 60 FPS、真实触屏／手柄／物理键盘硬件验收、主游戏整套 UI 挂载或最终存档恢复验收。结果不代表整个 MVP、正式发布或生产／B4 完成；既有五图确认与冻结继续有效。
