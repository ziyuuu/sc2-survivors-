## 二、持续观察的具体行为

1. 短效果完整播完尾迹，再以短间隔重复；不把每一帧都当新事件叠加。普通攻击和持续光束维持可观察的连续阶段。
2. 生成、持续、正常结束、死亡/取消按实际适用流程分别提供入口。选择“到期退场”会先展示对象，再发生真实退场，随后重新开始一轮。
3. 等待较久的装备周期、任务寿命和冷却只在检测场景中预置临近边界；显示当前阶段。正式游戏的冷却、概率、数量、寿命不改。
4. 循环重建清理上一轮的实体、投射物、粒子、飘带、音频声部及反馈收据。切换条目/模式后不残留旧效果，用户暂停时不自动重启。
5. 不同效果分别触发，不能只提前最早的一个周期；概率分支用可复现的有效场景触发，并核验真实结果。
6. 套装预览中本次观察到战斗HUD占用下方画面。实施时在检测容器内隔离无关HUD，调整预览取景，保留正式游戏界面。

## 三、套装覆盖口径

当前资料包含210个装备模板、3801个配置；其中104个含品质的套装模板、2601个套装配置、96种套装效果键。104不是104种独立套装名称。现动态目录包含55个套装模板、336个套装配置；其余49个模板在说明目录中，不能将它们全部等同于缺失特效。

实施时逐个效果核对以下映射，未匹配项必须明示并处理，不能因“页面运行成功”记为完成：

- 套装名称、品质、件数门槛及绑定方向 → 实际生效效果与参数。
- 效果 → 真实原生触发入口、必要对象和条件 → 可观察结果。
- 可观察结果 → 出生/生成、持续、命中/消耗、到期、死亡/取消等适用阶段。
- 无独立画面的属性/经济/规则效果 → 数值前后或规则说明；不编造战斗特效。

三族、2/4/6/8件等实际门槛、品质及英雄/精英绑定按真实差异保留。共用同一画面的重复数值配置可以合并，但必须能查到覆盖关系。新增“产生陷阱”“触发救援”“召回离队单位”“生成幻象”“幻象到期”等具体入口，避免只给“terran·4件”却不说明当前展示什么。

本次原生受控20秒检查还确认：紫色幻影4件可产生副本，20秒时有4个仍存活，单次寿命30秒；该结果不能代替其完整寿命检查。净化天空赠舰实际创建大和单位，modelKey未显式设置，需在实施阶段核验最终资源选择及尺度，当前不将其断言为与任务协战舰相同的问题。

## 四、实施顺序与完成条件

1. **先修正对象与正式渲染问题。** 处理带追猎者本体的通用效果、狂热者发辫，以及协战舰比例。修正巢虫/三舰/幻象/召回/退场夹具，使展示来自真实流程。
2. **再补齐可观察的触发与循环。** 为所有适用动态条目配置完整周期和重复策略；完成套装效果映射、自动触发与生命周期入口。移动酒馆等无独立动态的规则条目。
3. **最后同步交付并核验。** 正式改动进入正常构建；检测工具和同版生产模块打入一个新的综合离线HTML。保留165个单位及既有365个UI展示状态，动态对象数随正确归类调整，不为凑数量保留空条目。

完成条件：

- 每种效果都有实际触发和结果证据；实体数量、类型、模型、召回位置、寿命、删除时间、音频起止与原生定义相符。覆盖检查报告明确区分“有用例”“已触发”“已核验”。
- 受影响路径比较修复前后战斗状态，扣除明确的显示字段后，伤害、冷却、召唤规则、掉落与装备规则保持；旧存档只修正显示兼容。
- 循环公共调度加自动化检查；各生命周期类型至少连续3轮，验证暂停/逐帧/切换和结束清理，不能累积实体或声音。
- 狂热者用修复前后同动作画面核对发辫与刀光；舰队用同镜头比例参照及完整三舰场景核对。桌面、横屏、竖屏检查检测界面与取景。
- 运行必要相关测试、生产/工具类型检查、正常游戏入口及最终离线HTML有限检查，验证实际声音、控制、导出、无网络依赖与无页面错误。
- 自动检查覆盖语义与机制，用户继续最终画面/试听；不重新启动代理全目录逐项截图观看，不提前通过T01/V04/MVP。
