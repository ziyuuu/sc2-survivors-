## 已定位的画面问题

1. 战场视距下的小体型身体偏暗，局部轮廓和材质层次不足；应先修材质／光照，再决定镜头变化。
2. 高等级精英的紫色或渐变覆盖可能遮住源纹理；应只作用于来源允许的队色／身份区域。三种精英毒爆腹部白面需要分层校准。
3. 普通和三个精英不朽者均有大块平白覆盖；关闭泛光并未消除来源问题。既有R17的定向源适配是先行证据，不代表本轮138身份已修复。
4. 精英破坏者近景与战场剪影偏小，需要对照源包围盒、原生半径、模型presentation scale和镜头再决定；不能改战斗半径来修画面。
5. 航母真实子单位的血条挤占战场。虫族载体的大范围圈也影响身体／地表识别，须与并行UI工作的最新修改核对后再集成。
6. 地表、投影、分图光照、氛围与构图候选可以分别判断，组合候选仍偏暗，不能整体默认开启。正式修复必须先把不朽者、死亡附属层、输出与身份着色的问题处理正确。

## 失败、异常与仍需完成的门槛

- V3地图绑定遗漏、V4死亡阶段时钟停止、源路径首次解析错误、事件快照浅拷贝、超过家族容量和不存在敌方类别等测试装置错误均保留；后续修订修正。不会以失败装置记录判断正式游戏故障。
- V6持续测量使用旧事件扫描和自动化轮询，存在装置开销；该批帧率不用于CPU归因。V8收集器修正后，人族和部分虫族记录有效；虫族96体出现约746ms帧间隔。V9分段CPU和GPU未解释全部间隔，调度原因未定。
- V9后续批次约每秒一个帧回调；页面的可见／聚焦标志不足以证明真实呈现。打开浏览器的应用请求为queued，visibility请求未建立可见状态，截图也失败。三族／五图的可靠性能比较仍需真正显示浏览器后复测。不能将4–5帧样本作为有效成本证据。
- 首次V10 canvas导出得到空画面，原始记录和首张PNG保留。V11改为导出前立即原生render，再逐图核对PNG；不得把空画面算作已完成视觉对照。
- 导出接口对长字符串截断，首次V11单张PNG因此不完整；分段读回长度校验后完整PNG已解码。首次桌面恢复批次首组仍是1024尺寸，保留为`v12-desktop`尝试；固定1280实际宽度后的`v12-desktop-final`才作为四尺寸正式记录。
- 原版SC2同光照／队色／视距匹配录像、自然高密度战斗、物理手机／高刷／低内存、长时运行、人类美术判断仍属开放门槛。五图全部起点／中段／晚期构图属于后续完整美术实施的验收矩阵；本轮为方案候选测试。
