# 地图 单位与特效完整修复计划

地图、单位和特效都需要修复。优先处理原始材质语义在转换与运行中丢失的问题，再补投影、调整五图材质与照明，最后处理战斗特效的时序、叠加和性能。当前证据不支持通过统一提亮、提高金属度或增加后处理来一次解决质感问题。

本轮是调研、测试和实施计划。正式游戏保持主线 `ed215df3e0b50ccf7c5bc04d06b99114514db43a`，Web `d502a132ea56395855ae3c1a3e04c0b254692df763ea96750153d82972ed986a`，应用 0.6.8。实际验证、截图、计时和限制见 [本轮验证记录](VISUAL_REPAIR_RESEARCH_20261008.md)。本计划不代表修复已经正式集成。

## 已确认的问题与证据强度

| 优先级 | 问题 | 本轮依据 | 处理范围 |
|---|---|---|---|
| P1 | 复合材质与发光附属层解释错误 | 不朽者待机白块在关闭 Bloom 后仍存在，旧实验的原材质控制适配可恢复机体；`m3-scene.mjs` 把复合材质压成第一个标准材质 | 原始材质描述、导入器、运行材质、每实例动画控制 |
| P1 | 类似风险不限于不朽者 | 全部 206 个当前 GLB 中，37 个材质条目同时具有 unlit、无底色贴图、有发光贴图，涉及 27 个模型；其中含死亡模型。它们是待逐项复现的风险清单，不是 37 个已确认的可见故障 | 普通兵、精英、英雄、死亡、附属模型全量检查 |
| P1 | 狂热者死亡出现强白色光团 | 实际 World.hit／step 死亡诊断在 0.2 秒与 1.5 秒采样均可见，5.5 秒已不可见；关闭 Bloom 后仍有白色主体，定向隔离 `zealot.death` 后消失。尚未测得精确持续时长，也不能等同于旧 P6 的全部来源 | 优先核对该死亡模型的发光层、动画轨道、混合与淡出，再扩展同类死亡模型 |
| P1 | 材质扩展组合不符合规范 | 9 个材质同时带 `KHR_materials_unlit` 与 `KHR_materials_specular`；Khronos 明确排除此组合 | 明确每个材质的着色类别，再生成合法表示 |

| P2 | 五图地表材质与环境层次不充分 | 地表已有法线与真实起伏；四图仍共用同一八层纹理集的不同选层，查尔另用原贴图；粗糙度主要是整图常数，岩石与地表接缝仍生硬 | 地表选层、混合、尺度、粗糙度、接触过渡、分图照明 |
| P2 | 单位高光与原材质响应有差异 | 多数模型有法线和高光数据；导入器将源 specularity 近似为 roughness，原 HDR 高光与分层语义未完整保留 | 材质类别校准；比较原高光近似与现有 PBR 的可控适配 |
| P2 | 特效依赖近似重建 | M3 转换未导出原生粒子系统；运行中有独立的贴片、实体特效与批准的英雄实现 | 保留已批准设计，逐项恢复纹理、UV、混合、持续与空间关系 |
| 待验证 | 法线方向、切线、LOD、动画采样是否造成局部损失 | 已有 packed-normal 转换与测试；缺 tangent 也可由 Three.js 导数重建；动画 atlas 为 24Hz 且有插值。完整网格对照不能说明所有分辨率的 LOD 都无问题 | 逐模型、动作、视距检查，不全局翻转法线或关闭 LOD |

37 个风险条目与 9 个扩展问题可能重叠，不能相加当作故障总数。扫描的是实际可达的运行 GLB，不是全部私有源模型。完整清单在本地 `resource-audit.json`、`extension-audit.json`。

本轮 300 目标暂停场景的三次交叉测量显示：当前基线、加投影、完整组合的 GPU 均值中位数分别约 6.94／7.34／12.46ms；完整组合的 P95 为 33.4–33.7ms。基线与投影样本也有明显波动，不能据此批准默认开启。投影试验在查尔还出现偏黑阴影，照明试验在冰图使地表更平；这些候选需要继续校准，不能整包直接移入正式游戏。全部九次原始结果见验证记录。

## 修复架构

保留 Three.js、Vite、单一 World 和 60Hz 模拟。新增的材质描述与渲染控制从原 M3、Actor 和实际 World 事件读取，不把材质状态写回战斗规则，也不消耗玩法 RNG。

1. **源描述层**：保留材质类型、复合部件、默认 alpha、纹理用途、通道、UV 源、偏移与缩放、动画引用、混合、深度、裁剪、双面、Fresnel、HDR 与高光参数。对不支持的类型输出可定位清单，禁止静默退成白色实体。
2. **材质层**：区分受光实体、发光层、普通透明、加色、裁剪和折射／扰动。共享材质定义与 GPU 数据，不为每个单位复制独立材质和 draw call。保留原纹理、身体边界和既有模型身份。
3. **实例与事件层**：用稳定实体 ID 关联 batch 槽位，处理压缩、移除、重用、死亡、出生、变形与重新载入。身体姿态、攻击叠加、材质动画和护盾开关使用对应时钟。旧实验通过位置匹配槽位，只能用于冻结诊断，不能直接用于移动战斗。
4. **输出层**：规范线性色彩、HDR 累积、透明混合、tone mapping 和最终 sRGB 输出。检查目前按英雄是否存活切换 composer 的行为，防止全场观感随英雄加入或死亡跳变。Bloom 是单独可验收的效果。

原始资源文件只读；确有必要新增派生描述或重新导出运行副本时，保留源哈希与新旧清单、版本化生成工具，并把资源差异纳入发行验收。未经逐项校准，不全量换成 Phong，也不把所有模型的金属度设成 1。

## 分阶段实施

### R0 固定对照与源清单

锁定正式提交、Web、应用、资源、浏览器、GPU、画质和真实渲染分辨率。建立三方对照：当前基线 A、单项候选 B、同单位／同地图材质的原版 SC2 参考 C。原版记录地图光照、队色、质量档、相机、动作阶段与时间点；相机不能完全配准时比较明确的轮廓、材质和时序，不报整图像素一致。

本轮已提供可复用的固定场景、通道扫描与诊断开关。原版 SC2 当前客户端的匹配场景录像仍需补采；官方文章和原始模型参数仅支持设计判断。优先参考普通不朽者／精英不朽者、狂热者死亡、陆战队员、坦克、蟑螂、航母，以及五图地表与主摆件。

**出口**：全部 206 个 GLB 的材质分类与未支持清单完整；37 个候选逐个注明已复现、预期行为或待查；先给不朽者、狂热者死亡和地图岩石建立可重放基准。旧失败与旧构建身份保留。

### R1 材质与控制正确性

主要文件：`tools/m3-materials.mjs`、`tools/m3-scene.mjs`、`tools/import-m3-pack.mjs`、`src/render/loaders/sc2-materials.ts`、`src/render/units/animated-batch.ts`，另增独立的源语义与实例材质控制模块。

- 恢复复合层默认关闭与 Actor 启停；实际护障开始、保持、结束对应原动画曲线。显式区分无底色的发光材质与白色底色。
- 修正非法 unlit/specular 组合；验证第一、第二发光层以及 alpha 层的纹理色彩空间、UV 源、变换、乘加和动画。源模型明确需要的纹理不能落到默认白值。
- 完成攻击叠加材质轨道、复活／重载、变形与死亡事件绑定，禁止以位置寻找实体或用全局时间替代启动时刻。
- 把不朽者作为先行样本，再按数据清单扩展；死亡模型独立验收，不能只检查活体。

**出口**：已确认错误全部有来源、前后截图与时序记录；非激活层在预期阶段为零；同时存在多个实例且错峰触发时互不串状态；原本可见的批准效果不被误删。恢复相同存档后呈现正确阶段，不重播已结束爆炸。所有已支持材质扩展组合合法。

### R2 投影与接触关系

以现有单个主方向光和约 1024 级阴影图作为首个候选，测量后决定质量档。接入原 GPU 骨骼、炮塔、形变和实例变换，分别检查实际投影与深度／法线 pass。阴影相机覆盖当前可见范围，稳定到纹素，校准偏移以避免悬浮与自遮挡斑纹。

先做单位／摆件投影，再评估静态接触遮蔽或烘焙方案；半分辨率 SSAO 保留为独立可选候选。采用真实投影时处理旧圆形软影与地表手工暗斑的重复叠黑。低画质回退保留定位线索。

**出口**：静止、移动、转向、炮塔、飞行、变形、死亡、视口边缘与宽高比变化均无错位、闪烁和遮挡跳变；投影与实际身体姿态一致；低档不丢必要战斗信息；满足后述性能门槛才默认开启。

### R3 五图地表与场景材质

主要文件：`src/render/terrain/campaign-ground.ts`、`campaign-textures.ts`、`campaign-map.ts`；环境美术数据与影响碰撞的 `campaign-landscape.ts` 明确分界。

| 地图 | 重点修复 | 验收画面 |
|---|---|---|
| 工业遗址 | 地板与尘土／碎石混合、接缝、磨损尺度，金属与土地区分 | 起点、道路转折、建筑基座、边界 |
| 玛萨拉 | 砂土与岩石粒度和暖色层次，岩脚过渡，枯植被接触 | 沙地空旷区、岩群、植被旁 |
| 查尔 | 焦土／裂纹／熔岩分层，亮部范围与灰黑细节，热光局部化 | 暗地、裂隙、岩群与单位同屏 |
| 冰封哨站 | 雪与岩石各自的法线和粗糙度，积雪朝向与覆盖，降低大片无细节亮面 | 雪地、岩脚、积雪摆件与蓝色单位 |
| 边境矿场 | 压实路面、矿屑、尘土与机械区的材质关系，减少纹理重复 | 矿区入口、运输路线、机械摆件 |

先确认已有原贴图能表达哪些材料，再恢复适当的选层、混合／高度语义、纹理密度与粗糙度变化。以污渍、碎屑、植被疏密和基座过渡连接摆件与地表；配置每图主光、环境色、雾与有限反射参考，并同步检查三族单位。

本阶段保持 160×160、出生点、18 阶段开放面积、寻路和射线阻挡一致。真正增加悬崖、坡道或改变大摆件碰撞属于另一个几何变更包，需要更新地图身份并重验通行和战斗；不能伪称纯美术修复。

**出口**：五图各有起点／中段／晚期、空场／三族同屏的对照；岩石不悬浮、接缝不过硬、纹理尺度一致、明暗区域能辨认单位；冰雪和熔岩亮部仍保留层次；地图几何与完整 World 对照一致。

### R4 单位材质与细节

依材质类别建立参数表：人族涂装金属／裸金属／布料，虫族甲壳／软组织／黏液，神族金属甲板／晶体／发光层。将原高光颜色、强度、指数和 Fresnel 映射到明确的着色约定。比较现有 PBR 适配、原高光近似的误差与成本后选择；每个类别先用少量模型校准再扩展。

检查身体法线、镜像 UV、缩放与骨骼后的法线、低 LOD 接缝和轮廓。当前 24Hz atlas 带插值，只有时序或近景证据证明有损失时才增加采样；只为失败模型保留更高 LOD，避免普遍增加顶点与显存。

**出口**：30 普通家族、90 精英、18 英雄以及共享模型的变形／子单位／死亡覆盖完成；身体轮廓、队色、身份配色、原武器挂点和已批准动作保持；五图中无塑料化、过曝或黑成剪影的系统性问题。

### R5 特效时序 空间与叠加

按“源模型／纹理 → 实际事件 → 发射与挂点 → 生命周期 → 消退”建立表，覆盖普攻、弹道、火焰／光束、范围技能、护盾、治疗、出生、死亡、复活、脚下效果和资源掉落。保留已批准英雄与精英的技能形态、范围、数量和时刻。

- 核对普通透明、预乘 alpha、加色、深度测试／写入、排序、背面与多层交叠；每类先以单个实例验证再组合。
- 恢复 flipbook 起止、UV 滚动、颜色／大小／透明度曲线；导入器没有导出的粒子、ribbon 与扰动按可见影响排序适配，避免把全部特效仅当平面贴图。
- 优先确保发射口、目标点、范围边缘与终止时间正确；再增加地面软交界、适量局部照明或深度感。每项都有成本上限。
- 分离主体、轨迹、装饰的预算；不能为了减亮而删去命中核心、危险范围或批准的脚下效果。镜头外和结束的粒子及时回收；检查同材质实例排序与批次上限。
- 单独复现 P6-V01：先固定同一状态，依次隔离死亡、子单位、掉落物、护盾、英雄／精英、Bloom；随后连续记录启动至结束，确定贡献与持续时间。当前 schema26 应重新获得相应自然战局；旧 schema23 检查点只在其原构建中复核，不向正式游戏添加旧档兼容。

**出口**：开始／峰值／结束与多次重触发均正确；1、10、30 个同类效果和真实大编制混战可读；透明排序、长驻亮块、重复播放与残留对象问题关闭。P6-V01 只有在匹配场景、连续证据和人工复核支持时才能关闭。

### R6 全场验收与发行

每个功能独立开关、独立提交、独立回退。组合测试只接纳已通过单项验收的方案；比较 A 当前基线、B 单项修复、C 最终组合、D 低画质回退，并在相同状态下切换。旧实验的 B／C／D 名称仅用于历史对照，不当作正式版本名。

**逻辑与资源保护**：核对完整 World／Profile、地图与 RNG；材质和画质切换零状态变化；不改变攻击、伤害、时钟、技能、数量、身体尺寸和 hellion.2 已批准范围。原始 M3／DDS／UI 位图与旧证据哈希保留。Coze v10、已启用配置、私有数据库和后台均不在视觉修复范围内。

**自动与浏览器检查**：运行完整当前回归、typecheck、数据文档与 165 天赋检查；Web 和全离线覆盖三族、30 家族／90 精英／18 英雄、变形／子单位／死亡、保存／加载／新局、窗口调整与 context loss。真实浏览器截图与录像必须检查画面；单纯断言“资源加载成功”不能当作视觉通过。

**自然性能门槛沿用既有合同**：同机同浏览器、同存档、同视角、同 CSS 与实际像素分辨率、同画质，三次 180 秒自然样本；P95≤16.9ms，P99≤20ms，超过20ms帧≤1%，新增模拟欠账≤0.1秒且不累积。保留首十秒、加载／转场、长帧、失败与 GPU disjoint 情况。另记录 GPU、CPU 提交、draw calls、显存估计与贴片覆盖。固定暂停场景用于归因，100／300 目标用于压力诊断，二者都不能替代自然门槛。

**视觉验收**：固定相机、灯光、姿态、seed 与时刻；采用全图、单位局部、法线／材质通道、分层与时序对照。数值记录可包括固定单位区域亮像素比例、轮廓／地表对比及残留时长，但雪地、熔岩和预期闪光使用各自基线，不能设一个全图白像素阈值来压暗所有效果。原版参照只比较已配准条件。

**分档与回退**：原材质语义正确性是各档共有底线；投影分辨率、AO、环境反射、装饰密度按测量分档。降低画质不得改变模拟和核心反馈。原版阴影方案可回退，已修复的白块与状态错误不应被回退重新引入。

**发行出口**：生成带真实构建身份的新 Web／离线 HTML／应用包；校验资源重用与新增清单、离线恢复、包更新／回滚／重复执行／篡改拒绝；提交、推送、比较 main。视觉修复本身不授权单独 Coze 上传或线上数据库操作。人工、实体设备、低内存、长时间和完整 M6/M7 门槛按实际证据分别报告。

## 顺序与工作量

建议执行顺序为 R0 → R1 → R2 → R3 → R4 → R5 → R6；在 R1 中尽早处理死亡和发光材质，避免它们继续干扰后续照明判断。R3 与 R4 相互校准后，再确定特效最终亮度。

| 阶段 | 单人专注开发的初步量级 | 交付物 |
|---|---|---|

## 技术依据

- [Blizzard SIGGRAPH 2008 原文](https://advances.realtimerendering.com/s2008/SIGGRAPH2008%20-%20StarCraftII.pdf)，第 5 章，说明 SC2 当时的分层材质、局部光、遮蔽、阴影和可扩展性设计；这是历史引擎资料，不是当前客户端参数表。
- [Blizzard 地图美术指南](https://news.blizzard.com/en-us/article/20097658/mastering-mapmaking-part-one)，支持单位可读性、摆件与地表衔接、阴影及粒子覆盖成本的验收方向。
- [Three.js 色彩管理](https://threejs.org/manual/pages/color-management.html)，用于检查颜色与数据纹理、线性计算及最终输出；具体实现同时核对本地锁定的 0.186.0 源码。
- [Khronos unlit 定义](https://github.com/KhronosGroup/glTF/blob/main/extensions/2.0/Khronos/KHR_materials_unlit/README.md)与[specular 扩展](https://github.com/KhronosGroup/glTF/blob/main/extensions/2.0/Khronos/KHR_materials_specular/README.md)，用于判断着色输入与扩展组合是否合法。
- 原始 M3／Actor、本地转换器、运行 shader 与固定诊断是项目因果判断的依据。第三方 M3 reader 使用旧实验已固定的 `ee0eff037e2e40d2aad72f4f856af0710b8a44e5`，不把其渲染效果当作 SC2 原版。
