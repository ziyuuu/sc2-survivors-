# S07 密集移动与占位查询小合批 · 2026-10-20

用户批准S07相关移动/碰撞查询小合批，同时补A01对应六条审计并回归S09爆虫主动接近。实现、Node验证及浏览器对照已本地完成。[看板](PERFORMANCE_BOARD.html) · [范围报告](../../reports/qa/performance-s07-20261020.json)。

## 实现与采纳范围

本批只改五处生产文件：native-traversal、terran-elite-runtime、protoss-elite-runtime、engagement、squad。

- 跨崖的一次同步搜索内复用起点高度、当前占位实体与预留落点列表；仅在实际进入阻挡检查时整理地图placement尺寸、旋转参数。每次新搜索重新采集，不跨tick缓存失败、不降重试频率；提交落点仍重新检查。保持原候选顺序、每0.25距离和五个方向搜索、九点足迹、原最大跨越距离/高度、冷却及跳跃/跨步时长。
- 掠夺者精英的同一次击退在伤害与装备连锁结束后，按需收集一次当前活地面阻挡，供原20段、每段0.1的检查复用；最后才提交目标位置。此前死亡/生成的实体已包含在当前集合内，下一次击退重新采集。
- 不朽者精英每个拉扯目标使用实时Map迭代做占位判断，省掉全实体数组复制；每次命中仍重读当前实体。前一个命中可能造成死亡、生成或移动，因此没有跨目标共享旧占位快照。
- 接战缓存命中时直接按顺序比较原名单所含的ID、射程和飞行状态，保留实时存活、武器、模式、目标资格筛选。只在重建时保存比较字段，代替每次filter/map/join构造字符串。队形缓存同理按ID顺序比较；原刷新时间、锚点距离/转角阈值和选位算法保持。

ContactSolver、separation、SpatialHash、steering、S09 melee-approach及World调度没有改变。碰撞仍两遍求解、原每体候选限制及修正距离预算；分离仍保持原候选顺序与12接触限制。不能直接改成只查同平面，否则“检查20个候选”的预算含义变化；也未扩大预算来消除原小幅重叠。300上限、4∶4∶1、模拟频率、伤害/射程/冷却、经济和五图保持。

## 六条审计结论

- **SIM-013**：300只限制活敌，不限制尸体/友军/结构总数。保留尸体1.5秒生命周期，不把总实体截断为300。300活敌+1000尸体对照确认尸体短期保留且按原时刻清理，空间索引仍跳过已死体。
- **SIM-014**：密集碰撞已有空间网格、有限候选、两遍修正和有界位移，保留这些语义。30/300密度及五图中央场景360步精确；当前未找到经验证且不改变行为的求解器新收益。已有小幅重叠如实保留，不以加大修正预算换取不同战斗行为。
- **C03**：同次跨崖搜索复用高度/列表及placement几何参数；保留原候选搜索与每步重试，落点提交重新验证。支持的单层悬崖、原CharTerrain与阻挡/预留/地图修改边界已测。当前五图levels=0限制与失败查询回退明确单列，不新增地形能力。
- **C06**：掠夺者一次击退共享当前阻挡列表；不朽者逐目标重读当前Map。伤害/连锁之后才读占位，原击退概率/RNG、距离、顺序、Boss例外及地形合法性不变；命中后回调局部计时与状态对照通过。
- **C19**：闪烁每个实际单位提交时仍重新计算可用位置；手动转移仍保留预览与提交时原子验证。预览不能替代后续实时占位，未采用陈旧快照优化；S06已有freePosition调用内集合复用继续沿用。实际八单位闪烁与转移封堵/重试精确，无单独新增性能收益。
- **C22**：接战/队形缓存命中省去名单数组及字符串构造；资格、顺序、射程/飞行字段实时比较，原失效阈值/刷新周期保持。死亡、失去武器、架起、模式变换、目标、飞行/射程、重排和锚点变化回归通过。没有按tick共享可能过时的接战名单。
