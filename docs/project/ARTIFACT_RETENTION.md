# 产物保留规则

2026-11-16 用户明确要求：“把旧 Current、V04 和 T01 都删掉，并更新旧保留规则，以后已经结束、可以重新构建的产物都不要保留。”本规则立即生效，覆盖旧文档、旧 AGENTS 记录和历史脚本中的相反保留约定。

- **已结束且可以重新构建的产物全部清理。** 包括基线、离线 HTML、Web 构建、应用／资源 ZIP、检测页、截图、视频、逐帧图、详细日志、追踪、临时测试存档及缓存。任务失败、曾经验收、命名为 Current／正式版／基线，或被历史报告引用，都不是长期保留理由；不以去重、压缩、换目录归档代替删除。
- **只长期保留简要结论、决定和复现代码。** 记录适用版本、实际结果、限制及重建入口即可，不保留可重建的逐文件证据、整套快照或详细运行产物。
- **进行中的工作只保留当前实际使用的产物和必需输入。** 被替代、已停止或已解决的批次及时清理；工作结束时同步清除本批可重建产物。真实运行／部署仍在使用的必要资源不属于已结束产物，不因此中断服务。
- **源码、测试代码、构建工具、锁文件、必要项目文档、Git 版本记录、原始游戏资源、唯一美术源和用户真实存档保留。** 生产数据、账号、聊天记录及其他项目资料不属于本项目产物清理范围。生成产物与原始输入要按引用关系核对，不能仅凭目录名或未跟踪状态删除。
- **旧 Current、V04、T01 不再有保留例外。** 已授权删除的四处旧交付及实际结果见[清理报告](../../reports/qa/disk-cleanup-20261116.md)。以后的已结束可重建产物按本规则直接收尾，不再为“历史基线可能有用”自动延长保留。
- **清理前核对范围，清理后核验结果。** 确认完整绝对路径、目录链接、实际使用者、唯一输入和重建方法；只在已授权项目范围执行。保留简要清理结果，清除执行清单、哈希明细和临时日志。不要为证明可重建而重复生成整套已结束产物。

2026-10-25 的“完成后删除可重建产物”要求继续有效。2026-10-27 的 T01 r33／V04 保留例外，以及旧记录中的 Current 保留、全部原始证据保留、仅压缩不删除等约定，均由本次决定取消。历史报告保留当时结论与日期；其中的生成物路径可能已不存在，需要复现时使用对应代码和资源重建。
