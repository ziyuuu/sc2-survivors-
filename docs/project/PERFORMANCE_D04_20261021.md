## 保留的失败和撤回方案

初期尝试把整个未来阵容的解析与 GPU 准备搬入战斗，出现约1–2秒以上集中长帧，已撤回。只缓存未来文件的候选又漏掉第三关即时奖励的首次模型准备，实际出现约2.6秒资源等待；早期脚本只检查阶段端点，未及时检出中段等待，后续改为逐帧检查并保留原记录。

按用户要求提前确定一份奖励后，初版仍有约1.1–2秒长帧。修复了零实例但仍可见的后续子网格参与首次编译，并分别匹配颜色、接触深度和阴影的实际预热条件；独立预热每次只处理一个子网格。离屏诊断目标使用32像素阴影贴图，正式战场阴影规格不变。秒级集中停顿已降下，但仍保留数次约200–300毫秒等待。

后续诊断中的慢调用在成功日志读取、反射和纹理上传之间迁移，不能把它全部归因为某一张纹理。HTML 图像替代方案既未改善整体帧耗时，也改变了透明贴图像素，撤回。不透明法线的字节纹理曾通过 GPU 像素对照；原生图像解码后直接复制 BGRA／RGBA 的25张贴图也曾逐像素一致，但两者都没有消除实际长帧，全部撤回。最终仍使用原材质加载器和原始图像路径。

早期完整旧版测量遇到其他任务的浏览器与低内存并发，冷轮及失败的热轮均不用于正式性能结论；单独保留环境干扰记录。所有早期沙箱、夹具、选择器、像素比较方法及测试失败继续保留，不回写成通过。

最终R23首次复测在第1关遇D盘空间耗尽，报告写入ENOSPC，原JSON截断保留；这一轮完全排除性能结论，离线未启动。确认无D04进程后，仅清理D04根目录内29个已关闭测试浏览器profile，验证目标和无链接，释放约17GB；原始截图、报告、构建保留。清理后使用未改动R23构建另起Web／离线R24记录，未改标失败。详见final-r23-disk-failure.json与profile-cleanup.json。
