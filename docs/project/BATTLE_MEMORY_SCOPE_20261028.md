中低档同时降低贴图、渲染尺寸与特效，是[已经批准并发布的方案](SITES_QUALITY_IMPLEMENTATION_20261028.md)，不是本轮才提出的功能：中档颜色/发光贴图约半尺寸、上限1024，低档约四分之一、上限512；渲染比例分别为 `min(DPR,1.5)×0.85` 与 `min(DPR,1)×0.70`，并联动精简特效。下节的256/512方案只代表进一步加强低档缩减，不能混写成“目前中低档尚未降低画质”。分辨率降低不会自动释放仍提前加载的模型和贴图，因此两类问题需要分别修复。

## 低档可进一步降低画质的具体方案（未实施）

目前低档对允许处理的颜色/发光贴图按原尺寸的25%缩小，长边上限512；不是所有贴图都小于512。法线、遮罩、透明度、翻页动画等受保护资源仍有较大尺寸。单纯降低WebP品质主要省下载字节，不能有效降低解码后的像素占用。

建议下一步仅调整低档：普通世界模型颜色/发光贴图长边上限256，地形保留512；对法线/粗糙度另做512上限的材料验证。UI、文字、队伍颜色遮罩、危险预警和动画维持，中高档维持。代价是模型近看纹理更软、表面凹凸细节减少；实际节省需生成样本后测量，不能承诺固定总内存降幅。这是待用户选择的视觉取舍，本轮未改变低档资源或新增设置。

## 行业方案检索补充

用户要求参考艾泽拉斯幸存者并扩大方案检索。本轮仅检索与源码核对，没有新增实现或部署。其[游戏入口](https://wow.aethus.pl/)要求WebGPU；直接读取启动源码返回403。公开的[社区重建](https://github.com/OutThisLife/azeroth-survivors-re)明确非原项目，不将其Rust/Bevy或资源策略冒称线上原版实现。未取得同手机实测、原版贴图尺寸或内存，不能根据画面断言它模型更重或毫无稳定性问题。

建议顺序：先分层测量加载峰值与实际驻留；重新评估大贴图KTX2/UASTC；补齐资源引用计数、字节预算和安全淘汰；再收紧英雄/装备/订单依赖、按屏幕覆盖与材质语义分档。此前桌面KTX2小样约四分之一RGBA载荷，文件体积和转码成本较高，不能推为iPhone或整个游戏75%节省。GPU压缩为有损技术，高品质也需原画对照。

标准做法还包括纹理流送、材质通道打包、关闭效果时释放渲染目标、短声音缓冲/长音轨流式、实例化与LOD。项目已有半精度动画图集、实例化、部分LOD/剔除、音频分库及预算，不重复记作新收益。本轮复用中档样本：动画图集14.78MB、PCM32.72MB、GL贴图分配估算559.23MB；口径存在包含与共享关系，不能相加当总RAM。优先纹理路线是目前证据支持的工程判断。

Three的WebGPU迁移需要改写现有自定义材质及后处理，并非替换一个开关；转Worker和进一步gzip也不会自动消除资源驻留。具体来源、排序和边界已补入同页简要JSON报告industryResearch。
