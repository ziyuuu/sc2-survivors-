## 第一批确定的造型

- 普通箱为 SC2 `Crate_01`，高级箱为 `DOM_Crate_00`，使用原网格与原贴图并调整尺寸。取消木纹拱盖、金锁和宝石方案。
- 医疗包使用绿色十字 `Pickup_Medic_RechargeEX3`；弹药使用 `PickupPlasmaRounds`；护甲提取陆战队 `Shield` 骨骼权重对应的盾牌；核弹使用 `NukeFalling` 的弹体。均保留原始纹理与轮廓，不使用通用卡通道具。
- EMP 参照幽灵 EMP 图标和 `EMPMissile` 的蓝白光核。原素材是能量效果，因而用有体积的柔化能量核心表示拾取物；这部分为参考原型重建，不宣称是原版实体手雷。
- 情报为自制军用手册：实体封面、书脊、纸页、护角与封扣。
- 传送门参考 [魔兽世界法师传送门](https://www.wowhead.com/spell=49360/portal-theramore)：竖直椭圆、发光外沿、流动旋涡与地面符文，动画时间跟随游戏时间。
- 翅膀从原生飞龙模型按 Wing/Flap 权重提取网格、UV、翼膜与骨刺；移除甲虫鞘壳，适配现有单位测量尺寸和背部姿态。继承原有飞行规则。

## 第二批设计确认 · 2026-10-21

用户已确认：小屏 UI 应以 PC 版等比缩放。小地图可以整体移到左上，但地图、边框和图标的相对位置、排列顺序与比例保持 PC 版；不能把 PC 右侧竖排按钮改成地图下方横排。其他 HUD 组件按后续明确纠正恢复原布局，不将该原则扩大到士兵栏或底部操作区。

用户明确否定额外的退出／放弃设计和状态面板。当前实现的特殊关深色信息块、挑战中的“撤退返回／放弃挑战”及其规则说明属于助手额外加入，不能因为代码中已存在而视为用户批准。第二批将移除这些设计；不是将面板缩小、收起、换成图标面板或挪到另一处。

玩家应通过游戏表现做判断：横穿是否完成要看成员实际到达地图底边／出口；治疗是否完成要看血条回满；敌人是否清完、道具是否拾取要看场景中的实际变化。缺少可见线索时补足场景表现，不用常驻文字替代游戏引导。传送门的就近进入交互也不能依赖屏幕角落的常驻状态框。此原则适用于后续任务与感染表现，不再沿用“常态状态面板保留目标／进度”的旧提议。

挑战中途不提供额外的退出、撤退或放弃操作，按既有成功、失败或到时条件结束。已确认的成功奖励领取、满包整理和结算后返回流程继续作为完成流程处理；不得把其中的返回入口复用于中途放弃，也不得通过弹窗关闭、键盘或手柄路径遗留同一放弃操作。加载失败的技术恢复与重试单独处理，不作为新增玩法退出选项。

用户已确认毒爆从地图上边缘生成、整体向下穿行，保留平行／斜向／扇形变化和缺口，镜头沿用第二批开始前的逻辑；本批对取景、安全边距、缩放和相机控制器的尝试已全部撤回。60秒、四名成员、五次机会等已确定规则不因本次展示与来弹方向调整改变。

以上为此前设计确认的沿革；第二批已完成，当前实现以最终纠正和第二批记录为准。第一批截图与验证记录保持其历史含义。

## 第二批范围补充：重复文字与商品双层说明 · 2026-10-21

用户明确要求把原审查中的过多／重复文字问题并入此次第二批，不延后到第三批：

- 感染者逐个常驻“净化 0%”及叠加遭遇名称造成遮挡的问题一并清理。净化、治疗、敌我关系等变化以单位外观、动作和既有血条等游戏表现为主，不另建净化状态面板，不把原文字拆成更多漂浮标签。
- 任务栏仅显示真正任务的名称和一句话任务描述；遭遇及特殊关既不显示名称，也不显示说明。使用屏幕右侧黄色文字，不加框体，参照魔兽世界任务插件的轻量追踪排列。清除“待入场”等实现状态、“受击不打断，离开重置”等规则细节及重复遭遇标签；不附加进度数字、倒计时、状态行、规则展开项或面板按钮。一句话描述直接说明玩家要做的事，需要感知的进展由场景反馈承接。
- 商品沿用已有的“简要／详细”两层说明及当前切换交互，不重做一套分层，也不因精简简要文案而删除详细规则。简要层独立概括用途、主要收益和重要代价；详细层保留完整数值、条件、限制和升级差异，避免机械重复整段简要文字。
- 两层都删除“权重重新归一”等实现术语；用实际游戏效果解释。例如骰子的简要用途可表述为“更容易刷出紫色和橙色商品”。详细概率说明必须与实际抽取规则一致，不能把权重增量直接写成概率增加相同百分点。
- 桌面简要卡片无需滚动即可读完，详细内容组织清楚、减少冗余造成的滚动；不能靠缩小到难读字号、截断、隐藏重要代价或删减完整规则通过验收。现有购买、升级、价格和简要／详细切换保持可用。

源码核对：`src/ui/intermission-skin/skin.ts` 已有简略／详情切换；`presentation.ts` 的 `cardPresentation` 未给趣味商品单独生成简要文案，回退到 `CardView.stat`，而 `src/ui/presentation/intermission.ts` 将完整描述传入该字段，名为 `trim` 的函数当前只执行 `gameText`。因此问题是这批商品未正确填充现有两层内容，不是缺少简要／详细功能。`src/render/units/fun-visuals.ts`、`src/ui/hud/random-mission.ts` 与 `src/simulation/fun-shop/state.ts` 分别包含本次点名的感染标签、任务细节和商品技术措辞，实施时连同展示入口一起核对。

任务栏最终约束：任务名称和一句话目标均采用黄色字体，在屏幕右侧按任务顺序纵向排布；名称和描述均为12px，与顶部矿物／瓦斯数字同字号，仅以字重区分。无背景框、边框或卡片容器。窄屏可自然换行，仍只保留这两项语义内容，不通过缩小字号或添加滚动面板挤入更多内容。布局避开现有 HUD 交互与主要操作区域；没有任务时不显示空壳。该文字追踪条与已否定的特殊关状态面板分别按上述范围处理，不恢复后者。
