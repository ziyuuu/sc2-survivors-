## 1. 范围与现状

当前deploy/coze/coze-web-server.mjs只服务GET/HEAD静态文件、runtime-config与health；没有账号、数据库、统计或反馈接口。此前“业务后台暂缓”被用户本次明确要求替换。

新增：一个仅管理员可登录的后台、持续的授权游戏数据采集与分析、游戏内意见入口、玩家数据声明及关闭/删除入口。首版不强迫玩家注册，不增加联网战斗、排行榜、付费服务或自动云存档。

后端承担接收、校验、去重、数据库保存、报表聚合、反馈管理；60Hz战斗与资源渲染仍在前端。

## 2. 独立用户的统计口径

- 同意统计后，使用本域随机生成的浏览器标识和独立会话标识。没有姓名/手机号/账号的情况下，称“独立终端（浏览器）”，不能称准确的自然人数。
- 管理后台区分统计用户、访问会话、战局数量、开局与继续读档；同一终端多标签/多次读档不会新算玩家或新开局。
- 不用设备指纹、IP合并、完整User-Agent、GPU型号或跨站标识强行识别人。
- 换设备、无痕浏览、清理站点数据会得到新终端；多个人共用浏览器也可能合为一个终端。图表旁明确这个口径。
- 同意率与独立终端统计分开；拒绝统计的玩家不被暗中长期追踪。报表只反映授权样本，不能宣称覆盖全部玩家。未授权人数及同意率不通过秘密持久ID采集，首版显示“授权样本规模”，不伪造全站同意率。
- 统计日期统一Asia/Shanghai；服务端记录接收时间，保留客户端事件时间以标记延迟。测试/锁血/必杀样本明确分组并默认排除运营图表。

## 3. 采集哪些数据

| 数据组 | 字段/事件 | 分析用途 |
|---|---|---|
| 授权访问 | 随机终端ID、sessionId、同意版本、首次/最后活跃 | 授权样本DAU/WAU/MAU、新增、回访及留存 |
| 运行环境 | 应用构建ID、资源发行ID、移动/桌面大类、横/竖屏、动作模式 | 版本比较与适配故障；不采集指纹 |
| 资源加载 | 冷/暖准备耗时、网络字节、缓存命中/失败类别、解析/GPU准备耗时 | 老玩家是否反复下载、更新是否真正增量 |
| 战局 | runId、种族、难度、开始/继续/胜利/失败、有效战斗秒数、最高关/无尽轮 | 种族选择、关卡漏斗、失败位置、战斗时长 |
| 成长与构筑 | 本族等级、冻结天赋语义ID/级数、家族/军衔/三型精英/英雄等级、路线攻防等级 | 80级与顶级阵容是否达到困难/地狱15+目标 |
| 卡牌与经济 | 展示/购买/领取的卡ID/品质/层数、资源花费、刷新次数、培养/补员/换兵摘要 | 恶火重复、卡牌价值、构筑与经济节奏 |
| 战斗摘要 | 每关伤害/治疗/回盾/死亡/复生等总量，按家族/英雄/卡来源归类 | 高级兵/精英/英雄实际价值，支援效果对等性 |
| 性能/故障 | 每关P95/P99帧时、长帧计数、单位峰值、模拟欠账增量、限定错误码 | 自然场景性能与版本回归 |
| 用户主动反馈 | 分类、正文、版本/种族/难度/关卡摘要，可选联系方式 | 问题复现、需求与意见管理 |

不自动上传完整存档、屏幕截图、回放、键盘/触摸轨迹、姓名、精确定位、通讯录、账号密码或本地文件。不会因为写了“玩家数据”就允许上传任意整个World对象。反馈首版不带文件上传；需要截图/存档时以后另设明确自愿附件流程。

浏览器ID是可区分访问者的假名化标识，不宣称绝对匿名。应用统计库不持久保存IP；网络基础设施仍会处理请求地址，运维日志另按实际部署配置说明。

## 4. 管理后台

入口`/admin`，必须管理员登录；公开路由不能读取运营表。

1. 总览：今日/7日/30日授权独立终端、会话、战局、活跃战斗时长、新增与回访趋势。
2. 关卡：种族×难度×玩家等级×版本的到达/完成/失败分布；战役和无尽分开；未结束战局显示未完成，不自动归为失败。
3. 平衡：家族、90款精英、18英雄、卡牌的使用率、实际输出/恢复/复生、死亡、搭配与到达关卡。关联不直接当成强弱因果；至少显示样本量。
4. 加载/性能：首访与回访、冷暖缓存、下载字节、进入耗时、帧时与欠账分布；锁血诊断、开发样本单独查看。
5. 反馈：分类/日期/版本筛选，待处理/处理中/已解决/暂不处理，标签、管理员备注、优先级。
6. 导出：按当前筛选导出CSV；联系方式另有权限和显式导出操作，默认报表不附联系方式。导出带指标口径和样本量。

每日图表分钟级刷新足够；前端可30秒轮询已缓存报表，不每次刷新重扫事件表。首版不自动邮件/私信用户；用户未授权联系时只管理站内反馈状态。

## 5. 玩家意见入口

- 标题、暂停和关间提供“反馈”，不占战斗常驻大面板；打开战斗反馈时按现有暂停合同暂停。
- 分类：问题/性能/平衡/建议/其他；正文10—2000字。默认附可见版本与当前种族/难度/关卡摘要，提交前允许关闭这份摘要。
- 统计授权不是提交反馈的前提。仅提交本次正文与明确勾选的摘要；未授权时不绑定持久统计ID。
- 联系方式选填，单独说明仅用于处理反馈；不自动发送邮件。返回反馈编号和本机保存的查看/删除凭据，后台仅存凭据哈希。
- 草稿仅在本机临时保存。失败保留正文并显示“未发送”，成功后显示“已收到”，同一提交ID重试只生成一条。
- 服务端限制频率、长度和大小，参数化入库；反馈显示转义。客户端按钮禁用不是唯一防重复措施。

## 6. 后端与数据边界

Coze原项目接入持久化PostgreSQL。可采用官方集成或已有外部PostgreSQL，通过服务器环境变量连接；不得用发布容器临时JSON/内存当数据库。开发/生产隔离，不在更新时把测试数据覆盖生产数据。

建议独立analytics服务模块、数据库repository、admin界面与前端telemetry客户端；不把World改成业务数据库对象。

最低数据表：`consent_records`、`visitors`、`sessions`、`run_summaries`、`stage_summaries`、`events`、`daily_metrics`、`feedback`、`admin_users`、`admin_sessions`、`admin_audit`。数据库版本独立于战局schema；新增后台不要求将本地存档搬到服务器。

接口：

- `POST /api/telemetry/consent`：明确授权版本与签发上报凭据；拒绝不创建统计访客。
- `POST /api/telemetry/batch`：只接受白名单字段，事件ID去重；最大32事件/64KiB，限制频率和时间跨度。
- `POST /api/privacy/withdraw`：撤回授权，服务器吊销凭据，前端清空未发送队列。
- `POST /api/privacy/delete`：持有本机隐私凭据才可删除对应可关联记录；反馈另按反馈凭据删除。
- `POST /api/feedback`、`GET /api/feedback/:id`：提交/凭据受控查看，未授权统计也可使用。
- `POST /api/admin/login`、`POST /api/admin/logout`、`GET /api/admin/metrics`、受控反馈管理/导出API。

初始管理员由部署方在服务端初始化，不提供公开注册，不内置默认密码。口令只存强密码哈希；会话用Secure/HttpOnly/SameSite Cookie、超时、退出吊销、登录限速与CSRF防护。管理员API同源且不沿用静态资源的`Access-Control-Allow-Origin: *`。数据库凭据、签名密钥及管理员初始化秘密不进入Git或网页。

上报凭据不是可信战斗证明：游戏在客户端运行，数据可能被篡改。后台用于运营/平衡诊断，不宣称防作弊战绩。

## 7. 性能、保存与保留

- 只在加载结束、卡牌交易、关卡结算、战局结束等真实事件点记录；战斗摘要在本机累加，活跃心跳最多每60秒。无逐单位逐帧网络上报。
- 同一事件保存稳定ID，不为继续读档重复创建run_start。网络队列最多256KiB/200条，保留24小时；溢出优先丢低优先级心跳并计数，不无限写盘。
- 网络失败/数据库不可用不影响60Hz模拟、训练、付费事务和存读。诊断记录是非权威旁路，上传不能改变奖励或RNG。
- 停止授权立即停止新采集与队列重试，不清本地游戏存档或资源缓存。离线HTML默认不上报、没有内置公网统计地址；联网后也不追补未授权历史。
- 拟保留：原始事件90天，战局/关卡可关联摘要180天，独立终端去重索引在最后活跃365天后删除；不含终端标识的汇总730天；反馈及选填联系信息180天，管理员安全审计90天。到期任务由后端执行，不依赖游戏网页有人打开。
- 新增终端按保留中的365天去重索引识别，不能宣称准确终生累计用户。汇总保留期间清理标识后不重新识别用户；可关联明细支持用户删除。
- 期限均为拟实施参数，不声称法律统一规定这些天数。正式声明按最终数据库/备份/平台日志配置同步；删除请求还需登记备份覆盖期限，恢复备份后重放删除清单。

## 8. 新增实施阶段

| 阶段 | 工作 | 完成标准 |
|---|---|---|
| B0 | 确认字段、口径、保留期限、声明和管理员入口；确认生产数据库 | 声明与实际字段逐项一致，标清开发/生产 |
| B1 | 数据库、管理员认证、事件/反馈API | 非管理员无数据权限，重复提交一次入库，失败不影响游戏 |
| B2 | 前端授权/关闭/删除、低频采集与反馈 | 未同意零统计上传，拒绝也能游玩/反馈，撤回清队列，读档不重复开局 |
| B3 | 报表、反馈处理、CSV与到期删除 | 已知样本核对UV/留存/关卡与摘要，导出转义，删除与备份策略验证 |
| B4 | Coze原项目增量部署交接 | 保留域名/资源/生产数据；数据库仅必要结构更新；校验真实线上权限与接收 |

修复主线P1—P4可先进行，后台B0—B3独立准备，最终一起纳入发布验证。数据库不可用时管理员报故障、游戏继续；health公开仅报告组件可用性，不泄露用户数、反馈、连接字符串或令牌。

Coze首次部署不要同步诊断明细和管理员测试账号，后续升级不DROP生产表、不清成长/资源缓存。应用与资源仍按固定Git提交增量获取。后台依赖安装/数据库配置在升级指南单列，不能继续宣称新版完全无需安装依赖。Coze账户内发布仍由部署执行方完成。
