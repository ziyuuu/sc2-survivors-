## 舰装剩余工作

### 正式合流，不再另做一套 UI

`src/main.ts` 仍调用默认 `boot()`；`bootstrap.ts` 只有显式传入 `equipmentAccount` 和舰装资源解析器才挂载 UI，`newStarshipRuntime()` 未提供账户时默认不启用舰装。因此，现状比“已经正式接入，只差一个按钮”更具体：**共享实现和原游戏挂载入口都有了，常规发行入口尚未启用和联合验收。**

后续沿 R22 接入原首页“旗舰配装”、小地图原位置“背包”和原关间背包标签，统一账户、图片资源准备、开始／续关／结算回调；使用有真实敌军的正常流程验证。复用当前实现，不重画舰桥、不恢复被取消的额外出征准备页。

最新规则按 R21／R22：战斗中禁止换装；关间允许本次背包内合法属性散件与特殊装备换装、分解；模块／套装仍局外更换。战场丢弃回到地面，销毁不返粉尘。满背包保留地面装备；撤离后的满仓溢出按 R19 直接分解。合成只使用曾真实获得的合法配方。旧“全部只能局外换装”“待入仓”“随机合成未获得配方”等描述已被后续决定覆盖。

## 难度、性能和稳定性仍缺什么

**规则修改已完成，完整平衡尚未完成。** 四档主力／弱兵投放、连续成长、300 在场上限、4∶4∶1 比例、弱兵只给等比矿气、无尽指数平滑已接入。最近又调整普通入门，三族各三种子完整前三关 9/9 完成，不能继续拿较早的普通裸装 0/9 当作当前结果；也不能用 9/9 宣称后十五关、所有难度或真人体验通过。

后续应在完整构筑和功能合流后检查：简单的三族体验、普通完整路线、困难／地狱中后段清怪与资源、不同成型度装备、无尽连续多轮、任务与独立虫潮叠加、撤离收益与失败损失。早期 R2 的蓝装困难虫族有 300 在场／5,925 排队的历史样本；它不是最新版本的重测结果，但说明后段清怪和积压必须验证，不能用保留队列正确代替节奏平衡。

**全内容 60 FPS 尚未达到。** 最新同一密集诊断场景，原生实时 FPS 约 7.38→8.08，冻结画面约 8.10→8.83；约十秒墙钟只推进 1.867 秒战斗。该场景为地狱 18 关、300 活跃敌人及锁血夹具，不能泛化为整局平均 FPS，也不能用早期不同负载的约 15 FPS 与它直接相减。CPU 尾部和 GPU 时间没有证明改善；自适应只调绘制分辨率，无法保证解决 CPU 瓶颈。

仍需收口的具体项：

1. 完整版本的整帧 CPU／GPU 预算和可验证优化；未采用的网格合批、额外剔除、shader 改写或静态阴影缓存仍是候选，不是本次新增必做清单。
2. 三族早期、后期、无尽及首次装备／英雄／事件效果的自然样本，按原约定设备、分辨率与质量测量；重复记录中位数和最差值，保留首十秒和模拟欠账。
3. 导航到可操作菜单、入场与再入场的完整加载体验。历史百秒量级入场和菜单停顿未被最近战斗优化证明解决，需要最终版本复测。
4. 长局、重复换图、上下文丢失恢复、内存峰值和回落；低内存与高刷新设备仍缺最终完整证据。已有局部恢复检查继续有效。
