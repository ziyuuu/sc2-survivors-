# 舰装 UI 接入普通游戏 · 2026-10-16

用户要求：“那你接入ui，两个分支应该是可以同步的吧。”随后要求检查小地图旁的溢出、不对齐和错误贴图，检查其他文字居中／左右对齐，并允许给装备预设取名。本批将现有 R22 舰装窗口接入普通游戏入口，并完成这些界面修正。

## 分支与范围

集成分支 `feat/starship-ui-integration` 从装备分支 `feat/equipment-fx-performance` 的 `736c933` 建立，继承已提交的装备表现、紫色虫卵与优化。UI 及其素材管线作为后续独立提交，便于合并或撤回。装备分支原引用和 main `cb2e2f3` 保持不变；两个分支没有各自复制一套规则。

本批不推送、不合并 main、不替换 Current 或旧命名交付。性能优化方案比较在 UI 接入之后继续；本批不声称关闭全内容 60 FPS 或整体 MVP 验收。

## 实际入口

- `src/main.ts` 调用 `startGame()`。创建空装备账户，粉尘为 0、库存为 0；使用正常敌人波次和战役规则，没有 R22 的无敌人／预赠库存参数。
- 主菜单“旗舰配装”、十二槽配装、仓库、工坊、原作战部署、战场小地图背包和 `I` 热键、原关间背包标签，共用 `World` 的装备账户和现有控制器。
- 战斗背包持有界面暂停租约并清理移动输入。战斗中不允许换装或分解；丢弃接回原地面实体和拾取事件，销毁不返粉尘。关间沿用散件／特殊装备、模块／套装、污染和保护规则。
- 关间背包增加“撤离结算”，调用已有 `extractEquipment()`。结束画面提供“战利品结算”入口，展示入仓、满仓分解和遗失结果，并可整理仓库后返回原首页继续下一局。
- 按用户先前决定，存档接入留到 MVP 收尾。当前账户和战局只保留在本页；刷新或关闭会重置。主菜单明确提示，隐藏不可用的读取／保存／导出操作；不读取、迁移或覆盖原正式存档。
