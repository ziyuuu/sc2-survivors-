# 工业战场画质修复样板 · 2026-10-09

用户要求先修复、实际测试并拿出达到目标观感的可运行结果，再讨论完整修复计划。本轮交付独立工业战场样板，使用真实 World、原始单位模型和动作，提供人族、神族、虫族编队及同场景对照。正式游戏集成与全项目修复计划仍是后续工作。

## 范围与基线

- 在隔离工作树完成，最终继承并保留另一项已完成的 `91ea5c8` 修复；未改写原工作区的其他预览。
- 新增实现全部位于 `preview/sc2-quality-20261009`。最终对 `src`、`tools`、`deploy`、`public` 的 Git 差异为空，原游戏数值、模拟、UI、地图与部署不在本轮改动中。
- 工业甲板、排水格栅、平台厚度及设备摆放属于本样板的场景构图。外墙通过现有障碍物 API 阻挡单位。这不是五张正式战役地图的新版本。
- 9 类普通单位及对应死亡模型的材质来源于 18 个原始 M3 文件；14 张样板贴图来自原 DDS 解码，含 12 张队伍色掩码和 2 张工业地板贴图。原始文件保持原样。

## 已实现的画面修复

1. 从原始 M3 恢复高光颜色、指数、HDR 系数、双发光层、透明度与 UV 动画。Three 的光照计算仍是适配实现，不能据此称为原 SC2 渲染器逐像素复刻。
2. 用原 DDS 的队伍色掩码恢复蓝色己方、红色敌方。雷神原先烘焙为红色的问题在样板中纠正。
3. 修复 GLTF unlit 材质遗漏发光贴图而形成白色面的情况。不朽者的护障依据实际单位身份、原生护障状态及原始开始/结束曲线显示；狂热者死亡使用原纹理与时间轨道消散。
4. 通过同一个样板 renderer 实例的可见对象与实例提交顺序绑定真实单位/尸体身份，不再依赖位置匹配，也未修改正式 renderer 源码。
5. 投影使用原始骨骼姿态；接触阴影复用当前颜色通道的深度，避免另绘一遍全场法线。泛光限制在局部亮部。
6. 使用原始工业面板与法线、原始工业设备/墙沿模型。纠正样板中透明发光墙沿的遮挡和投影，补足平台轮廓与设备层次。
7. 保留原生受击持续时间，将会盖住全身材质的受击染亮改为局部边缘亮光。伤害、生命值、武器事件与战斗时钟不变。

## 可运行文件与操作

- 单文件：`D:/星际/dist/SC2-Quality-Sample-20261009.html`，内置所需资源。已在本机 HTTP 和禁止外部资源连接的 CSP 下验证；内置浏览器协议策略禁止 `file://`，因此未自动验证双击本地文件。
- 本机预览：`http://127.0.0.1:4211/sample.html`。
- 点按或右键地面移动；暂停时缓存样板指令，恢复或逐帧推进时交给原生 World 执行。拖动平移镜头，滚轮缩放，空格开始/暂停，重置还原完整初始状态和镜头。
- 纯画面提供屏幕内退出按钮，也支持 Escape。测试记录默认折叠，提供真实受击、死亡、逐帧推进及短时 GPU 测量。
- “原单位材质/光照”保持本样板构图，切换原单位材质、原光照/后处理路径；它不是对旧生产地图的截图重现。切换前后比较完整 World/Profile 校验值。

构建与检查在仓库根目录执行：

```powershell
node node_modules/typescript/bin/tsc --noEmit -p preview/sc2-quality-20261009/tsconfig.json
node --import tsx preview/sc2-quality-20261009/verify-scenario.mts
node preview/sc2-quality-20261009/stamp.mjs
node preview/sc2-quality-20261009/build.mjs
node preview/sc2-quality-20261009/serve.mjs
```

构建不需要重新解析原始 M3，使用已记录哈希的材质元数据与样板贴图。`prepare-source.mjs` 是本机原始数据提取工具，另需原私有输入及 `.cache/visual-restoration-reader/m3-loader.js`；不作为运行时依赖。

## 最终结果

R15 已通过独立样板 TypeScript 检查。最终 19 份浏览器状态记录及对应截图覆盖三族静态/交战、同场景材质对照、真实受击、护障、死亡、重播和重置，均为页面/模型错误 0、资源待加载 0、墙体边界违规 0。最终桌面为 1280×720 CSS 像素，另测 390×844 与 844×390；两组窄屏的五个顶部操作均在屏内、无横向溢出，竖屏全编队可见，点按移动经过原生指令执行并返回成功。

人族最终版本实际运行至 World 时间 60 秒并进入 reward、自动暂停，随后重新演示和空格暂停成功，重置恢复 32 个初始单位、时间 0、初始镜头及完整 Run 状态。三族交战图均取自真实模拟到 1 秒后的暂停画面。护障测试记录实际命中触发、移动跟随、90 点护障被九次 10 点伤害消耗至 0，以及结束消退；死亡截图分别记录原轨道早期与后期。

原生诊断脚本推进 3601 tick，执行两次移动命令，每 tick 检查实体半径与样板墙体，边界违规 0；原护障曲线和材质轨道插值通过。18 个 M3、14 个 DDS 和 14 个解码 PNG 共 46 项来源哈希匹配。最终汇总重新核验 21 份构建来源文件和 HTML 哈希。没有将上游正式游戏的 1194 项回归误计为本轮执行。

提交前仅清除了 `pose-shadow.ts` 与 `source-materials.ts` 各一个末尾 CRLF 空行，汇总以精确追加该空行后的 SHA-256 证明两者和已测构建来源一致，其余 19 份来源逐字节匹配。保留原构建和截图的实际来源摘要，未重新标记证据。

## 证据与边界

逐版源快照、实际截图、错误记录及测量保留在 `reports/local/sc2-quality-20261009`。每份浏览器 JSON 记录实际 revision、源摘要、硬件、视口、World 状态、异常及测量参数。最终统计见该目录的 `delivery.json`。

早期离线遗漏资源、可变初始快照造成的不完整重置、暂停移动被原生 World 拒绝、墙体穿越及受击全身染亮均保留原失败证据，并在后续版本纠正。早期曾临时修改两个正式 renderer 文件，随后完全还原；最终采用样板实例适配器。

本轮可验证材质、状态驱动特效、交战、输入、布局和独立资源加载。它不关闭自然战役性能、完整 M6/M7、历史 P6-V01、实体设备、长期/低内存、Science Vessel 来源缺口或生产后台验收。玩家对参考图观感的最终判断仍应依据可运行样板和实际截图，不能由自动检查替代。
