# iOS 首关结束与续局自动重载核对

2026-10-28，归属 V06-SAFARI-001。用户报告 Coze 重新部署后可预下载并进入第一关，在奖励页出现前整页自动刷新回加载页；随后继续游戏在35%再次自动刷新。网址为 https://sc-survivors.coze.site 。这是真机用户反馈，代理尚未在原机复现；不是已经证明的内存终止，也不是错误提示或单纯加载停住。

## 已核对

- Apple 说明系统可能因内存压力终止进程，应通过 Jetsam 记录核对终止进程及原因。WebKit 工程师在2024年针对 iOS 17 的回复说明网页进程存在受整机内存压力影响的软限制；该回复不能用来给 iPhone 17 Pro / iOS 26.7.1 指定固定上限。
- 本地 `src/app/asset-readiness.ts:91` 在进入模型准备前设进度35%。救援、任务、公共特效准备及模型文件准备可发生在下一次模型进度回调之前；35%不是文件定位，也不表示已完成35%的内存分配。
- `prepareSnapshotAssets` 从 `raceModels` 开始，包含本族全套普通、精英、英雄和固定敌人；新开局从 `openingPreloadModels` 开始。直接执行当前函数计数：人族15对54、虫族10对32、神族14对40。数字是开局默认无天赋与读档基础清单的模型键数，不含后续实际身份补充、死亡/变形依赖；神族读档还额外加入carrier.1。不能按此比例推导内存。
- 读档末尾无条件调用 `prepareEndlessAssets`，会准备无尽首领、建筑与地图模板。它发生在模型进度回调之后，因此不能单独解释35%处刷新；属于读档整体额外开销。
- 首关奖励出现前涉及关末状态、检查点快照/序列化、UI更新及后台调度。尚未取得终止前采样，不能认定是下一关加载或保存造成。
- 本地源码搜索未发现 `src` 中直接调用 location.reload/replace/assign 的路径；未验证线上启动器及其版本，不能据此排除线上主动刷新。
