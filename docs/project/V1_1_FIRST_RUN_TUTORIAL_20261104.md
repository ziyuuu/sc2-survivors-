## 镜头、字幕与声音分镜

以下为审稿台本。人族副官与神族执行官的拟配对白和字幕逐字对应。**虫族全程只用腺体震动声，虫后的中文指令只显示为字幕。** 虫后头像与新字幕出现时播放一声短促的震动音，同一条字幕停留期间只播一次。目标指示与字幕同时出现。建议保留普通战场的角度与缩放，仅在安全时向可见目标轻移约半秒，停留约一秒，再平稳回到小队。玩家一旦下达移动指令，立即把镜头交还给玩家。敌人正要攻击或目标在远处时，使用边缘方向标或小地图脉冲，引导玩家自己靠近。镜头移动只影响观看。

## 一次首局怎样教完

| 时机 | 顾问引导玩家做什么 | 完成依据 |
| --- | --- | --- |
| 第一关就绪 | 在本族通讯中选「接受教学」或「跳过教程」。建议等待决定时暂停战斗计时，选择后回到同一战场 | 玩家明确选择。载入完成、经过几秒或点到战场都不算接受 |
| 第一次移动 | 指向附近一个可达位置，按当前控制方式移动整队 | 小队实际到达。桌面与手机采用玩家已有的控制方式 |
| 敌方工蜂出现 | 标出**敌方工蜂**，带队进入射程，让部队自动攻击。随后指向地上的矿物和瓦斯，让小队靠近收集 | 先核对同一只工蜂被击杀，再核对其资源被拾取。被动收入和救出己方工人是其他事件 |
| 首批援兵抵达 | 到本族增援落点，保护载体、清除威胁，守到士兵出来并加入部队。开工扣费与落点接应是同一份订单的前后两步 | 以实际乘员入队推进。只走到落点还没接到兵时继续保护。错过或未救下时等下一批正常援兵 |
| 首次正常关间 | 在「基地建设」查看本族生产或科技，选一项可行的发展。到「战备补给」，比较现有矿气、卡牌收益与下一批补员开销，作一次购买或留钱的决定，再返回前线 | 用真实购买、生产安排或玩家主动出发确认操作。保留原报价和余额，买不起时也能继续 |
| **第一次真正拾取装备**，可早于第三关 | 顾问指出刚刚进入本局背包的那一件。若还在战斗，先认物品，来到下一个允许整备的关间再教穿戴。若首件属于局外模块，先记下它，等撤离后装 | 在当前阶段允许时，玩家亲手选择刚拾取的可用散件，装入匹配槽位，看到物品或属性改变。已提前完成的动作直接承认 |
| **第三关战役首领被击杀** | 对接受且仍在教学的首局，这只首领一次掉落 **2–3 件**。顾问指向战利品，玩家移动拾取。此前还没取得装备时，这里同时触发首件教学 | 以第三关原有首领的真实死亡与物品入包为准。普通精英、击伤首领或等到关末都不会兑现这批装备 |
| 第三关后的正常关间 | 把这批装备分成「现在能装」与「回旗舰再装」。先装可用散件，随后引导点现有「撤离」。若散件已经穿好，直接引导撤离 | 玩家主动撤离，成功结算后，本局带回的那件模块实际进入仓库。选择「返回前线」仍可正常游戏，在后续合法关间仍可撤离 |
| 撤离结算后的旗舰 | 从仓库找到同一件刚带回的模块，进入本族舰装界面，选匹配的槽位，完成装备或替换。顾问收束通讯 | 核对同一物品 ID 已装在本族旗舰上，显示出该模块的实际作用。记为完成，之后的新出征安静开始 |

步骤随事件推进。玩家如果先拾取装备、先接到援兵或自行打开背包，回到对应环节时只提示剩下的操作。第三关首领奖励独立于当时正在显示的台词。击杀后仍需完成该关，再从正常关间撤离。

## 第三关的两件用途

用户指定的是**第三关原有的战役首领**。在源码 `43ef159` 上，用种子 17 读取简单和普通难度的排程，两者的第三关都在第 30 战斗秒安排一只跳虫首领。现行自然首领装备结算成功时生成一件。1.1 在符合首局教学条件时，把**这笔首领装备掉落的总数**改成 2–3 件。其余独立奖励沿用各自的来源和回执。[战役排程](../../src/data/campaign18.ts) · [现行掉落与拾取](../../src/simulation/starship/drops.ts)

建议至少匹配两种实际用途。一件是本族、无污染、可在关间装上的属性散件。另一件是本族、可在撤离后装到旗舰的模块。这样即使只掉两件，也能教完两次操作。若本次定为三件，第三件从该阶段合适的现有装备中取。具体模板、品质分布与第三件的出现比例留在掉落调校时确定。白色散件与白色后勤模块可作核验样本。[装备目录](../../src/simulation/starship/catalog.ts) · [穿戴资格](../../src/simulation/starship/inventory.ts)

奖励在首领死亡时一次确定数量、模板和唯一物品身份，进入真实地面掉落、拾取、背包与带出流程。重放死亡事件或恢复检查点只兑现同一份奖励。跳过发生在首领死亡前，这只首领走正常掉落。奖励已经产生后跳过，已出现在地面、背包或舰上的物品照常处理。背包已满时保留正常拾取条件，玩家腾出空间后可取。

## 首局识别与永久跳过

1. **先认新玩家，再写首个检查点。** 启动时成功读取本地存档，主档与两份备份均为空，才记录「待首次入关」。这个资格随账户保存，玩家先看设置、选种族或重新打开菜单都能保留。已有档案、已撤离但无续局、导入档、从备份恢复的老玩家都走正常入口。存储打不开或档案损坏时先走既有恢复流程。
2. **在关卡里询问。** 将待邀请状态绑定到第一次正式出征。第一关资源就绪、首个检查点成功后才弹出通讯。等待选择时关闭再恢复，回到同一个待选决定。已接受则按同一出征和已完成动作继续。
3. **任一步跳过都是整套结束。** 从第一句通讯到最后的舰装操作，每个环节都能点「跳过教程」。立即撤下通讯、目标指示和排队提示，让玩家继续当前操作。将「已跳过」保存到账户，刷新、恢复当前关、撤离、重开和换种族都不再邀请。自然完成同样关闭后续教程。
4. **账户决定与本局物品分别记录。** 结束意愿随统一档案持久化，恢复较早的战斗检查点时优先读取账户终态。各步进度、第三关首领奖励回执及带回的物品跟随对应出征。战中重打遵循已有检查点，钱包、装备和回执随同一版本恢复。写入失败沿用原来的失败保护与重试。
5. **提前结束首局的衔接建议。** 提前撤离且带回了可装备物品时，可直接教当次能完成的舰装操作。战败或主动放弃这次出征后，关闭该出征的剩余提示和未触发奖励。完成或跳过后的新一局采用正常战役规则。

现有入口会先读取账户，开始新局后还会写初始检查点。因此只在首关现场检查「现在有没有存档」会漏掉真正的新玩家。[读取与续局](../../src/app/run-session.ts) · [开始新局与初始保存](../../src/app/bootstrap.ts) · [备份与失败保护](D05_CHECKPOINT_20261023.md)

## 实施时的界面与验收

涉及的页面是首关战场、关间基地建设与战备补给、本局背包、撤离结算和旗舰配装。新增交互集中在**本族通讯头像、一句当前指令、目标指示、接受与跳过**。采购、装备和撤离沿用原有控件。具体摆位按桌面、手机横屏和竖屏确认，保留移动区、战场视野和关键按钮。静音时仍可完成每一步。[UI 规范](UI_RULES.md)

实施验收至少覆盖三族各一次从空档入关到穿好舰装的完整流程，另查有档玩家、空账户先退回菜单、备份恢复、任一步跳过后重开，以及首领奖励前后读档。在第三关固定输入下核对同批 2 件和 3 件两种情况、已提前取得首件、背包满及已跳过的普通掉落。验收看实际移动、击杀、拾取、乘员、钱包、装备槽和真实入仓结果。
