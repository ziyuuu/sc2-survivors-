# iOS 分关加载与资源回收

## 实际行为

- 正常新局在确定种族、难度与地图种子时生成 18 行内容清单，成功提交新局后随检查点保存。每行记录自然事件机会与类别抽数、任务和遭遇类型、特殊门票与传送门候选顺序、英雄名单及每个本族兵种的精英变体。无尽用相同种子与轮号推导当轮数据。缺少清单的旧版 schema 26 战局沿用原规则。保存的清单须与战局种子、种族、难度及规则版本一致。
- 步数、射击和后台加载均不消费内容抽数。实际入场仍检查安全窗口、队伍、剩余时间、任务占用、特殊关间隔和次数。酒馆及诱饵按已购等级生效。玩家仍选择是否领奖、进入或购买，合法的手动精英变体、装备指定身份、已经承诺的订单与奖励继续有效。
- 加载器依据当关清单、实际阵容、存档中的在途部队和奖励准备资源。读档扫描跳过未来 18 关的配置。没有首领、情报、虫后或竞技场英雄来源的关卡，关末货架候选等到选购后再准备；确认跳过选购时不为未买商品展开全部精英变体。公共战场拾取物复用同一个道具包，部分音效和同族特效仍共用整组。专用资源按玩法依赖和玩家分支准备，实际进入特殊地图时才建立地图实例。
- 关间优先提交保存并完成当关必需准备。压缩版把原先点击后最多约 5 秒的可选预热移交后台。独占准备通道内，新关登记必要模型后回收闲置批次；存活单位、待发成员、必要形态、死亡表现及近期复用模型保留。退出特殊地图时销毁该地图的视图和雾层。任务建筑和死亡模板在没有活动实例且近期关卡不用时释放。磁盘资源包可供重新进入时读取。

## 内存监控

压缩入口在页面可见时，每两秒采样已保留的 HTTP Blob、模型动画图集、已绑定的分档贴图和解码 PCM。压缩贴图按实际 mip 载荷计量，其他贴图按像素估算。这些分项和采样峰值可在现有诊断报告的 `resourceMemory` 中查看。采样间隙的峰值、浏览器自身、驱动、未纳入的渲染目标等支出仍需从进程或真机工具观察。

近期资源模式使用 256 MiB 游戏预算，其他模式使用 512 MiB。达到高水位后暂停启动普通推测性预载，回落至预算的 80% 后恢复；开战所需加载与进行中的结算继续。预算属于本次工程选择。在 Windows 实测中另按当前测试浏览器的 PID 汇总专用字节和工作集。

iOS 的终止条件受设备及系统当时的内存压力影响。Safari 网页没有可依赖的实时进程总余量或 Jetsam 阈值。Web Inspector 的 Memory 时间线能观察被检查页面，设备 Jetsam 报告能核查实际终止原因。[WebKit 内存时间线](https://webkit.org/blog/6425/memory-debugging-with-web-inspector/) · [Apple 终止报告](https://developer.apple.com/documentation/xcode/identifying-high-memory-use-with-jetsam-event-reports)
