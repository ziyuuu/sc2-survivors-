## 2. 创建环境

按官方[Codex Cloud环境说明](https://learn.chatgpt.com/docs/environments/cloud-environments)，在Codex中选择`Work in → Cloud → Select environment → Create environment`，或在`Settings → Codex Cloud → Environments`创建。

选择本仓库与`main`，需要时由用户完成GitHub连接。环境先保持私有。让环境设置任务读取本交接，检查Node22、Git LFS、Python3和浏览器测试依赖；报告安装与验证结果后再发布环境。不把“保存配置”当作“环境已发布”。

环境需要依赖下载与本仓库LFS资源访问。使用官方包管理器网络设置；遇到具体资源主机失败时只补实际必需域名，不关闭网络保护。秘密值只放环境秘密配置，不写入仓库或提示词。

现有工具可以按固定提交和散列分批下载发布资源，不必拉取全部原素材：

```sh
npm ci
node tools/fetch-coze-resources.mjs --commit <交接40位提交> --group all --out deploy/coze/public
node deploy/coze/start-coze.mjs
```

启动器默认监听3000；这可验证当前已构建Web游戏和资源，不等于重新构建源代码。分组、断点和校验规则见`COZE_GITHUB_DEPLOY.md`；已校验文件复用，不重新下载。若资源访问需认证，使用环境秘密，不将令牌打印。

## 3. 云端源码构建门槛

不能仅执行`npm ci`就宣布完整构建环境就绪：

- `public/assets/`、`src/assets/runtime.generated.ts`与`reports/local/`是忽略文件，本地存在不代表云端克隆后存在。
- `predev`调用`ensure-assets.mjs`，它可能继续本地素材准备，并在部分缺失时返回零退出码；必须另核验必需资源完整，不能把零退出码当作资源就绪。
- 完整`npm run build`/`build:web`依赖素材准备、动作裁剪、可达资源报告；其中原始CASC获取与若干提取脚本使用PowerShell、本地源缓存或本地转换工具。云端应先核对实际依赖，不假装Linux已验证。
- 首个云端环境任务应通过固定发行清单恢复当前已核验的运行资源及生成元数据，再验证源码类型检查、规则测试与Web构建。此恢复仅改变工程准备流程，禁止以缺素材为由换模型、删能力或关闭卡牌。
- 若确需原素材重新转换，留在本地处理后提交对应派生资源；不上传本机凭证、浏览器档案、私人截图或整块磁盘。

只有在干净云端工作区实际跑通命令、必需资源散列校验及浏览器启动后，才记录“云端开发环境已迁移完成”。
