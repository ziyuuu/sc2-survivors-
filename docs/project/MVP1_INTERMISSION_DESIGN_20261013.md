# MVP 1 三族关间原型设计

最新范围：已另行完成[独立对接模块](MVP1_BUILDING_CONNECTION_20261013.md)，按[缺项定案](MVP1_BUILDING_RULES_DECISIONS_20261013.md)统一三族UI与逻辑。用户明确要求不挂载主游戏。下文保留R17样例阶段的设计、待定项和验证边界，不能用旧“待定”覆盖后续确认。

日期：2026-10-13。阶段：设计与交互评审，正式规则尚未实施。范围依据 [MVP收尾计划](MVP_COMPLETION_CONTRACT_20261013.md) 的建筑包及用户本次“先设计、尽量沿用原流程、先做三族关间原型”的要求。

本轮交付一份设计和可点选的三族UI原型。它用于确认信息位置、布置方式和连续关间流程；选择会更新原型内存中的设施、解锁及布置，但不执行真实钱包、生产、存档或战斗。下一轮真实规则独立包才执行这些功能，不能把本轮样例选项当作建筑包完成。后续用户修订：移除方向栏下方的路线小字，在设施调整内查看构建树，加入下一关评审循环；三族专属科技和攻防研究改为图标UI，三个标签页切换后仍可继续点击。

## 1 沿用现有流程

保留关间“基地建设 → 战备补给 → 返回前线”三步，不新增强制发展步骤。保留发展方向、最多三张购买卡、每窗口选择一次、刷新、跳过前往补给，以及设施调整、强化和休整入口。“武器与防护研究”与设施调整内的“科技”标签内容相同，移除主页面和整备菜单的重复研究入口，统一从“设施调整 → 科技”查看。布置可在建设或补给时打开，不要求每关重新配置。

选中方向后看本线路项目；卡面查看详情，购买按钮独立；完成一次发展选择后进入补给。设施配置通过现有“设施调整”打开，关闭后回到原关间步骤和方向。补给沿用原三卡结构及流程，本轮不重做补给规则。

原型外部提供种族与场景切换、重置和范围说明，均不进入正式UI。“返回前线”展示当前布置的出征预览；点击“下一关 · 进入整备”跳过战斗，进入下一关关间，保留已选设施、解锁和已应用布置，重置新窗口选择和刷新计数。可连续评审第1至18关，第18关结束后通过“重新评审”重开，不访问正式存档。

## 2 视觉基准与布局

复用当前 `intermission-skin` 的三族背景、米白卡片标题带、立绘、矿气图标、按钮、弹窗、字号及响应式规则；不新造主题、不换字体、不生成替代原画。没有正式水晶素材时以文字与现有设施符号说明用途，不交付假素材。

| 视觉角色 | 沿用值或来源 |
|---|---|
| 画面底色 | `#08121b`，现有整备皮肤 |
| 面板 | `#14212bea` |
| 主文字 | `#f3f1e8` |
| 次文字 | `#acb9bd` |
| 分隔 | `#f1eeda42` |
| 动作强调 | 沿用现有 `--action-fill`、`--action-gold` |
| 字体 | Microsoft YaHei UI／Microsoft YaHei／Segoe UI，系统回退 |

保留现有横屏三卡、窄屏单列滚动和弹窗内容滚动。主页面不再显示方向栏下的路线小字。设施调整采用始终保留的“布置／科技／构建树”三个标签页，切换不丢尚未应用的布置；标签栏在内容滚动时保持可见。构建树只读，集中展示建筑前置和分层兵种顺序。用户进一步确认按截图上方原兵种小图标作为基准：三族兵种、建筑前置、专属科技、科技前置、攻防系统与武器／防护节点统一为28像素，不再带大图标框；横竖屏保持相同尺寸。依照本次标注，科技／构建树名称缩至14像素、状态和前置文字12像素、分区标题16像素；名称与状态优先放在同一行，极窄的攻防节点允许自然换行，专属科技的单位前置另占一行。辅助符号与装饰标记更小。设施标题不再附加“布置只影响后续生产”，构建树不显示基础建筑开局说明；非基础建筑前置使用图标路线。攻防节点只显示图标、名称、等级和研究状态，删除“基础研究”“阶段6／12”等常驻小字；已有资格判断保留，条件仅留在节点提示中。科技与树使用同一呈现模块，研究选择仍在原发展卡入口进行。按钮和选中状态同时用文字、边框表达，键盘焦点保持可见。

布置页删除“每组／每座最多两种、轮流生产／孵化、付费订单保持原进度”说明、重复的输出箭头摘要、付费订单脚注与水晶用途脚注。三族均只保留设施名称、必要的方向／数量、单位选择按钮和训练启停；最多两种及草稿交互沿用现有逻辑，订单语义仍在设计文档说明，不在布置页重复展示。

```text
第N关完成 · 种族       基地建设                 矿／气
基地建设  ──  战备补给  ──  返回前线
设施调整                 强化一览   休整
原三方向按钮
原购买卡1            原购买卡2            原购买卡3
刷新及实际费用                             前往补给
```

设计复核：不把关间做成新管理后台，不拆成“选建筑—选升级—选生产—确认”四个强制页面。路线放入现有设施调整内的可选构建树视图，布置保留原弹窗，其他位置沿用现有结构。

## 3 三族最小改动

### 人族

方向继续为兵营、重工、星港。候选只属于本线路，前置仅提示。构建树按 [人族规格](TERRAN_DEVELOPMENT_FLOW_SPEC_20261012.md) 显示陆战队员→死神→劫掠者、恶火→坦克→雷神、医疗运输机→科学船→维京→女妖；已解锁、下一层和未解锁状态在树内区分。

布置仍按整条线路最多两种输出轮流生产，现有建筑数量、单位选择和训练启停继续使用。没有解锁的单位显示原因，不允许选择。不能为了选星港先弹出购买兵营的卡片。

### 虫族

保留原三个方向按钮及发展卡框，不新做逐座发展页面。针对单座的进化卡在详情中明确目标孵化场；同类候选需要选择目标时，在原详情内容里增加孵化场选择，不新增强制流程步骤。目标资格变化后必须重新检查，不凭旧卡给全体进化。

布置内容从三条共享产线改为逐座孵化场。每座一行：编号、开放方向、输出选择和启停。移除常驻的轮流顺序与已付费任务提示。选择兵种使用原单位按钮；已选两种后其他按钮禁用并通过按钮提示“最多两种，先取消一项”。单座双方向开放后可地空混选，其他孵化场不跟随改变。

```text
孵化场1  地面          [跳虫 已选] [爆虫 已选] [其他可选]
                                            训练开启
孵化场2  地面＋天空    [刺蛇 已选] [飞龙 已选] [其他可选]
                                            训练开启
```

天空入口继续检查至少一次完成的全局地面进化。缺少前置只说明如何完成；第二次进化保留双方向。路线、作用范围及价格未定部分按 [虫族规格](ZERG_DEVELOPMENT_FLOW_SPEC_20261012.md) 标明，不把原型样例当作已定案。

### 神族

方向仍为传送门、机械台、星门。沿 [神族规格](PROTOSS_DEVELOPMENT_FLOW_SPEC_20261012.md) 展示顺序，前置提示不占购买卡。传送门方向加入“建造折跃水晶 ×2”单张卡；详情明确一次两座、仅生产狂热者／使徒，不绕过解锁。

布置弹窗在传送门组附近追加折跃水晶组，复用原生产单位按钮。价格未定时显示“费用待定”和“预览建造”；点击仅在原型内存加入两座水晶用途样例，不执行付款。两座输出共享还是逐座独立暂不落成正式规则，因此该组的输出修改仍禁用。跨关保留这组样例，便于体验建造后的布置位置。

## 4 刷新 失败与页面往返

刷新费用统一显示已有水晶（矿物）图标和数字，不再常驻“免费 · 建设剩余1次”或“矿”等文字说明。人族、神族建设窗口首次显示图标＋0，使用后显示图标＋50，再按50／90／130递增。天赋免费与共享付费计数的完整规则仍以人族规格为准。虫族沿用当前样例费用，以相同图标和数字显示，不自动套用人族基础免费。无障碍标签保留费用含义。

原型中的刷新仅切换评审卡组；不实现新的随机抽卡、折扣或天赋计算。钱包是固定样例，不在原型内模拟付款。发展选择更新样例状态，下一关展示相应后续选项；补给选择记录本窗口已选状态。未定价的进化或水晶操作明确使用“预览”按钮，不能将原型可点击当作正式价格或前置判定已获批准。最终独立包必须按正式交易执行并验证失败分支。

前置不足、资源不足、满两种输出、待定报价均提供就地原因。缺少前置的空卡区使用大图标、名称与未完成状态：人族和神族显示实际所需建筑；虫族天空显示至少一座孵化场完成地面进化的要求。提供“前往对应方向”按钮，仅切换现有发展方向，不在当前线路放入跨线购买卡。不要用跨线卡片补空白，也不要只用颜色区分。布置修改先在弹窗暂存；三个标签页共用同一草稿和底部“取消／应用布置”。切换标签保留草稿，“应用布置”确认，“取消／关闭／Escape”关闭整个设施窗口并丢弃未应用修改。标签切换使用键盘左右键，科技与构建树是同窗口视图，不再打开会丢失标签栏的另一弹窗。

## 5 独立包实施前集中决定

下表为建议，不是已获批准的新规则。UI样例可以先评审，依赖这些答案的真实规则实施须先定案。

| 未定项 | 建议起点 | 影响 |
|---|---|---|
| 虫族初级跳虫／爆虫 | 开局保留跳虫，爆虫单独解锁；同级表示无额外顺序 | 不自动送两个物种 |
| 虫族平级后续物种 | 各自解锁，不互斥；进入下一层只检查对应前层进度 | 需定义层级完成判定 |
| 新孵化场第一次选天空 | 全局已完成地面进化后允许 | 保留防速飞龙门槛，减少重复进化 |
| 虫族共享边界 | 方向开放逐座，兵种科技全局共享；本座仍检查方向 | 避免五座重复买同种解锁 |
| 虫族初级奖励 | 方向进化开放生产资格，不额外送身体 | 不改生产付费与席位 |
| 虫族进化费用与刷新 | 给出完整报价表后集中确认；本轮不填新价格 | 不用样例钱包掩盖经济未定 |
| 神族高阶圣堂武士 | 追猎者／哨兵任一解锁即可 | 同级支线不会迫使玩家两项全买 |
| 水晶输出 | 两座作为独立组，共享狂热者／使徒两输出，沿用原轮流规则 | UI只增加一组，减少逐座操作 |
| 水晶与传送门关系 | 传送门仍可生产前两种，水晶补充生产容量 | 不撤销既有合法生产选择 |
| 水晶费用与上限 | 独立成对价格与独立成对上限待确认 | 不把传送门单座费用硬套给水晶 |
| 成对建造天赋 | 支付与免费判定按一对，双建额外交付一对并另检查上限／付款 | 防止原生两座自动再次翻倍 |

既有雷神、雷兽、航母第10关生产限制暂保留。建造、事件修复、舰装获得设施须共享同一初始化与交易入口；付费订单保留原参与设施、类型、付款和进度，新配置只影响后续任务。后续最小接口约定统一由建筑包实现，不在这份UI原型里复制生产规则。

## 6 本轮交付与验证范围

原型入口源码：`preview/building-workbench/`。本轮为其中的UI评审入口，成品放 `dist/mvp1-intermission-design-20261013/`，截图和检查放 `reports/local/mvp1-intermission-design-20261013/`。它复用正式UI组件、数据与现有素材；`review-flow.ts` 只推进UI评审内存状态，不承担正式资格、交易、订单或生产计算，后续不能当作另一套正式业务实现使用。

检查项目：主页面无路线小字；三族科技与攻防使用图标节点、状态与阶段提示，两视图一致；三个标签页切换及滚动后始终可见、保留同一布置草稿，取消与Escape关闭整个窗口；发展选择后的设施及解锁能保留到下一关；双方向孵化场和两输出跨关保留；水晶样例可预览建造并跨关查看；新窗口刷新重置；第18关结束不产生第19关；桌面与窄屏布局、键盘操作正常。

本轮结束后先集中评审最小UI变化及第5节未定语义。下一轮交付共享正式规则的真实建筑独立包，再早期验证小规模“真实扣款—建造—生产交付”主游戏接入。不能把本轮静态卡组、样例水晶或页面选择当作真实生产、存档兼容、战斗平衡、MVP1关闭或最终60FPS验收。
