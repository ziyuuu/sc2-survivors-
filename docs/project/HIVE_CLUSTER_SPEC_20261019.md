# 消灭虫巢群：完整编码规格 R2

日期：2026-10-19。MVP 包 2。状态：READY（推荐编码基线；未实现、未运行验收）。依据：[趣味原稿](RANDOM_EVENTS_ITEMS_CONCEPT_20261009.md)、[公共调度](ESCORT_WORKERS_SPEC_20261019.md)、[最新掉落规则](LOOT_ELITES_20261019.md)。

本规格保持原稿的 2—4 座巢、每 6 秒生产、每 20 秒增产至初始两倍、约普通蟑螂 8 倍生命与护甲 2，以及“守军真实击杀收益；最新用户追加每座虫巢掉落当前精英档装备，仍无全拆结算奖品”。精确增长公式、选址、接取和队列策略为本轮推荐初值，不冒充用户逐项确认或平衡验收。上一任务的信号延迟与坚守属性不自动套用本任务。

## 1. 玩家流程

地图出现一组 2—4 座可攻击虫巢，小地图分别标记。每座独立生产普通虫群，出兵后主动寻找我方作战。玩家可以立即拆巢减少来源，也可以留巢获取守军资源，但留得越久，单位时间出兵越多。

第一次有效伤害命中任一任务巢，或正式队伍到达任一巢外沿 6 单位内，自动接取整组任务。只杀其产兵不算接取。所有巢从生成时就开始生产，不等待玩家接取。拆掉全部巢即成功，不要求清除已出场守军，没有额外领奖操作或任务奖金。

## 2. 公共调度与生命周期

- 只在战役第 4—18 关生成，使用唯一 activeTask 槽、每关 10 秒宽限、每 15 秒 15% 检查、结束后 30 秒 GCD。待接取也占槽，无尽零生成、不继承。
- 允许已完成后同关再次随机出现。不要求农民、生产设施或精英奖励资格，不预留奖励身份。
- offered 未接取进入下一普通关时失效；active 已接取可跨普通关保留。关间、暂停、特殊关挂起冻结生命状态、生产及成长时钟。
- 未接取也可被自动武器、范围伤害击中；首次实际正伤害先标记接取再处理死亡，远程一次摧毁全组也能正常成功。免疫／零伤害不接取；玩家归属召唤物的有效伤害可接取。
- 靠近接取要求控制点与至少一名活正式战斗队员均在同一活巢的外沿 6 单位内且地面通路连通，不允许隔崖触发。临时协战或子机单独靠近不接取。
- 无限时失败，也不因一座巢被拆或玩家离开失败；任务目标只有拆光。正式小队全灭仍按整局失败处理。
- 战役结束、撤离、失败：取消未完成任务；第 18 关末先处理本步真实死亡与完成，再取消其余任务。终态只释放一次任务槽并进入一次 GCD；无尽不继续计时。

## 3. 生成与空间

| 参数 | 推荐初值／算法 |
| --- | --- |
| 数量 | 2、3、4 等概率，生成时固定 |
| 中心 | 距控制点真实可行走路径 12—20 单位 |
| 巢间中心距离 | 8—12 单位，组内每座至少与另一座满足该距离 |
| 分布范围 | 所有巢中心距组中心不超过 12 单位 |
| 碰撞半径 | 2.4 世界单位，复用现有扩张巢身体基准；表现按模型校验，不重复乘单位缩放 |
| 合法性 | 每座可地面接近并有可攻击位置、可出兵出口；建筑之间保留可通行路径 |
| 尝试 | 最多 32 组完整候选，整组成功后原子生成，否则本次不生成、不占槽、不触发 GCD |

不与主巢、扩张巢、地形／建筑碰撞或当前身体重叠，不堵死出生区、关卡必经路与主巢入口。整组落点不得要求改变五图地形。候选按稳定顺序、共享种子抽取；数量、基础产量和落点生成后固定，表现重建不重抽。

虫巢为独立 taskHive Body：敌对、地面、Armored／Biological／Structure，无移动、普通攻击、探测、主动技能或默认自然回血。所有合法对地普攻、技能、持续和范围伤害按正常战斗规则作用；无结构资格的技能不得强行命中。不是正式主巢、地狱扩张巢或随机精英。

## 4. 巢生命与战斗接入

- 每座满血 `maxHp = 8 * referenceRoachHp`，护甲固定 2，无护盾。referenceRoachHp 为生成当时难度／关卡／进度、density=1、regular 普通蟑螂经过现有成长计算后的最大生命。不是精英／Boss 蟑螂，也不是弱兵身体。
- 抽取无副作用的敌人属性计算器供创建器与本任务共用；不能为了查询生命先创建一只蟑螂再删除，消耗实体 ID、随机数或产生事件。
- 生成后巢 HP 上限与护甲固定，跨关不回满或重算。20 秒成长仅改变产量，不改变巢生命、护甲、体积或已出场敌人的属性。
- 玩家半自动部队按原索敌选择合法敌对建筑；不强制所有部队放弃正在攻击的敌人，不增加单兵操控。须验证现有整队移动能让玩家实际选择拆巢顺序。
- 巢加入 Body 查询、空间哈希、碰撞、弹体追踪、范围技能目标、视线及原结构受击／死亡事件。不能只显示模型，却无法被部分真实武器攻击。
- 结构被击毁计一次普通结构击杀统计，但不伪装移动兵、精英或 Boss，不触发限定这些身份的击杀／卡牌奖励；结构允许的普通战斗触发依真实目标资格执行。

## 5. 每巢生产与成长

每座巢独立抽一次 baseCount ∈ {3,4,5}，整数等概率。每座 ageTicks 从实体实际生成起算，活着且普通战场有效模拟时每步加 1；1200 步即 20 秒。每批到期数量为：

`count = min(2 * baseCount, baseCount + floor(ageTicks / 1200))`

即基础 3 的巢在 20／40／60 秒升为 4／5／6；基础 5 的巢在 20／40／60／80／100 秒升为 6／7／8／9／10，封顶后不继续涨。每次生产读取到期时年龄并冻结批次，不在排队中扩大。

- 第一批在生成后 360 个有效步（6 秒）到期，此后每 360 步一次；没有额外开场守军。正常同步情况下 t=6／12／18 各出 baseCount，t=24 首次使用加 1 产量。
- 每个批次在到期时读取当前关普通非空波的兵种模板，取最近已调度普通波，尚未调度则取本关首个普通非空波；仅普通兵，不复制 Boss、随机精英、主巢技能或整波预算。
- 对模板基础 types 顺序循环取兵，每巢有独立递增 typeCursor，跨批连续，避免每批重复截取开头导致后段兵种永不出现。类型序列不应用主波的 4∶4∶1 扩容；任务产量是实际身体数，主波自身配比保持。
- 每批固定当前难度、关卡、进度的普通兵快照，density=1、regular，使用真实敌人创建／成长规则，guardOrigin=true。不用 weak companion 的资源倍率或主波预算归一系数；不额外产生精英。
- 不硬编码必须是某一种怪物，随当前批次已开放普通兵种变化。跨关的新批使用新强度，旧身体和已到期批次保留其出生／到期快照。
- 每座有 1—2 个出口，位于巢碰撞体外的合法可占用点，距外沿 0.5—2 单位；按实际兵种半径、飞行资格、地形、现有身体检查。不能从巢内部穿墙、叠身体或全地图四边刷怪。
- 出场单位按正常敌方寻敌／移动／攻击规则作战，不把它们永远拴在巢边，也不因玩家离开停止生产。

## 6. 容量与拆巢时序

共用现有 300 移动敌人上限和 Boss 预留。静态任务巢按既有结构统计方式不占移动兵槽，但固定最多 4 座；不得把生产的移动兵排除出计数。任务额外产兵不扣原主波或独立随机精英预算。

- 每巢最多一个 pendingBatch，每批最多 10 名；总待入场最多 40 名，不缓存漏过的每个 6 秒周期。
- 正常批次放完后，从本批到期点计算下次 360 步；若阻塞至下个到期点或之后，放完后从实际放完时刻重新等待 360 步。尚未放完时不创建第二批，不在恢复空位后补发历史积压。
- 每有效步整个任务最多投放 8 名，以巢 ID 稳定循环轮转，每巢每轮至多 1 名；游标持久保留，避免同 ID 巢长期抢占全部空位。主波及 Boss 优先使用合法容量，任务使用余量。
- 队列堵塞不冻结 ageTicks，年龄成长仍封顶；但已经到期的 pendingBatch 数量不变。出口堵塞与容量不足同样处理，不瞬移出兵到远处。
- 每步顺序：伤害／死亡清理→接取／全巢死亡完成判定→存活巢年龄和到期批次→投放。死亡巢本步不能再生产；只取消它尚未入场的成员，其他巢照常。
- 拆巢不杀死已经出场的守军，也不重新归属或加强它们。最后一巢死亡即 succeeded，取消余队，已出场守军继续正常战斗与真实掉落，无须清场。

## 7. 收益与经济边界

最新用户确认：每座真正被击毁的虫巢追加一次当前版本精英装备掉落，复用完整策略（保底层＋概率基础层）。规则见[任务装备收益契约](TASK_EQUIPMENT_REWARDS_20261019.md)。本条覆盖 R1 的巢零装备规则。

守军资源收益来自真正生成并被击杀的守军，复用 `DROPS.guard` 与现有实际击杀掉落管线，不能改用 `DROPS.ambient`。本地当前基础表为：

| 普通守军 | 基础矿／气（尚未应用全局地面气体修正） |
| --- | --- |
| 跳虫 | 1／0 |
| 蟑螂 | 2／1 |
| 毒爆 | 1／1 |
| 破坏者 | 3／2 |
| 刺蛇 | 2／1 |
| 表中没有的合法普通兵 | 沿现有回退 1／0，不凭任务编造额外价值 |

- 此表是代码现状引用，实施读取共享表，不复制价格。地面气体 +50% 及合法资源加成只由原掉落／拾取路径处理一次，保持现有小数或累计规则，不在任务层再乘或提前取整。
- 正常普通敌人的装备掉落资格保持，不新增保证掉装备、精英装备保底或额外任务掉落。所有非 Boss 不掉卡；守军与巢都不能借旧分支掉卡。
- 每座巢掉一次精英档装备；巢本身无矿气、卡牌、精英／英雄身份、设施或全任务结算奖励。不得误用现有 expansionProfile.reward 或扩张巢的 tryRewardDrop。
- 消失、排队取消、关卡结束清理不视为击杀；只有真实原掉落条件满足时才掉资源。毒爆自爆按现有击杀归属与掉落规则，不为本任务造击杀收据。
- 无额外留巢时间上限、收益衰减或封顶：留巢换资源是该任务本意，同时占用唯一任务槽并持续产生战斗压力。暂停／关间不能产兵刷收益。
- 初始总产量 6—20 名／6 秒，完全成长后 12—40 名／6 秒；这是无遮挡且有容量的理论范围，不是运行验证。实施需记录实际击杀、拾取和压力曲线，再判断参数是否需调整。

## 8. 跨关、清理与隔离

状态 offered→active→succeeded；offered→expired；任何非终态→cancelled。没有单独任务计时失败。首次受伤和最后一巢死亡可在同一步由 offered 直接完成。

- 已接取跨普通关保留各巢 ID／位置／HP／年龄／baseCount／下次生产／pendingBatch／typeCursor，保留已出场任务敌人的真实状态与出生快照；破坏过的巢绝不重建。
- 普通战役沿现有同图关卡机制继续；特殊地图挂起时整个任务留在原地图，恢复后继续，不把巢搬进特殊战场。若未来出现不保留普通地图的转换，必须补迁移契约后再开放该模式，不能假定 prepareStage 自动支持。
- 未接取跨关失效时移除残巢，清空未入场批次，已入场敌人在继续中的普通战场仍保持普通敌人；整局退出则随 World 正常清理。残巢回收不播放“真实击杀并发奖”的逻辑。
- 不放进 `World.expansionHives` 或 `World.hive`：不增加 hiveFrenzy、不成为地狱关末必须拆除的扩张巢、不驱动第 18 关胜利或主巢技能、不提供该集合附带的探测。
- 任务不改变普通关胜负条件；留巢跨关不能导致“扩张虫巢尚未清除”的失败。真实主巢与扩张巢原规则保持。
- 重复死亡／UI 回调／WebGL 重建不重复成功、GCD 或掉落。只以模拟状态判断，渲染不发兵、不改变 RNG。

## 9. 数据结构与真实代码接点

以下均为拟新增接口，并非当前已经接通：

```ts
type HiveClusterTask = {
 id:string; sourceStage:number;
 state:'offered'|'active'|'succeeded'|'expired'|'cancelled';
 accepted:boolean; hiveIds:number[]; enemyIds:number[];
 roundRobinCursor:number; endedReceipt:string|null;
};
type TaskHiveState = {
 id:number; taskId:string; baseCount:3|4|5;
 ageTicks:number; nextBatchTick:number; typeCursor:number;
 pendingBatch:TaskHiveBatch|null; deathProcessed:boolean;
};
```

Body 只保存一份实际 HP／maxHp／armor／位置；TaskHiveState 关联同一个 ID。TaskHiveBatch 保存 dueAgeTicks、源关卡／进度／density、成员及剩余索引、合法出口；所有随机抽取属于模拟共享随机源。死亡巢从存活 Body 集合移除，任务保留已处理 ID／进度，防止重复统计；enemyIds 随真实敌人回收移除，不能长期无限积累历史 ID。

已核对的接点与必需改动：

- `src/data/hives.ts` 当前扩张巢 profile 自带生命、甲、出兵和 reward；仅借鉴组织方式，不直接套其规则。
- `src/simulation/world.ts` 的 addUnit／enemyStamp、releaseHiveBatch／hiveSpawnPoint：复用或抽出创建和合法出口能力，增加任务源；后两者当前为私有，不声称已有可调用的任务 API。
- `World.hit` 当前扩张巢死亡会 drop、tryRewardDrop、删除集合并提示亢奋减少；新增独立 taskHive 死亡分支，明确仅任务巢精英档装备掉落与停止生产。
- `World.body`、哈希重建、contacts、所有结构候选查询需包括 taskHiveBodies。`combat/expedition-heroes.ts` 等有显式枚举主巢／扩张巢的路径，改为共享合法敌对结构枚举，逐一验证射线、范围与地面技能。
- `World.hiveFrenzy`、tickDetection、endStage、主巢控制器继续只读原结构来源；不因通用目标枚举加入任务结构而扩大这些身份专属规则。
- `src/data/economy.ts` 的 DROPS.guard 与 World 真实死亡分支复用；`src/data/enemy-tuning.ts` 与 addUnit 中的普通敌人成长抽取纯查询，避免查询即生成。
- prepareStage／nextStage 的集合、弹体与敌人清理需纳入已接取任务保留；新的任务控制器统一拥有生产计时、终态与 GCD。
- 渲染及小地图接通模型 `model.hive`、原结构动作／死亡资源与独立任务标记；资源就绪检查保证所需源资源可用。

运行内快照覆盖任务、结构、队列与游标；WebGL 恢复只重建表现，不重置生产或回放掉落。正式存档继续按已约定延期。

## 10. 表现与提示

任务出现提示“发现虫巢群：摧毁虫巢可阻止增援，击杀守军获取资源”。HUD 显示“已摧毁 1/3”，小地图仅标记仍活的巢，选中／靠近显示每座 HP、当前产量和下次出兵进度。明确“每座虫巢可掉精英档装备；全部清除无额外结算奖励”。

每次实际入场触发出口／囊体动画，排队未入场不能假播已产兵；成长达到 20 秒整数档时可提示产量变化，不额外放大碰撞体或叠无关光效。死亡即时停止生产，播放可用原结构死亡效果；残骸仅表现、不再阻路或接受伤害。自动失效清理与真实拆毁事件分开。
