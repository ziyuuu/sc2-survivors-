# D01：保持当前敌人投放时序 · 2026-10-21

用户在核对极端场景的来源后明确决定：“保持现状吧”。D01 作为决策任务完成，结论为保留当前投放规则，不实施分帧补兵。

保留敌人上限 300、4∶4∶1、原队列与跨轮积压、投放优先级、出生时序和重试规则；swarm 现有每步最多 8 只的限制保持。不会删除积压、截断队列或延后出生来降低压力。S06 已完成的查询优化继续保留。

## 决策依据与证据边界

- 原“满员清场后一步补 176 只”来自人为制造满员积压，再通过脚本清零敌人 HP 的压力实验。旧复核已经注明 synthetic HP clearance，不能当作正常战斗发生过的清场事件。见[旧复核矩阵](../../reports/local/performance-audit-review-20261019/matrix-final.json)及[原审计说明](../../reports/local/performance-audit-review-20261019/全项目性能审计与问题总表.md)。
- S06 后续将 176 条待出生记录直接放入测试队列，衡量出生和固定步的局部 CPU 成本。这证明查询优化有效，不能证明正常对局会触发相同峰值。见[测试构造](../../tools/performance-s06-cases.mjs)、[浏览器构造](../../tools/performance-s06-runtime.ts)及[S06 测量](PERFORMANCE_S06_20261020.md)。此前对 D01 的说明未先交代人工构造边界，现予以明确。
- B03 一条无锁血、简单难度、人族 bio、合法白装开局的规则运行，覆盖 18 关及 12 轮无尽；151200 个固定步逐步统计的敌人峰值为 124，未达到 300。该单一路线不证明所有难度和配装都不会满员，也不证明只有锁血才能形成积压。见[运行记录](../../reports/local/performance-b03-20261019/natural-2/report.json)与[逐步统计脚本](../../tools/performance-b03-natural.mts)。
- A01 已否定“无尽无限加速”和“一步补任意多个逾期 Boss”的旧推断，不能据此改变投放政策。

目前没有正常无锁血对局复现该极端清场并造成集中补兵卡顿的证据，不追加针对人工极端场景的时序优化。仅当正常无锁血对局出现可复现、可归因的集中补兵卡顿证据时，才重新评估 D01。V01–V04 的既有验收范围保持，不新增专项压力测试。
