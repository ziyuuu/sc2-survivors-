## 下一步：建筑交接后推进舰装

既定顺序保持 **1 → 3 → 2 → 6 → 7B → 8**。建筑已经实施，所以近期主要新增开发是舰装；先用已有证据完成建筑交接，只补查真实缺口。

1. **完成MVP 1当前新局功能交接。** 将三族前置／解锁、付款与刷新、逐座孵化场、水晶组、草稿提交、旧订单保留和真实生产交付逐项对应到当前代码与已有记录。确认购买及后续设施赠予共用 `grantFacility`，保留唯一生产调度器。输出“已验证、后续集成复验、最终收尾”三类清单；有具体缺口才补实现或测试。建筑当前新局范围可供舰装接入，不将其扩大为整个建筑包最终验收。
2. **把舰装最新定案整理为可执行输入。** 保留12槽、4非属性＋4进攻＋4防御、三族隔离及已确认品质／套装规则。只有明确允许的套装可混色，其余上下位替代按最高有效档；装备只在局外装卸，关间也不换装。对尚未确认的强度、掉率、局外交易价格、身份映射和撤离／失联细节列出带推荐值与影响的集中决策表，只在依赖该项的批次前定案，不重新评审已确认规则，也不把原型价格当成批准数值。
3. **先做共享真实规则与最小接入。** 正式装备数据、唯一物品位置、合法装卸、属性／套装计算及一次性收益由可复用业务模块承担；独立入口和主游戏导入同一份代码，沙盒状态隔离。先以一件已确认进攻装备验证“局外装上→新局真实主武器变化→局外卸下→下一新局恢复”，覆盖同槽替换、跨族拒绝、污染拒绝与物品不复制。涉及设施的能力调用建筑同一入口；不以面板数字或演示动画代替实际效果。
4. **分批完成MVP 3既定范围。** 在上述最小接入通过后补齐已列白绿蓝紫橙内容、关键能力、套装、掉落拾取、背包／仓库、撤离／失联、清洗及稿内交易。保持局外配装规则，验证重复操作不重复发单位、刷新、弹药或收益；未定规则先定案再接入。完成“局外配装—出征—获得装备—按已定规则结束—局外处理—再次出征”的真实循环后，进入趣味内容正式接入。

用户在[建筑规则定案](MVP1_BUILDING_RULES_DECISIONS_20261013.md#存档延期)明确要求“MVP收尾前都不考虑存档”。继续遵守：近期交接与舰装最小接入按新局和隔离状态验证，不提前增加旧档转换或存档专项作为开工条件。运行状态及交易身份必须真实；保存、恢复、会话结束与损失的一致性放在后续MVP收尾统一落实，不能永久豁免，也不默默写入现有版本宣称兼容。
