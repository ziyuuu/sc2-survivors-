# 开屏预热与加载优化 · 2026-10-12

用户确认继续以锚点为镜头跟随中心，保留现有自动取景逻辑；本轮优化加载，并确认“调色盘”指着色器编译／材质预热。基线为相机控制交付后的 `4163bc2`。证据位于 `reports/local/loading-20261012`。

## 镜头说明

镜头生产代码不改。默认固定 50°；自动模式根据实际身体边界、锚点、附近可见目标和 HUD 遮挡寻找可容纳的视图。默认偏好下，没有次要目标时从 45°／110% 开始寻找，通常拥挤视图逐步升至 60°／60%。角度候选为 2.5° 一档，扩展约 0.6 秒，收紧先等待 1.5 秒再平滑过渡约 1.2 秒。单位数量增加但仍容纳得下时，不强制再拉远。滚轮、捏合和手动角度／缩放会切回固定模式；横竖屏偏好独立。抵达范围上限后镜头也不会继续改变。锚点远离队伍时保留既有取景边界，不能据用户接受跟随规则宣称所有主队始终可见。

## 加载修改

设置页的角度／缩放显示保存的基准偏好，不是自动模式的瞬时输出；打开设置暂停后，自动取景冻结。这与自动模式实际改变俯仰并不矛盾。本轮不修改镜头行为或设置控件。

- 开屏仍优先完成菜单。菜单开始显示时后台准备三族都会遇到的跳虫本体、死亡及源材质，完成正式 HDR 目标预热；不为未选种族加载整套军队。正式战局入口等待同一个任务再继续，复用已准备模型；可选预热失败不会阻止菜单，正式入口重新检查必要资源。
- 相同不可变源纹理复用解码结果；每个材质获得独立 Texture 包装，保留颜色空间、UV 包裹、过滤参数和原始材质状态。相同源图片由 Three Source／GPU 纹理缓存复用，失败项允许重试；立方体六面顺序属于键的一部分。
- 原先着色器自定义键包含 GLB 哈希和材质编号，导致代码相同的源表面不能共享程序。现在精确登记本项目生成的颜色与深度 GLSL、材质类型、UV 布局和实例模式；不使用近似哈希，不合并不同代码。Three 自身仍负责基础着色器和渲染配置变体。贴图、每实体材质曲线、骨骼、颜色和生命状态数据保持独立。
- 实际 HDR 目标预热仍触及每个待准备网格，以最多 8 个网格为一组提交，减少场景遍历和阴影重复工作。颜色预编译使用与正式游戏相同的线性 HDR 目标，启动编译后立即恢复目标，再异步等待；避免额外编译直出画布的 ACES／sRGB 变体。各组只提交主场景到真实半浮点缓冲区，接触阴影／Bloom／输出链在最终照明帧运行一次；最终照明帧统一等待全部 GPU 工作结束，成功且上下文有效后才记录准备完成；不再逐网格或逐组往返等待 GPU。

没有删减原模型／动画／贴图／光照／特效，不降低画质，不缩小已选种族预加载名单。不改模拟、输入、存档格式、地图生成或后端。Run26／Profile6／地图配方3保留，原 881 资源记录／863 文件不变。这里只优化加载，不是此前延期的整体 FPS／质量档阶段。

## 证据范围

早期 `baseline-r1`、`candidate-r1`、`candidate-r2` 采用原生新局菜单和随机地图，分别记录约 127.5／118.3／97.0 秒入口墙钟；这些是探索记录，不能单独作为严格配对提速结论。`candidate-r3` 加入固定种子和真实 GPU 标识，保留对应实际版本；后续开屏预热构建另编号。不得把早期截图／耗时重标为最终版本。

固定种子 529、1280×720／DPR1、AMD 集显／Chrome ANGLE D3D11、新建浏览器上下文的配对记录：基线入口 121987.6ms，最终 r7 入口 93765.9ms，缩短 23.13%；从导航到准备好为 125790／97924ms，因此并非只把等待转移到菜单。菜单可操作为 3047.1／2340.3ms。单次本地配对仅说明该条件下的墙钟差异，不是全设备承诺。最终 Web 标识 `8c91b5d6512dc439fcaaefea6c11288b029b5a3ea85850d13652e46559792d7d`。

开屏方案 r4 的直出分组预热为 101.5 秒；r5 每组重复完整后处理为 139.3 秒，因更慢而放弃；r6 分组 HDR 为 114.9 秒；r7 再统一编译目标为 93.8 秒。所有候选、截图和失败保留实际构建身份。
