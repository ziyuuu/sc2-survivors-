# 双生虫群与 SC2 控制台：实施及验证

本轮批准来源：[实施稿](TWIN_SWARM_SC2_HUD_20260928.md)。承接 main 中尚未提交的交战、分级虫海、60秒无尽、Web资源分离成果，一起交付；没有清理磁盘、添加旧开发档兼容或修改未批准的平衡数值。

## 已落实

- 玩家战斗单位五类基础属性统一加强15%，原生护盾同步；英雄旧加强仍在，所属截击机只继承一次。技能、治疗、射程和价格不借此改动。更新属性保留实际伤损。
- 狂热者接敌停靠与攻击距离一致，移动目标及时重选接触位置；不增加射程、不允许穿墙。
- 普通/精英跳虫两身体一名额、共享培养及精英身份；五/七名额对应十/十四只。每对单只死亡后900固定步补员，整对死亡取消；堵塞等待，幸存者不回血。换兵五对只产生五份继承，所有十个旧身体退役且无击杀奖励。
- 虫后距己方落地载体6内自动注卵，45秒独立冷却，每舱一次，最多两个零付款普通名额；按实际剩余容量结算，输血不变。第一只出舱死亡、第二只仍在舱内时继续保留已付款名额，不能被注卵占用。
- 当前战局 schema10 保存配对、缺员时钟、交付关联、注卵冷却与收据。暂停/关间不推进，读档不回血、不重放结算。整对阵亡的空槽记录保留至重建该名额，供界面区别于从未填满的空位。
- 常驻 SC2 式部队控制台：小地图、头像网格、只读详情和原技能；桌面十列四行、手机七列两行分页。精英紫徽章、英雄橙徽章，双生各自血条、2/2或1/2及倒计时，原生盾蓝条和受击/破盾反馈。查看头像不产生移动或施法。
- 静态应用与散列资源分离，部署工具按固定提交分组/断点获取并验证散列。业务后台与管理员统计按约定延期。

## 内容诊断与自然实战分开

三个诊断采用原地图、真实World固定步、公开合法操作控制器，**同时开启玩家锁血和必杀**；不送钱、不删敌、不强制结束关卡。三族均完成18关和无尽前五轮，实际模拟时间2100秒，六个战役Boss、主巢目标、换场和购物被走到。此项只证明内容/流程可达，不证明自然平衡或帧率。数据在`reports/local/twin-diagnostic/summary-{bio,swarm,shield}.json`，每份档案都带诊断来源。

同控制器、种子7、零天赋人族生化自然尝试：

| 难度 | 辅助 | 结果 |
|---|---|---|
| 简单 | 无 | 完成17关，第18关败北，总战斗1734.85秒；友军身体峰值20 |
| 普通 | 无 | 完成2关，第3关败北，总战斗163.72秒；友军身体峰值5 |

自然结果在`reports/local/twin-natural-easy`及`twin-natural-normal`。这是自动操作方案的结果，不是人工通关率；也不能写成“简单/普通通关平衡已通过”。没有继续擅自加伤、减敌或给予隐藏奖励。这些战役记录先于“第一只出舱即死”的容量边界补丁；该补丁另有通过的专项和全量回归。

## 后期导入中查实的种子问题

首次用UI导入合法种子7的第16关档案时，被菜单固定种子89241误拒绝。已取消把菜单种子当作地图兼容条件，继续严格核对档内两份种子一致、规则/地图/难度/天赋一致；恢复RNG及配置来自档内，再导出仍保留7。预览不改变当前战局，不增加旧档兼容。687项回归含这个场景。首次失败记录保留在`reports/local/twin-perf-late`，重测另存`reports/local/twin-perf-late-retry`。

42身体压力夹具两次未找到全部合法位置，未取得性能结果；扩大半径后发现偏移中心可能落在悬崖，已改用经过通行核验的中心重新布置。保留失败并单独重跑，不修改游戏中的出生或碰撞规则。
