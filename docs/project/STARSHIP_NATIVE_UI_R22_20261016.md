# R22 舰装 UI：复用原游戏的首页、战场与关间

2026-10-16。用户要求移除额外舰桥和舰装出征准备页，用原首页的“旗舰配装”替换“天赋”；战场必须是真实地图、没有敌人、存在可拾取的装备；关间沿用原页面并加入背包标签。最后一次入口位置修正明确为替换小地图原“天赋”按钮，不新增位置。

## 当前入口与实现

- [运行说明](../../preview/starship-native-ui-20261016-r22/README.md)，[本地预览](http://127.0.0.1:4421)。此预览依赖项目已有运行资源与舰装素材。
- `src/ui/starship/native.ts` 负责共享装备窗口的原菜单／战场覆盖层和原关间页内挂载，接入真实 World 宿主、输入清理、暂停租约与原生进入／续关回调。
- `src/app/bootstrap.ts` 接受显式舰装资源解析器；具备 UI 挂载能力时，HUD 才替换首页／小地图入口并增加关间背包服务。未提供该挂载能力的既有入口继续保留原菜单。
- 原首页、种族／难度与作战部署、BattleRenderer、地图、队伍移动、装备落地／拾取、建设／补给选择及下一关流程均复用生产代码。没有复制模拟首页、地图或关间页面。
- 预览仅通过显式参数关闭波次和敌人系统，使用实际战役地形；初始库存、地面掉落和“进入关间”是标明用途的验证夹具。关间按钮调用真实 `World.endStage()`，不直接改写 phase。
- 原来的舰桥／出征准备页从舰装窗口移除；历史 page 参数映射回旗舰配装，避免旧调用跳入空页面。
- 小地图原第四个天赋控件替换成背包，原 CSS 位置未改动。`I` 打开／关闭背包，保留 `B` 的原生用途。

## 规则与图像

沿用 R21 的合法换装、丢弃、销毁、分解和合成资格。战场背包持有界面暂停租约并清理输入，禁止换装；丢弃立即执行并接回原落地事件，物品身份和品质不变。销毁不返粉尘。关间沿用真实属性散件／特殊装备换装与分解；模块／套装和既有保护规则不变。

装备图使用统一正方形容器，并按实际可见图案范围归一缩放、居中。`tools/measure-starship-art.py` 只读取原图片，记录 495 个装备图键、618 个运行／详情图的尺寸与 alpha 边界；`art-metrics.ts` 生成 CSS 参数，将图案最长可见边统一到容器的 88%。舰船、封面与品牌图片不套用装备缩放。原图片字节不修改，不重新生成图片。

正常清单图为 64×64，窄屏为 58×58；槽位、详情和操作动画各自使用一致的专用容器规格。统一的是同一使用场景内的图案规格，保持原图长宽比，不把全部图强行拉成正方形。

实际关间挂载发现并修复两项集成问题：原游戏单位详情样式污染装备比较表；从背包切到休整再返回会留下已关闭的背包路由。修正限定在舰装样式与相关关间导航中；有对应浏览器失败记录和导航回归。
