## 开屏与后台准备

`BackgroundPreparation` 为可选准备和正式入场共用一条串行通道。开屏普通预算从 navigation 起算 15 秒，20 秒停止开屏新任务；任务提前完成可提前开放菜单。预算结束不等待正在进行的可选任务。同步解析、纹理上传和驱动编译不能强制抢占，因此这不是所有设备上的硬性页面可交互时间保证。

优先准备通用跳虫及死亡、当前种族或已选英雄、已知存档地图、公共效果与掉落材质，再准备当前选择的模型。菜单种族、英雄、存档预览以及关间已有部队、下一关敌人和当前补给选项改变优先队列；不会新建选关玩法或预先启动游戏。选择变化丢弃未开始的旧任务，已完成的公共工作继续复用。

隐藏页面不开始可选任务；用户输入后让出 250 ms，菜单帧耗时超过 24 ms 时暂停开始新任务。可选模型入口数上限 24，菜单在首次正式加载前可以回收不再需要的旧入口，包括网格、独立纹理包装、骨骼数据纹理和不再被使用的共享解码引用。入口数不是材质、子形态、总内存或正式部队数量上限。地图仅按已知选择准备，不批量预载五张地图。

原有图片/立方纹理解码复用、精确 GLSL 缓存与实际 half-float HDR 编译保持。公共资源按任务拆分，新增公共网格分组 4，部队 HDR 首绘沿用分组 8。后台 GPU 工作以 fence 异步完成；正式入场最后完整光照和后处理首绘仍等待 GPU 完成。可选/正式入口通道中的单位不再额外重复做一次 1×1 首绘，均以随后必做的实际 HDR 首绘完成就绪校验；战斗中原有即时增援路径保持。临时预热期间保留可见画布，避免相机或临时场景泄露到菜单/关间。

正式入场先接管通道、等待当前可选任务，再检查当前请求的完整资源。成功解码不等于可入场，模型/依赖/材质/首绘/地图/存档校验仍须完成。可选失败保持菜单可用，正式缺失有错误和重试。取消后的旧任务与替换请求串行，不允许旧请求发布新请求的就绪状态。后台和入场准备不调用原生部队到达通知或改变世界暂停状态；战斗中原有增援加载语义保留。

## 运镜与设置

固定和自动的默认值、算法及原有输入语义保持，默认仍为固定 50° / 100%。新增“运镜”模式使用原生 anchor，角度范围 40–60°，缩放范围 60–160%；无自由旋转、额外摇晃或游戏规则改变。

运镜每 0.2 秒评估构图。紧凑安静、行军、交战、分散或巨型单位分别使用不同角度和距离偏好，再交由现有主部队、附近对象和真实 HUD 遮挡候选检查扩大视野。紧急扩大约 0.7 秒，移动/交战常规过渡约 1.4 秒；稳定约 2 秒后使用约 2 秒收近。数值是指数过渡的设计时标，不代表所有变化都精确在该时刻停止。小于约 4% 缩放或 1° 角度的目标变化忽略，暂停和玩家决策冻结动态评估；减少动态效果时直接到达目标。

设置相机组按“模式 → 当前实际输出 → 已保存手动偏好 → 重置”组织。实际角度和缩放独立显示，不再把手动基准当作自动输出。手动滑块、滚轮或双指接管运镜时，从当前实际输出保留另一维度并进入固定模式；角度仍遵守原有 2.5° 手动档位。横屏和竖屏独立保存，重置仍为固定 50° / 100%。
