# SC2 UI 设计基线 · 2026-10-05

用户在 R7 小地图边框修订后确认「好的。记住这轮的设计理念」，并补充「非移动版本不需要左下的摇杆」。本文记录这轮已确认的视觉方向及该补充，作为以后 UI 工作的延续依据。R7 是视觉参考；R8 仅补正桌面／移动输入展示。

## 整体风格与封面

- 继续参考《星际争霸 II》本体，保留三族气质、金属面板、切角和克制的种族色，不大幅更换主题。
- 人族、神族、虫族使用与背景渐变融合的角色立绘，避免以战场模型代替封面。每族保留多个封面、轮换与淡入；当前原型每族三张，共九张。
- 通过字体层级、头像、图标、色彩、生命／护盾、冷却遮罩及反馈表达信息。界面文案短而像游戏，去掉「席位」「三种型号」等开发／策划语言；长规则和具体参数由用户请求后展示。价格、选择结果和必要决策信息保持明确。
- 动效保留封面融合、页面衔接、选择反馈和底栏折叠等，控制强度，支持关闭及减少动态偏好。

## 战场与底栏

- 优先保留战场可见面积，战场区只展示地图、部队与必要操作；不放教程式说明、策划提示、运输说明或奖励提示浮层。
- 主地图使用 R6 的薄金属内框、细纹和切角护片，不恢复厚蓝边、尺规刻度或多层发光描线。
- 左上小地图使用 R7 的 SC2 人族 HUD 外壳方向：钢灰装甲、倒角、凹陷内沿、非对称护角和少量铆钉／指示灯。缩小后的细节应简化，不挤压屏幕内容或阻挡输入。
- 底栏固定为两行：一行部队头像、一行指令；可折叠，并通过分页保留部队与英雄入口。折叠和旋转不能丢失操作可达性。
- **桌面／非移动版本不展示左下摇杆**，包括缩窄的桌面窗口。移动横屏和移动竖屏保留摇杆。正式实现按平台／输入场景区分；静态原型提供明确版本选择，避免只用窗口宽度推断。

## 菜单与内容

- 局外天赋按「种族 → 方向 → 完整天赋树」逐级进入，每个方向能看清节点分布、前置连线和详情，避免上下遮挡。
- 难度、地图和强化商店保持紧凑、清晰的选择层级，修复重叠、裁切和显示同步错误；商店、晋升、生产和招募沿用简短游戏文案。
- 本轮原型不新增独立「首领奖励」页，也不凭空增加功能、奖励或玩法。该原型页面的移除不代表删除正式游戏已经批准的首领掉落规则。
- 横屏、竖屏都必须保持菜单衔接、阅读和控件可达，不以一版的缩放截图替代另一版布局。

## 范围与追溯

本轮为独立静态交互原型及设计记忆，不修改正式游戏、战斗参数、模型、存档、已批准 P3-A 规则或既有验收状态；不构成清理、提交、推送或部署指令。需要后续运行时落地时，应沿用此视觉基线并按当时明确授权实施。

## 关间卡片的最新用户约束 · 2026-10-05

- 兵种需通过画面识别，用符合星际背景与各自特征的立绘作为主要画面；精英突出自己的装甲、武器、甲壳、利爪、灵能或攻击特点。
- 有几个战士就展示几个，人数增加时不能缩小单体；通过队形和前后层次展开。跳虫按每对两只展示，晋升也表达实际对应战士。
- R10 是落实这些要求的本地矢量立绘稿，尚未获用户确认最终画风；不替代此前已批准的整体 UI 方向，也不构成运行时落地授权。范围与验证见 `SC2_INTERMISSION_CARDS_20261005.md`。
