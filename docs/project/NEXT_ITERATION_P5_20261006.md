# P5 管理后台、授权统计与反馈 · 本地实现合同

2026-10-06。用户先要求继续 P4 后续工作，并选择“先收尾 P4，再推进 P5”。本轮已完成 P4-D/E 本地工程收尾，再实现 P5/B1—B3 与 B4 本地交接包。没有扩大到 P6 全部发行验收，也没有上线采集。

## 已实现范围

- 同源 Node API、持久 PostgreSQL repository、14张业务/辅助表、独立数据库迁移。生产使用 `pg`，本地用文件持久化 PGlite 验证真实 SQL、事务、重启和删除。不是临时 JSON 业务数据库。
- 默认关闭；明确同意后创建本域随机统计ID。独立会话、稳定战局/事件ID、限定白名单、32事件/64KiB 批次、有界24小时队列。跨标签页合并队列并共享授权；服务器去重，读档不重复新开局。
- 撤回立即停本机采集，断网保留服务器撤回/删除待办；删除可关联数据，不删游戏存档、成长或资源缓存。反馈独立授权、10—2000字、可选联系信息和可见摘要、固定ID重试、回执受控查看/删除。
- 管理员由服务端 CLI 建立，无默认密码/公开注册；scrypt、哈希会话/凭据、Secure/HttpOnly/SameSite、8小时绝对/30分钟闲置超时、CSRF、精确同源、限速。联系方式单独权限和审计导出；CSV 转义公式前缀。
- 七个页面：运行总览、关卡进程、部队与构筑、卡牌与经济、加载性能、反馈处理、历史日汇总。实际18英雄/90精英/30普通/24支援及2类未归因来源，共164身份；样本分母、阶段搭配、天赋/科技、军衔/到达关卡、D1/D7/D30成熟同期群、日期/版本/种族/难度/天赋点/场景筛选。没有样本时显示空态，不造数据。
- 后台每小时维护，明确90/180/365/730/180/90天保留；独立持久删除日志先落盘再提交事务，备份恢复前重放清单。部署说明写明停机调度和平台日志仍需真实运维配置。

## 设计与采集边界

玩家入口沿用游戏深色面板、原暂停/输入合同，标题/暂停/关间可进入，战斗不新增常驻大面板。后台使用深蓝侧栏、浅灰蓝工作区、铜色强调和青色趋势图，中文系统字体，无额外图片/字体资源。导航按日常管理任务分组；说明紧邻真实指标，移动视口以重排和表格横向滚动处理。

实际字段、归因来源、统计口径和期限见 [玩家数据说明](P5_PLAYER_DATA_NOTICE_20261006.md)。时间/输出来自实际观察，不按阵容推算伤害；实际子机输出归母舰一次。观察器保存在 World 外部 WeakMap，读取运行态并累加有限摘要；不改 RNG、数值、技能时间、实体、付款或存档序列化。

17个原模拟文件新增只读观察调用；`World.diagnosticRun` 只读返回沙盒/自动刷怪关闭状态。新增一次可选来源参数和回调不参与伤害计算。不能称这些模拟源文件哈希不变；证据是每个观察插入可逆，去掉后完整恢复 P4 原文，再加全量规则与精确 World 对照测试。渲染/英雄精英数值、数据和资源没有在 P5 更改。

原计划的反馈 GET 查看改为同源 POST 请求体携带回执，避免秘密进入 URL。`playerLevel` 报表对应实际冻结已分配天赋点0—80，不虚构未使用永久资源的“玩家等级”。日汇总不含浏览器ID；不能把跨日/跨版本 UV 简单相加。构筑同阶段出现只表示相关性。已有游戏事件可能因浏览器关闭、网络失败或有界队列溢出缺失，不称为权威全量战绩。
