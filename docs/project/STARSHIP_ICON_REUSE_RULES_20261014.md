## 复用与显示

1. **属性件按部位。** 八部位为武器研发、武器生产、弹药研发、弹药生产、装甲研发、装甲生产、动力一、动力二。同族同部位跨白绿蓝紫共用基础图，实际品质使用独立品质框。
2. **模块按功能主题。** 同族同功能的上下位使用同一基础图。名字和数值不同不自动增加绘图任务；功能不同且不在本规则的合并映射内，不随意共用。
3. **套装按主题。** 一个主题一张套装识别图，八部位共用，用部位角标区分。主题图表现该套装的代表性器件或标志，不将八件物品塞入一个小图。绿色2／2仍是任意两个合法不同属性槽满足已定规则，图片复用不改变门槛。
4. **身份按标识。** 英雄、精英、方向绑定使用真实名称与已有头像／身份徽记区分，基础主题图共用。优先复用已有素材；缺失徽记单列补图，不包含在246张中。
5. **状态按UI层。** 品质框、部位角标、污染／净化标记独立叠加；不为每种组合输出新图片，不把文字烘焙进底图。未净化用“污染的”，净化后用“净化的”；装备实际状态与可用资格保持原规则。
6. **三族分别画。** 人族以机械军械为主，虫族以生体器官为主，神族以晶体与灵能构架为主。不能把同一幅人族器件换色当作另两族版本。

## 紫色例外与橙装

紫色默认使用上述复用方案，少数具有明确独特外形或需要重点展示的套装可另做专属图；具体名单尚未确定，不据此把全部英雄／精英自动列为例外。

- 追加一张专属主题图，预算加1张。
- 追加一套八部位独立图，预算最多加8张；若旧主题图确定完全不再使用，净增7张。仍有其他装备共用旧图时不能扣掉它。
- “一套八部位图”指一个种族的一组；三族都独立制作则最多加24张。
- 实际橙装不计入246张，专属图片清单后续单列，不与本次预算混算。

## 尺寸与空间预算

游戏内默认透明背景256×256 WebP。512或1024制作原图单独保存，不随游戏发布。品质框和徽记按UI所需分辨率独立保存。

| 分辨率 | 估计单张文件大小 | 246张估计总量 |
| --- | --- | --- |
| 128×128 | 5—15 KB | 约1.2—3.7 MB |
| 256×256 | 15—45 KB | 约3.7—11 MB |
| 512×512 | 40—120 KB | 约10—30 MB |

首批按约10 MB基础图预算规划，压缩质量以实际小尺寸辨识与透明边缘效果为准。以上是容量估算，不是已生成文件的测量值；首次样图完成后测量再更新。独立例外、徽记与UI装饰另计。

246张256×256图全部解码为RGBA约61.5 MiB，带完整mipmap约82 MiB；磁盘压缩体积不等于解码／显存占用。按当前界面需求加载、缓存与释放；是否使用mipmap按实际缩放效果决定。

## 与命名目录的关系

[现有名称目录](STARSHIP_UI_NAMING_20261014.md)及其JSON保留独立装备名称、ID、品质和规则。不同物件专名可以使用同一基础识别图；图片不承担全部名称差异的表达。

本规则覆盖命名R3中“每个品质／身份的物件都需对应独立成品造型”的制图要求。已有`imageKey`是装备索引，`artVariantKey`是候选变体索引，都不能直接作为必须生成一张图的任务数。后续实现应增加独立的基础图映射，按“种族＋类别＋本文件绘图主题”解析图片，再叠加品质、部位和身份等UI信息；本次不修改游戏代码或现有目录ID。
