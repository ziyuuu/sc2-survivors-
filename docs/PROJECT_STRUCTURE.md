## 目录职责

| 位置 | 放什么 | 管理边界 |
| --- | --- | --- |
| `src/` | 正式游戏规则、数据、UI、渲染、加载和保存代码 | 主游戏与独立功能入口复用正式规则，不在预览目录复制一套业务逻辑 |
| `test/` | 对应行为的自动回归 | 按改动验证；不因文档整理重复游戏矩阵 |
| `tools/` | 资源处理、构建、交付与诊断工具 | 保留工具引用的固定路径和历史脚本；适用范围看各脚本及 `HISTORICAL_QA.md` |
| `docs/` | 常用工程参考、数据参考、文档导航和索引 | 数值生成稿用既有命令更新，手写计划不伪装成运行事实 |
| `docs/project/` | 每批设计、实施、来源、验证和项目管理记录 | 已有文件名保持稳定；当前／历史用途通过 [索引](DOCUMENT_INDEX.md) 区分 |
| `preview/` | UI 原稿、效果实验、诊断入口及独立功能包入口源码 | 每个入口说明用途和依赖；含真实逻辑不等于已接入主游戏，见 [preview 导航](../preview/README.md) |
| `assets/` | 资源清单、原件与处理输入 | 原来源、原件和派生关系保留；`assets/private/` 不因被忽略而可删或可公开 |
| `public/` | 开发服务使用的静态内容和运行资源 | 与清单、构建和恢复工具共同维护，不手动整理资源路径 |
| `deploy/coze/` | 已同步的应用文件镜像、锁定依赖和 vendor | 是交付副本，不是日常开发目录；文档更新不自动重打包或覆盖已验收镜像 |
| `deploy/runtime/` | Git LFS 跟踪的运行资源与恢复依据 | 与应用清单对应；保留既有资源身份和完整性检查 |
| `dist/` | 实际构建、命名 HTML／ZIP、解包应用及 Current 入口 | 文件日期不一定等于最终修订日期；精确版本查清单。整理不更新交付字节 |
| `reports/qa/`、`reports/balance/` | 可提交的验证摘要与数值分析 | 保留当时构建、实际范围和失败记录；不等于全部原始证据 |
| `reports/local/<主题>-<日期>/` | 本机截图、录像、日志、原始结果和交付核验 | 默认不入 Git；以当轮清单和用户保留／清理要求管理 |
| `reports/local/legacy-logs-20261013/` | 本次从根目录及 reports 顶层移入的旧散落日志 | 只归档、未删除；原路径、新路径与 SHA-256 在本次移动清单中 |
| `dev/` | 已有本机开发辅助文件 | 当前 `dev/null/` 内容保留；不得按目录名判断为垃圾，见 [说明](../dev/README.md) |
| `.github/` | CI 与仓库自动化 | 原件恢复和 hash 检查继续保留，不在目录整理时简化来源检查 |
| `.cache/`、`node_modules/` | 本机缓存与已安装依赖 | 与源码、原件和交付区分；本次不清理或重装 |
| `.git/` | 版本库数据 | 本次不提交、推送或改写历史 |

根目录保留 `README.md`、`AGENTS.md`、入口 HTML、包清单／锁文件及 TypeScript／Vite 配置。`design-qa.md` 仍被既有 UI 记录引用，保留原位。根目录旧 `error.log` 已移入本地日志归档；其内容不放入公开文档。

构建后的独立包放在 `dist/<主题>-<日期>/` 或同名 ZIP，证据放在 `reports/local/<主题>-<日期>/`，范围和验证放在 `docs/project/`。源码、可运行成品和证据各自有位置，不用一个 HTML 同时冒充三者。

2. 沿用 `主题_YYYYMMDD.md`、`主题_VALIDATION_YYYYMMDD.md`，必要时增加 `SOURCES`。同一批次迭代继续保留原批次日期，用 R2／R3 和实际构建指纹区分，不能把旧失败改名成最终通过。
3. 新命令日志直接写进对应 `reports/local/` 批次目录，不再散放根目录或 reports 顶层。公开摘要不包含账户、凭据、数据库内容或其他私有数据。
