## 桌面正常玩法：本轮新证据

实际执行 `node reports/local/qa-early-progression.mjs`，同内容已纳入 `tools/play-progression.mjs` 便于复现。只读诊断状态并发出键鼠输入，不修改 HP、伤害、阵容、波次、落点、速度或时钟。证据 `reports/local/qa/EARLY_PROGRESSION.json`。

| 流程 | 观察结果 |
|---|---|
| 首关 | 默认 1 Marine / Rank 1 / 45 HP；第 12、38 秒各一只跳虫；真实运行至 60 秒进入三选一，击杀 2，枪兵剩 5 HP |
| 建造/生产 | 实际支付兵营 150 M 并等待建造；支付 Marine 50 M 等待生产。任务在 64.63 秒产生一个仓，没有直接加兵 |
| 刷新/选择 | 首次刷新支付 50 M，三张组合从 Infernal / Starport / Siege 变为 Factory / Minerals / Infantry；选择并实际支付 Infantry Weapons，Marine 每发 +1 |
| 首次实战救援 | 仓体随机落在约 (-2.68, -18.65)，守军 2 Zergling。靠近后在射程边缘停下；约落地后 11 秒清敌成功，仓剩 1119 HP，第二名 45 HP Marine 在仓边出现并归队 |

对照失败保留：相同正式开局先站立应战，随后直接冲入仓中央，在 **72.38 秒**死亡。`EARLY_PROGRESSION_rush-to-center.json` 是正常键鼠输入的失败记录。成功路线采用射程边缘站位；没有通过修改单位基础数值让脚本强制获胜。当前只覆盖这一随机序列和两种操作策略，不代表全地图、全部落点或 12 关已平衡。

## 桌面画质与材质

旧实现：抗锯齿关闭、统一 DPR 上限 1.5，M3 转换只接 Diffuse。1920×1080 CSS / DPR 2 的旧画布为 2880×1620。地形预览只有约 820×820，Marine 原战斗模型颜色贴图是 512×256，不能把这些局限描述成 SC2 客户端的正常最高画质。

修复后 `node tools/qa-quality.mjs` 五组通过，零捕获错误：

| 场景 | 默认画质 / 实际画布 |
|---|---|
| 桌面 1440×900 / DPR 1.25 | native / 1800×1125，抗锯齿开启 |
| 桌面 1920×1080 / DPR 2 | native / 3840×2160，抗锯齿开启 |
| 手机尺寸 390×844 / DPR 3 | balanced / 585×1266，抗锯齿开启 |
| 手机尺寸 844×390 / DPR 3 | balanced / 1266×585，抗锯齿开启 |
| 断网 HTML 1920×1080 / DPR 2 | native / 3840×2160，零 HTTP(S) 请求 |

每组实际切换画质、重新加载检查保存、暂停页切换检查模拟时间冻结；HUD 都是单枪兵，无横向溢出、文字选择或页面滚动。开发版 GPU 材质检查：8/8 有 normalMap 与 specularColorMap，桌面 anisotropy 8 / 均衡 4；离线包内 GLB 也有相同图层引用。原始 DDS 未人为降低分辨率。素材导入 42 项，失败 0；8/8 原法线/高光，7/8 原发光（Marine 无此引用），一项 Medivac 辅助非 UV0 层明确记录为不支持。

这些是实际像素、载入、GPU/DOM 状态验证，不是人工视觉审核。完整 SC2 shader、队伍色、动态材质、阴影与地形仍未还原。
