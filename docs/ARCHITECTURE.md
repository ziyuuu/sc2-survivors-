# V3 runtime

`src/simulation/world.ts` owns fixed 60 Hz state. Three.js never owns HP, cooldowns, target selection, paths, production, rank or timers. V2 `rules.mjs` is retained and reused for atomic payment, damage and biological healing; its older lab-only production/reward primitives remain regression tested. The current complete runtime loop is `World`.

`src/data/sc2-units.ts` is the one locked unit profile. `src/data/game.ts` holds movement and obstacles; `src/data/ranks.ts` holds the approved progression multipliers; `src/data/stages.ts` owns stage/difficulty budgets and `src/data/economy.ts` owns gathering, drops, workers and discounts. Production/reward costs share these data objects in the browser and standalone build.

Ground actors use steering, separation, a 4-unit spatial hash, small static obstacle visibility/corner routing and a shared anchor breadcrumb trail with independent progress per actor. Movement always integrates velocity. Reversal preserves positions, cooldowns and identity. Soft leash stops chasing; hard leash prioritizes returning and applies at most 1.22x catch-up, while retaining close self-defense within 2.5 range. It must never disarm a surrounded straggler. No teleport correction exists. Tanks accept only explicit squad commands and can remain behind while sieged or morphing; vehicles have finite turning rates. Turret aim is separate from hull direction, and queued mode requests never cancel a morph halfway.

Each building independently and automatically charges a currently affordable order. Paid jobs and unresolved deliveries reserve training capacity; wallet contention rotates between buildings. Completion creates one falling original pod. Landing creates fixed stage guards; clearing all guards plus local threats opens the pod. Only destruction fails a pod; no deadline exists. SCV eggs have their own 30-second deadline, one economic grant and one presentation event. Drones remain economic bodies outside the four Zerg combat types. HP, enemies and unresolved pods persist across stages.

Reward screens stop all clocks and pay stage resources once, then present a building round and a random reinforcement/tech/economy round. Each allows one paid choice or skip. Buildings are keyed by independent ID and may repeat. Offers have persistent random discounts, are not wallet-filtered, and both rounds share reroll charges 50/75/100… without reserving funds. Building rerolls preserve unlocked types and change prices; random rerolls change the distinct card combination.

Corner routing targets are cached for 0.15–0.18 seconds, invalidated when the requested goal changes substantially or the corner is reached. Actual acceleration, turning, separation and collision still run at 60 Hz. This reduces repeated static-obstacle queries without moving actors through terrain or snapping their positions.

`src/render/scene/battle-renderer.ts` adapts state to the original GLB geometry. The M3 pipeline provides eight animated combat GLBs, eight independent death models and separate tank siege/morph models. `AnimatedBatch` samples selected original clips through AnimationMixer once, deduplicates bind palettes, stores half-float bone matrices and plays independent instances on the GPU. Small enemy silhouettes retain 24 Hz original poses; larger/friendly actors interpolate. Simulation time and distance drive playback. Death render copies finish after the gameplay entity is removed, without participating in gameplay. A clearly labeled static/procedural path remains only for development when the animation pack is missing; the friend bundler rejects missing animation/death packages.

`World.visualEvents` is a bounded presentation log with its own serial counter. Real damage, attack, death and bile impact publish read-only snapshots; they never consume gameplay IDs or RNG. `BattleEffects` uses original M3-referenced flipbooks with pooled instanced particles; hit highlights are presentation-only and cause no gameplay stun. Emission composition is a web adaptation, not a full M3 particle/SC2 Actor implementation. Audio uses exact original local imports when provided, with explicitly labeled synthesized fallback and bounded concurrent voices.

GPU instance buffers pool units, health bars, resource pickups and effects. Off-camera units are culled from rendering while simulation continues. Desktop uses native DPR; mobile balanced quality caps DPR at 1.5. Soft instanced contact shadows are local presentation; dynamic shadow maps/postprocessing are omitted. KTX2 texture compression is not present. One physical Android device has short-run timing/touch evidence in docs/QA.md; no broad or long thermal validation is claimed. Existing textures are small; external maps are extracted for development without changing their pixels.

`src/ui/hud.ts` responds to simulation change notifications at up to 10 Hz. It does not own rules. `src/ui/mobile/input.ts` handles independent keyboard/joystick state, pointer capture, cancellation, blur and visibility changes. UI buttons remain clickable while a movement pointer is captured. Reward/settings overlays have their own vertical scrolling. Production is a read-only HUD status, with no battle shop.

`tools/download-runtime.mjs` extends the existing exact-match catalog. `tools/import-m3-pack.mjs` fetches exact original M3/DDS assets and pinned converter source, validates before writing, converts locally in Node and records hashes/provenance. `dds-png.mjs` supports the pack's BC1/BC3 highest mip; unsupported formats fail explicitly. `tools/prepare-assets.mjs` prefers these imported animations, extracts independent development glTF/bin/textures, and creates a generated ID manifest. `tools/build-demo.mjs` bundles the same TypeScript entry with esbuild and embeds all runtime resources. Missing mandatory animation or unit assets cause a failed friend-demo build. Development first-run setup attempts the documented source automatically. Original audio slots remain explicitly missing until valid local WAV/OGG imports are present.

F1 and mutation APIs are compiled only in Vite development mode. The friend bundle exposes only a read-only metrics snapshot function, useful for QA. No debug speed, resource or spawn controls are compiled into its normal UI.


Small or mobile Zerg silhouettes can use locally simplified original index buffers (meshoptimizer 1.2.0, relative error limit .035, target 30%). Original vertex positions, skin indices/weights, normals, UVs, materials and animation atlas are reused. No geometric unit substitution occurs. The full mesh remains available for native large silhouettes. Runtime reports expose actual achieved LOD ratios.

`movement/contacts.ts` resolves same-layer circle contacts after movement through the spatial hash, with two bounded solver passes sharing one broad-phase query of at most 20 local candidates per actor. Moving actors yield to stationary bodies; sieged/morphing tanks and active pods are fixed. Map/obstacle tests also constrain contact correction. Each actor has a per-step correction budget, preventing crowd ejection/teleport. The air layer never collides with ground bodies. F1 can display gameplay radii. Owner-indexed hash buckets speed targeting/healing without discarding same-owner separation or collision.

`tools/budget-envelope.mts` is a conditional analytical ledger, reusing actual economy/queue/payment code but explicitly assuming collections, rescue outcomes, attrition and card availability. It never proves a battle victory. `campaign-study.mts` is a crude control-policy regression aid, not the Normal difficulty target.

Collision pair buffers are pooled per World. Squared-distance rejection avoids square roots for noncontacts. StageConfig is cached until stage or difficulty changes; per-actor movement no longer allocates configuration copies. These are performance changes, not reductions in enemy budgets or simulation frequency.

`src/data/terrain.ts` is shared by simulation and `render/terrain/char-geometry.ts`. Fixed heights, ramp portals, footprint slope tests and line-of-fire queries use the same coordinates. Terrain portals are cached by region pair; local obstacle steering remains bounded. Conservative flat rectangles bypass slope sampling only when the entire swept footprint is contained, preventing the heavy all-flat query path observed on the physical-phone stress test. Event spawn cells are flood-connected to the central region for each unlocked boundary.

The independent M3Studio audit checks source skeleton names, transform IDs and clip durations without using the production converter. Shader compilation is separately validated for every original material, including unlit auxiliary layers. Neither result asserts human visual fidelity. Original artwork and local captures remain ignored.

`FixedStepper` preserves every 1/60-second tick and caps catch-up CPU work to 8 ms / 8 steps per render. Excess debt is retained and exposed as `simulationBacklogSeconds`; under sustained overload the simulation can lag wall time. This avoids multi-second render starvation without deleting combat/production ticks or disguising slow simulation as high FPS. Pausing/visibility reset the clock as before.
