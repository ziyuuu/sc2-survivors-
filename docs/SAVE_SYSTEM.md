# 存档机制 · M2 mvp-1.0

当前实现入口：src/app/run-session.ts、src/persistence/、src/simulation/persistence/。只在本地保存。M2 沿用一套三族18关规则，并将四线天赋冻结进每局；旧开发战局不能续玩，但可原文导出，并在核验后明确导入永久资源本金。实际验证见 [M1记录](project/M1_VALIDATION.md)与[M2记录](project/M2_VALIDATION.md)，设计见 [运行稿](MVP10_RUNTIME.md)。

## 版本与战局身份

- 外层格式为 sc2-survivors-save、version 2，包含保存时间、图编码数据和校验和；读取上限32 MiB。
- 战局快照 schema 3、rules mvp-1.0；RunConfig固定种族、难度、campaign-18、地图身份与SHA、种子和已购买天赋等级／投资摘要。后续局外改配不回写本局。
- 唯一永久档案 version 4 保存资源余额、实际投资账、领奖／导入收据和三族各三份预设蓝图；四线共用80点，只有活跃方案付款。洗点与切换按实际已付资源全退再扣，事务失败不改变档案。
- M1 的空天赋永久档案v3与零天赋战局schema2规范化升级；不恢复旧12关或117节点运行分支。
- 读档先解码并校验外壳、档案、规则、字段、地图、种族、难度及配置一致性，再将候选状态恢复到现有 World。校验失败不修改当前战局或档案。
- 恢复战斗时暂停，清空瞬时输入，不补跑离线时间，不回血、回能、重抽关间选项或重置攻击冷却。HUD、敌军压力和奖励均使用档内难度，不使用标题菜单的临时默认值。

## 玩家操作与保存时机

有效未结束的v2存档在标题提供继续；返回标题保留可继续战局。战斗暂停、设置和关间可保存、导出完整JSON；标题可导入。战斗按约10秒模拟时间及重要状态变化请求保存。保存请求在同步模拟步或菜单事务结束后的微任务执行，并按顺序提交。

界面仅在事务成功后提示已保存；失败时保留内存状态并提示导出。战斗读档仍保持暂停，由玩家决定何时继续。失败战局不可继续；胜利界面可恢复。浏览器存储按来源和浏览器档案隔离，换浏览器、移动 file:// 单文件或清缓存前应导出。

## 状态与事务

战局保存单位身份、种族与阵营、生命／护盾／能量、模式与冷却、英雄与精英身份、五家族编制、逐乘员已付款账本、生产配置与订单、空投乘员及守军、换兵请求与继承记录、建筑／卡牌已显示选项和领取收据、侦测与隐形、敌人和18关事件、随机数状态及无尽分钟收据。M2 另保存冻结天赋、额外领卡／建筑／击杀掉落收据、战术进阶票、转移准备和玩家爆虫停顿状态。run-fields.ts显式列出持久字段；Map、Set、Infinity及共享对象由图编码保留，不能直接序列化 World 或 Three 对象。空间哈希、导航缓存、渲染器和GPU对象在恢复后重建。

IndexedDB库 sc2-survivors-saves 的 snapshots 存储区使用 current、backup1、backup2。一次读写事务提交战局和永久档案，并轮换有效的当前版本备份；损坏主档可从有效备份恢复。旧v1原文在新提交时另存 legacy-current 等键，不被新战局覆盖。校验和用于发现损坏，不作为反作弊机制。

## 旧开发档只读处理

v1旧开发档只通过 dev-profile-import.ts 检查，不创建旧 World 或启用12关／旧商店。界面显示摘要、原文导出与永久资源导入选项。导入前按冻结的旧1／3／5／6／10价格核算“旧未花余额＋实际投资”；若同档含三族永久档案，则先验证两份本金和收据不矛盾，不重复相加。无法可靠核算时拒绝导入，但仍允许原文导出。

确认导入时，以源档校验和记录一次性收据，替换为已核实的永久本金和原领奖收据，九份现行预设保持空白；旧战局不加载。重复导入同一源档被拒绝。旧文件和两份备份不因检查或取消而修改。旧 localStorage 天赋档可包装成只读候选，同样需明确导入。

## 已验证范围与限制

npm run test:save覆盖M1的三族×四难度、旧本金／矛盾拒绝／重复导入、备份和精英事务；M2 回归另覆盖三族×四难度×零／41／80点、当前方案与本局冻结隔离、建筑／卡牌与爆虫状态。开发版浏览器验证天赋UI、战局读档、微操面板；file://独立包断网导入带天赋档。测试结果、包体哈希见 [M2验证记录](project/M2_VALIDATION.md)。

本地存储不可用、满额或事务失败时，内存战局仍保留，可手动导出；强制结束浏览器可能丢失最后成功快照之后的进度。不承诺多个同时打开的游戏窗口自动合并。存档不包含模型、贴图或截图。
